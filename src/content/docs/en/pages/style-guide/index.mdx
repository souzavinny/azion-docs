This guide describes how Azion writes its documentation. Use it when you write a new page, translate one, or review someone else's work. The rules exist so that every page reads the same way, translates well, and stays useful when a machine retrieves one section alone.

## What this guide covers

- [Voice](/en/documentation/style-guide/writing/voice/): the register every page uses.
- [Sentence structure](/en/documentation/style-guide/writing/sentence-structure/): the sentence rules, adapted from ASD-STE100.
- [Word choice](/en/documentation/style-guide/writing/word-choice/): vocabulary to avoid and the patterns that read as machine-generated.
- [Terminology](/en/documentation/style-guide/writing/terminology/): product names and translation rules.
- [Headings](/en/documentation/style-guide/formatting/headings/), [text formatting](/en/documentation/style-guide/formatting/text/), and [code](/en/documentation/style-guide/formatting/code/): how content is formatted.
- [Content strategy](/en/documentation/style-guide/content/choose-a-content-type/): the [information architecture](/en/documentation/style-guide/content/information-architecture/), the page kinds, and how to pick one.
- [File conventions](/en/documentation/style-guide/conventions/frontmatter/): frontmatter and [bilingual pages](/en/documentation/style-guide/conventions/bilingual/).
- [Components](/en/documentation/style-guide/components/), [API docs](/en/documentation/style-guide/api-docs/), and [How we write the docs](/en/documentation/style-guide/how-we-docs/): sections reserved for content that is not written yet.

## Scope

This guide covers writing and information architecture. Components, visual design, and page layout are outside the writing rules: the [Components](/en/documentation/style-guide/components/) section holds their place until that content lands.

## The agent-facing rules

This guide is the single source for the writing rules, and coding agents read these pages directly. The `.agents` directory of [aziontech/docs](https://github.com/aziontech/docs) routes an agent to the right page here and adds what this guide does not cover: the MDX components, the sidebar files, the build validators, and the markdown version of each page. A rule changes in one place, here.

## The guide follows its own rules

Every page in this section passes the rules it describes: the sentence caps, the heading rules, and the size targets. When a rule proves unworkable here, the rule changes before any writer is asked to follow it.
