## Purpose

A Get started page is a tutorial whose goal is the first activation of one product: from not using it to the smallest working result. It follows the [tutorial](/en/documentation/style-guide/content/tutorials/) base form.

## When to use

- Write a Get started page when a product needs a documented path to its first working result.
- Write one Get started page per product, as the entry point directly after the product Overview.
- Do not write a Get started page for a task the reader already has in mind. That task needs a [how-to guide](/en/documentation/style-guide/content/how-to-guides/).
- Do not write a Get started page to present options or compare interfaces. The pattern has one path.
- Do not write a separate Get started page for a module or a feature. The pattern covers one whole product.

## Register

Procedural: 20 words per sentence, one instruction per step, imperative and active. [Sentence structure](/en/documentation/style-guide/writing/sentence-structure/) holds the rules.

## Structure

A Get started page follows the tutorial skeleton. [Tutorials](/en/documentation/style-guide/content/tutorials/) argues each part; the list below names what the pattern requires. The title takes the form `Get started with <Product>`.

**Required components**

- **Opening move**: `This guide instructs you through <outcome>.` followed by a short bullet list of what the reader will have done. Frame the outcome as a first: "your first bucket", "your first deployment".
- **Prerequisites**: a `## Prerequisites` section with bulleted items, each a link or a one-line command where one exists, otherwise a noun phrase naming the requirement. A single prerequisite is a sentence, not a list.
- **Stages**: numbered stage headings, `## 1. <Imperative verb phrase>` through `## N.`, ending in a stage that activates or verifies. Each stage holds one procedure and ends with its outcome sentence.
- **Next steps**: a `## Next steps` closing with bulleted links shaped `[Title](/path/) - one sentence on why the reader would follow it.`

**Optional components**

- **Screenshots**: for a step whose visible result is a screen, not command output.
- **Asides**: rare. A tutorial full of note blocks tries to be reference material.

## Template

Copy the template and replace each `<placeholder>`:

```md
This guide instructs you through <outcome, framed as a first:
your first bucket, your first deployment>.

- <What the reader will have done, as a short bullet list>
- <...>

## Prerequisites

- <A link or a one-line command where one exists, otherwise a noun phrase>

## 1. <Imperative verb phrase>

<A procedure, numbered when it has two or more actions.>

<The outcome sentence: what the reader now has or sees.>

## 2. <Imperative verb phrase>

<...>

## N. <Imperative verb phrase that activates or verifies>

<...>

## Next steps

- [Title](/path/) - one sentence on why the reader would follow it.
- [Title](/path/) - one sentence on why the reader would follow it.
```

## Rules

- **Document one linear path on the primary interface.** Alternatives are one link each, not parallel tracks. No `<Tabs>`.
- **Write each stage as a procedure.** Steps follow [Procedures](/en/documentation/style-guide/writing/procedures/), and every stage ends with its outcome sentence.
- **Keep prerequisites to the minimum real set.** Every item is a reason to abandon the page.
- **End in a stage that activates or verifies.** The reader leaves with proof of the working result.
- **Mark gaps, never fill them.** A mandated slot the input does not supply gets a `[GAP: ...]` marker, never silent omission, never invention.
- **Link tutorials and the main how-tos in `## Next steps`.** Give each link its reason.
- **Test every command before the page ships.** One instruction per step, and a visible result at each one.
- **Place it directly after the product Overview.**

## Examples

This excerpt of a Get started page for **Applications** shows the opening move, the prerequisites, and the first stage:

```mdx
This guide instructs you through the deployment of your first application from a template. The guide has three stages:

- Choose a template in Azion Console.
- Configure and deploy the application.
- Verify that the application answers on its Azion domain.

---

## Prerequisites

- An [Azion account](https://console.azion.com/).
- A GitHub account, for templates that integrate with GitHub.

---

## 1. Choose a template

To choose a template:

1. Access [Azion Console](https://console.azion.com/) > **+ Create**.
2. In the modal, select the **Templates** option.
3. Browse the templates and choose one.

The configuration page for the template opens.
```
