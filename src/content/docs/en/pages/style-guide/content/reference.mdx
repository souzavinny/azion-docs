## Purpose

A reference page is look-up material. The reader consults it to find one value, one field, or one limit, and then leaves.

## When to use

Write a reference page when:

- The reader needs to look up a field, a setting, a limit, or a flag.
- The information is enumerable and fits in a table.

Do not write a reference page when:

- The reader needs steps for a task. Write a [how-to guide](/en/documentation/style-guide/content/how-to-guides/).
- The reader needs the reasoning behind a design. Write a [concept](/en/documentation/style-guide/content/concept/).

## Register

Descriptive: 25 words per sentence, active voice, passive only when the actor is unknown. [Sentence structure](/en/documentation/style-guide/writing/sentence-structure/) holds the rules.

## Structure

**Required components**

- **Title**: a noun phrase that names the product or the resource.
- **Lead paragraph**: the product name in bold, plus what the reader can do with the product.

**Optional components**

- **Link button**: one primary call to action near the top of the page, and only one.
- **Management interfaces**: a list that names Azion Console, API, Azion CLI, and Terraform.
- **Implementation**: a table with the available scopes and the resource that implements each one.
- **Modules**: a table with each module and a one-line description.
- **Advanced settings**: a table with each setting and a description.
- **Limits**: a table with each limit, under a tip that support can raise limits.
- **Asides**: a tip above the limits table, and a caution for a version or migration warning. Use no other aside, and use these two sparingly.

Omit a section that has nothing to describe. The sections that remain keep this order.

## Template

Copy the template and replace each `<placeholder>`.

```mdx
import LinkButton from 'azion-webkit/linkbutton'

**<Product name>** is <what the product is>. With <Product name>, you can <what the reader can do>.

<LinkButton severity="secondary" label="<Call to action>" link="<destination URL>" />

You can create and manage <product name> with:

- [Azion Console](<guide URL>)
- [API](<API reference URL>)
- [Azion CLI](<CLI reference URL>)
- [Terraform](<Terraform reference URL>)

---

## Implementation

| Scope | Resource |
| --- | --- |
| <Scope> | <Resource that implements it> |

---

## Modules

| Module | Description |
| --- | --- |
| <Module name> | <One-line description> |

---

## Advanced settings

| Setting | Description |
| --- | --- |
| <Setting name> | <What it does, with the default value> |

---

## Limits

:::tip
Support can raise these limits. Contact <support link>.
:::

| Scope | Limit |
| --- | --- |
| <Scope> | <Value with the unit> |
```

A CLI command page takes a different shape. It opens with a one-line summary, then a `Usage` section with a shell block. An `Optional flags` section closes the page, with one heading per flag.

## Rules

- **Describe, do not instruct.** A numbered click-through belongs in a [how-to guide](/en/documentation/style-guide/content/how-to-guides/).
- **Put enumerable information in tables.** Fields, limits, flags, defaults, status codes.
- **Keep phrasing consistent down a column.** Readers scan; varied phrasing forces them to read.
- **State the units and the defaults.** A limit without a unit is not a fact.
- **Be complete before you are interesting.** A page missing three of twelve fields is broken.
- **No marketing.** Say what it does and where it stops.
