The terms below are the vocabulary of [Cache](/en/documentation/build/cache/), the [Applications](/en/documentation/build/applications/) module that stores copies of your content on Azion edge nodes.

<GlossaryFilter lang="en">

| Term | Definition |
| --- | --- |
| Adaptive Delivery | A [cache setting option](/en/documentation/build/cache/reference/cache-settings/) that keeps device-based variations of an object in cache, one per device group that Azion detects with [Device Groups](/en/documentation/build/applications/reference/device-groups/). With _Content varies by some Device Groups (Whitelist)_ selected, the cache key carries the device group name after the `@@` separator. |
| Advanced Cache Key | A [cache setting section](/en/documentation/build/cache/reference/cache-settings/) that varies cached objects by query string fields or by cookie values instead of by URL alone. It holds the Cache by Query String and Cache by Cookie options and requires [Application Accelerator](/en/documentation/build/application-accelerator/). Both options are case sensitive. |
| `BYPASS` | A cache status: the edge node requests the content from the origin directly instead of using a cached version, because a Bypass Cache behavior is active. |
| Bypass Cache | A [Rules Engine behavior](/en/documentation/build/applications/reference/rules-engine/#bypass-cache) for the request phase that stops Azion from caching the origin response for matching requests, which are all forwarded to the origin. It leaves the browser cache untouched and requires Application Accelerator. It does not reach the Tiered Cache layer, which keeps caching for its minimum TTL. |
| Cache by Cookie | An [Advanced Cache Key option](/en/documentation/build/cache/reference/cache-settings/) that varies cached objects by cookie name and value. The four settings are no variation by cookies, variation by some listed cookies, variation by all cookies except some listed ones, and variation by all cookies. In the cache key, the cookie names and values follow the `@@` separator and end with `;`. |
| Cache by Query String | An [Advanced Cache Key option](/en/documentation/build/cache/reference/cache-settings/) that decides which query string fields distinguish cached objects. The four settings are no variation by query string, variation by some listed fields, variation by all fields except some listed ones, and variation by all fields. |
| cache key | The identifier an edge node builds from a request to [index a cached object](/en/documentation/build/cache/reference/cache-keys/) and match later requests to it. By default it concatenates the scheme, host, path, and query string, then a `@@` separator with any appended variations, and it is case sensitive. For example, `https://static.example.com/page/site.js` produces `httpsstatic.example.com/page/site.js`. |
| cache key purge | A [Real-Time Purge type](/en/documentation/build/cache/reference/real-time-purge/) that takes a list of cache keys as its argument and removes exactly those objects, including variations by query string, cookie, or image format. Each variation to remove must be listed individually. |
| cache setting | The object in an application that holds one cache policy, documented in [Cache Settings](/en/documentation/build/cache/reference/cache-settings/): browser and edge TTL modes, Stale Cache, Large File Optimization, Advanced Cache Key, cached HTTP methods, and Adaptive Delivery. A rule with the Set Cache Policy behavior assigns a cache setting to the requests that match it. |
| cache status | The result of an edge node's [cache lookup](/en/documentation/build/cache/how-it-works/) for a request, returned in the `X-Cache` header when the request carries `Pragma: azion-debug-cache`. The eight values are `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED`, `BYPASS`, and `-`. The value `-` means no status was received because the content is restricted from caching, for example a `POST` request while caching for POST is turned off. |
| device group | An object created with [Device Groups](/en/documentation/build/applications/reference/device-groups/) that matches a regular expression against the `User-Agent` header of a request. Adaptive Delivery reads device groups to keep one cached variation of an object per group. |
| edge node | A server on Azion's distributed network that receives requests, holds the [cache](/en/documentation/build/cache/how-it-works/), and fetches from the origin when the cache cannot answer. The `X-Cache` header reports the IP of the edge node that answered a request. For the generic meaning of caching, refer to [the Learning Center article on caching](https://www.azion.com/en/learning/cdn/what-is-caching/). |
| Enforce HLS cache | A [Rules Engine behavior](/en/documentation/build/applications/reference/rules-engine/#enforce-hls-cache) for the request phase that Azion adds when you select a Live Ingest source. It bypasses your Cache Phase rules and applies Azion's cache policy for live HLS streams: 5 seconds for playlists (`.m3u8`) and 60 seconds for chunks (`.ts`). To apply the same policy by hand, refer to [Enforce HLS cache for live streaming delivery](/en/documentation/build/cache/guides/enforce-hls-cache/). |
| `EXPIRED` | A cache status: the cached content passed the TTL set on the edge node, so the edge node fetches from the origin and updates the cached copy for future requests. |
| Forward Cookies | A [Rules Engine behavior](/en/documentation/build/applications/reference/rules-engine/#forward-cookies) for the request phase that forwards the `Set-Cookie` header received from the origin to the user, even on a cache `HIT`. It requires Application Accelerator. |
| fragment | One piece of a file that [Large File Optimization](/en/documentation/build/cache/reference/cache-settings/) splits and caches separately, on demand. Each fragment carries its own cache key, with the `@@bytes=` separator and the byte range, and the default fragment size is 1,024 kB. |
| `HIT` | A cache status: valid, up-to-date content is delivered directly from the edge node's cache, without a request to the origin. |
| Honor Origin Cache Headers | A [cache setting mode](/en/documentation/build/cache/reference/cache-settings/), for the browser cache or the edge cache, that keeps the cache definitions the origin sends in its `Cache-Control` and `Expires` headers. With Stale Cache, a `stale-while-revalidate` directive from the origin then sets the stale window. |
| Large File Optimization | A [cache setting option](/en/documentation/build/cache/reference/cache-settings/) that splits a large file into fragments, each with its own cache key, and caches them on demand as the user consumes the file. It applies to the edge cache and, when Tiered Cache is active, to the tiered layer as well. |
| `MISS` | A cache status: the requested content is not in the edge node's cache, so the edge node fetches it from the origin, and the response might be cached for future requests. |
| origin | The server or service that holds the source of your content: web servers in your infrastructure, a cloud service, or Object Storage, reached through a [Connector](/en/documentation/secure/connectors/reference/origins/). An edge node fetches from the origin when the cache status is `MISS`, `EXPIRED`, or `BYPASS`. |
| Override Cache Settings | A [cache setting mode](/en/documentation/build/cache/reference/cache-settings/) that replaces the cache headers from the origin with a TTL you set, for the browser cache or the edge cache. An edge TTL under 60 seconds requires Application Accelerator. With Stale Cache, this mode uses the default stale window of 300 seconds. |
| `Pragma: azion-debug-cache` | A request header that makes the edge node return the [`X-Cache` and `X-Cache-*` debug headers](/en/documentation/build/cache/reference/cache-keys/) with the response: cache status, cache key, cache file, cache timestamps, and configuration ID. To read them in a browser, refer to [Verify cache indicators in the browser](/en/documentation/build/cache/guides/check-page-cache-time/). |
| purge layer | The cache layer a [Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/) acts on: _Cache_, the edge cache, or _Tiered Cache_, available only when that module is active. Purge the Tiered Cache layer first and the Cache layer second, so edge nodes do not refill from outdated tiered content. |
| Query String Sort | An [Advanced Cache Key option](/en/documentation/build/cache/reference/cache-settings/) that orders the query string fields alphabetically before the cache key is built, so the position of a field no longer creates a separate object. A URL purge of such an object must send the arguments in alphabetical order. |
| Real-Time Purge | The platform resource that [removes cached objects](/en/documentation/build/cache/reference/real-time-purge/) from the Cache or Tiered Cache layer before their TTL expires, so the next request fetches the latest version from the origin. The three purge types are URL purge, cache key purge, and wildcard purge. To run one, refer to [Purge cached content](/en/documentation/build/cache/guides/purge-content/). |
| `REVALIDATED` | A cache status: the edge node checked the cached content against the origin with conditional headers and found it up to date, so the origin did not retransmit the resource. |
| Set Cache Policy | A [Rules Engine behavior](/en/documentation/build/applications/reference/rules-engine/#set-cache-policy) for the request phase that assigns a cache setting to the requests that match the rule's criteria. The cache setting must exist in the Cache Settings tab before the rule references it. |
| `STALE` | A cache status: the cached content expired and the origin failed to respond, so the edge node served the expired copy under Stale Cache. |
| Stale Cache | A cache setting switch, on by default, that lets an edge node [keep serving an expired object](/en/documentation/build/cache/how-it-works/) when revalidation fails. It covers a 5xx error from the origin, a connection timeout or unreachable origin, invalid or missing cache-control headers, and an update in progress. During the stale window the edge node serves the expired copy at once and fetches a fresh one in the background. |
| stale window | The period during which [Stale Cache](/en/documentation/build/cache/how-it-works/) may serve an expired object. When the origin sends a `stale-while-revalidate` directive and the cache setting honors origin headers, that value sets the window; otherwise Azion assigns a default of 300 seconds. |
| Thundering Herd control | The mechanism by which an edge node [opens only one connection to the origin](/en/documentation/build/cache/how-it-works/) when several simultaneous requests arrive for the same object that is not cached. Each edge node requests the object from the origin once per `MISS` or other non-`HIT` status. |
| Tiered Cache | A [Cache module](/en/documentation/build/cache/tiered-cache/) that adds a second cache layer between the edge nodes and your origin servers and keeps content cached for longer periods. It requires activation for the account through the Sales team, and a cache setting that uses it needs a TTL of at least 3 seconds. For the generic meaning, refer to [the Learning Center article on tiered caching](https://www.azion.com/en/learning/cdn/what-is-tiered-caching/). |
| TTL | Time to live: the number of seconds a cached object stays valid before it expires, set separately for the browser cache and the edge cache in a [cache setting](/en/documentation/build/cache/reference/cache-settings/). Without Application Accelerator, the edge cache TTL cannot go under 60 seconds. The floor and ceiling of each layer are listed in [Cache limits](/en/documentation/build/cache/limits/). |
| `UPDATING` | A cache status: the cached content expired and a stale copy is being served while the edge node fetches the updated content from the origin. |
| URL purge | A [Real-Time Purge type](/en/documentation/build/cache/reference/real-time-purge/) that takes a list of URLs, converts each to its cache key, and removes only those objects, without recursion. Variations by cookie, device group, or image format are not removed; query string variations are, when the arguments come in the order the cache key uses. An asterisk in a URL purge is a literal character, not a wildcard. |
| wildcard purge | A [Real-Time Purge type](/en/documentation/build/cache/reference/real-time-purge/) that takes one expression with an asterisk (`*`) in the path or query string and removes every matching object, including its variations. It does not reach the Tiered Cache layer. |
| `X-Cache` | The response header that carries the cache status, the IP of the edge node, and the protocol of the request, returned when the request carries `Pragma: azion-debug-cache`. For example: `X-Cache: HIT from 203.0.113.10 with HTTP/2.0`. The full set of debug headers is listed in [Cache keys](/en/documentation/build/cache/reference/cache-keys/). |

</GlossaryFilter>
