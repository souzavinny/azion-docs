A cache key is the index entry an edge node builds for each object it stores. [Cache](/en/documentation/build/cache/) builds the key from the request URI and appends a marker for each variation the cache setting enables. For how an edge node uses the key to answer a request, refer to [How Cache works](/en/documentation/build/cache/how-it-works/).

## Cache key format

The default cache key concatenates these elements of the request URI, in this order and with nothing between them:

- Scheme of the request
- Host
- Path to the resource
- Query string
- The variation separator and, when a variation applies, the appended variation

An object with the URI `https://static.example.com/page/site.js` has the cache key `httpsstatic.example.com/page/site.js`.

Cache keys are case sensitive, so a key that differs only in letter case identifies a different object.

When the cache setting enables variations, the key carries the `@@` separator at its end, followed by the marker of any variation that applies. A key with the separator and no marker looks like `httpsexample.com/resource-path/image.jpeg@@`.

## Variations

Each feature that varies content appends its own marker to the cache key. Each variation of an object is a separate cache entry with its own key. The table lists every variation, the marker it adds, and one example key.

| Feature | Marker | Example key |
| --- | --- | --- |
| Request method other than `GET` or `HEAD` | The method name, prefixed to the key | `optionshttpsstatic.example.com/page` |
| Image Processor format conversion | `@@` and the converted file format | `httpsstatic.example.com/static/images/image_1.jpg?ims=880x@@webp` |
| Adaptive Delivery by device group | `@@` and the device group name | `httpwww.example.com/@@Mobile` |
| Advanced Cache Key, Cache by Cookie | `@@`, then each cookie name and value followed by `;` | `httpwww.example.com/@@user=user;` |
| Advanced Cache Key, Cache by Query String | `?` and the selected arguments, in request order | `httpstatic.example.com/page?name=name&city=city` |
| Query String Sort | The query string arguments, in alphabetical order | `httpstatic.example.com/page?city=city&name=name` |
| Large File Optimization | `@@bytes=` and the byte range of the fragment | `httpstatic.example.com/media/file.mp4@@bytes=0-1048575` |
| Cached `POST` or `OPTIONS` request | `@@` and the MD5 hash of the request body | `httpsdynamic.example.com/path@@md5_of_post_arguments` |

The options that turn each variation on are documented in [Cache Settings](/en/documentation/build/cache/reference/cache-settings/).

### Request method

When a request uses a method other than `GET` or `HEAD`, the method name is prefixed to the cache key. An `OPTIONS` request for `https://static.example.com/page` has the key `optionshttpsstatic.example.com/page`.

Cache stores `GET` and `HEAD` responses by default. Caching `POST` or `OPTIONS` responses requires [Application Accelerator](/en/documentation/build/application-accelerator/), and those keys also carry the request body hash described in Cached HTTP methods.

### Image Processor

When [Image Processor](/en/documentation/build/image-processor/) converts an image to another format, the converted file format follows the `@@` separator. The `ims` query string that requests the processing stays in the query string position of the key.

An image resized with `?ims=880x` and converted to `webp` has the key `httpsstatic.example.com/static/images/image_1.jpg?ims=880x@@webp`.

### Device Groups

When the Adaptive Delivery option of the cache setting is **Content varies by some Device Groups (Whitelist)**, Cache keeps one object per selected device group. The key ends with the `@@` separator and the device group name.

An application with a variation for the `Mobile` group has the key `httpwww.example.com/@@Mobile`. Device groups are defined in [Device Groups](/en/documentation/build/applications/reference/device-groups/).

### Cache by Cookie

Cache by Cookie is an Advanced Cache Key option, available with [Application Accelerator](/en/documentation/build/application-accelerator/). The key ends with the `@@` separator, then each selected cookie name and value followed by `;`. Cookie names and values are case sensitive.

Content that varies by the `user` cookie produces these keys:

- `httpwww.example.com/@@;`
- `httpwww.example.com/@@user=user;`

The first key carries no cookie value after the separator.

### Cache by Query String

Cache by Query String is an Advanced Cache Key option, available with [Application Accelerator](/en/documentation/build/application-accelerator/). The key carries the `?` separator and the selected arguments, in the order the request sent them. Argument names and values are case sensitive.

Content that varies by `name` and `city` produces these keys:

- `httpstatic.example.com/page?name=name`
- `httpstatic.example.com/page?city=city&name=name`
- `httpstatic.example.com/page?name=name&city=city`

With **Query String Sort** turned on, the arguments are grouped under one key in alphabetical order. The requests `?name=name&city=city` and `?city=city&name=name` then share the key `httpstatic.example.com/page?city=city&name=name`.

### Large File Optimization

With Large File Optimization turned on, each fragment of an object has its own cache key. The key ends with the `@@bytes=` separator and the byte range of the fragment.

A file of `2097151` bytes produces these keys:

- `httpstatic.example.com/media/file.mp4@@bytes=0-1048575`
- `httpstatic.example.com/media/file.mp4@@bytes=1048576-2097151`

### Cached HTTP methods

When the cache setting turns on **Enable caching for POST** or **Enable caching for OPTIONS**, the request body becomes part of the cache key. The key ends with the `@@` separator and the MD5 hash of the request body:

- `httpsdynamic.example.com/path@@md5_of_post_arguments`
- `httpsdynamic.example.com/path@@md5_of_options_arguments`

## Debug headers

A request that carries the header `Pragma: azion-debug-cache` receives a response with the `X-Cache-*` headers, which describe the cache entry of the requested object.

Request an object with the debug header:

<Code lang="bash" code={`curl -s -o /dev/null -D - -H "Pragma: azion-debug-cache" https://example.com/resource-path/image.jpeg`} />

The response headers include the cache status and the cache key, in this form:

```text
X-Cache: HIT from 203.0.113.10 with HTTP/2.0
X-Cache-Key: httpsexample.com/resource-path/image.jpeg@@
```

The full set of debug headers:

| Header | Value |
| --- | --- |
| `X-Cache` | The cache status of the request, the IP of the edge node that answered it, and the protocol of the request. The status is one of `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED`, `BYPASS`, or `-`. |
| `X-Cache-Key` | The cache key of the object, in the format described in Cache key format. |
| `X-Cache-File` | The cache file of the object: the MD5 hash of the cache key. |
| `X-Cache-Since` | The Unix timestamp of when the object entered the cache. |
| `X-Cache-Expire` | The Unix timestamp of when the object leaves the cache. |
| `X-Cache-Expire-In` | The time the object remains in cache, in seconds. |
| `X-Cache-Valid` | The time the object is set to stay in cache, set in the cache configuration or received from the origin's `Cache-Control` headers. |
| `X-Cache-Config` | The ID of the virtual host configuration, generated by Azion Console. |
| `X-Cache-ID` | The unique ID of the request. |

For the definition of each cache status, refer to [How Cache works](/en/documentation/build/cache/how-it-works/). To read these headers in a browser, refer to [Verify cache indicators in the browser](/en/documentation/build/cache/guides/check-page-cache-time/).

## Cache key purge

Real-Time Purge accepts a list of cache keys as the argument of a cache key purge. Each key takes the form the `X-Cache-Key` header returns, including the `@@` separator and any variation marker. Each variation of an object is purged by its own key.

The variations of one image processed by Image Processor, for example, purge as four keys:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

To purge every variation of an object, list each key or use a wildcard purge. For the purge types, layers, arguments, and limits, refer to [Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/).
