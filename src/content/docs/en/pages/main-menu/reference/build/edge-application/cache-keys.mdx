A cache key is an index entry for an object in Azion's edge nodes. When a request is made to an application for the first time, the edge node forwards the request to the origin server and generates a cache for each object received on the edge node. When the next request for the same resource is made to the application, if the resource requested matches one already found through the cache key, the edge node does not forward the request to the origin.

To obtain the cache key of an application's resource, request the content URI and add the Azion debug header `Pragma: azion-debug-cache`. A successful response returns an `X-Cache-Key` header with the cache key value:

```bash
X-Cache-Key: httpsyourdomain.com/resource-path/image.jpeg@@
```

:::note
To automate your browser and obtain other cache data, refer to [How to verify application cache indicators using Modheader for Google Chrome](/en/documentation/build/cache/guides/check-page-cache-time/).
:::

## Cache key format

Azion concatenates the following URI syntax elements to form the default cache key:

- Scheme of the request
- Host
- Path to the resource
- Query strings
- A variation separator and, when implemented, appended variations

An object with the URI `https://static.yourdomain.com/page/site.js` generates the cache key `httpsstatic.yourdomain.com/page/site.js`.

Cache keys are case sensitive, meaning upper and lower case characters are considered as distinctive.

Some cache keys change depending on variations generated on the edge node. If variations are enabled, the cache key can contain the `@@` separator at the end, resulting in `httpsstatic.yourdomain.com/page/site.js@@`.

## Complex requests

A complex request is any method other than `GET` or `HEAD`. If the resource is obtained using a complex request, the method is added to the start of the cache key.

For an `OPTIONS` request, the cache key generated for an object is `optionshttpsstatic.yourdomain.com/page`.

## Image Processor variations

When [Image Processor](/en/documentation/build/image-processor/) is activated, the cache key carries the `ims` query string. Variations with a converted format also contain the file format after the separator.

For an image that is resized and converted into `webp` format, the cache key generated is `httpsstatic.yourdomain.com/static/images/image_1.jpg?ims=880x@@webp`.

## Device Groups variations

If there is an object variation per [device group](/en/documentation/build/applications/reference/device-groups/), the cache key is appended with the separator `@@` and the device group name.

For an application that implements a variation for the `Mobile` group, the generated cache key is `httpwww.yourdomain.com/@@Mobile`.

## Advanced Cache Key variations

When the [Advanced Cache Key](/en/documentation/build/application-accelerator/guides/advanced-cache-key/) feature is configured, the formation of cache keys is also affected.

**Cache by Cookie** generates a cache key variation with the determined cookie names and values followed by `;`. Content variation based on the `user` cookie can generate the following cache keys:

- `httpwww.yourdomain.com/@@;`
- `httpwww.yourdomain.com/@@user=user;`

**Cache by Query String** generates cache keys with the query separator and the determined arguments, based on the order of the query strings submitted in the request. Content variation based on `name` and `city` can generate the following cache keys:

- `httpstatic.yourdomain.com/page?name=name`
- `httpstatic.yourdomain.com/page?city=city&name=name`
- `httpstatic.yourdomain.com/page?name=name&city=city`

For multiple query strings, if **Query string sort** is enabled, the query strings are grouped under the same cache key, ordered alphabetically.

## Large File Optimization variations

For fragmented objects, the cache key appends the `@@bytes=` separator for each piece of content.

For a file that is `2097151` bytes in size, with Large File Optimization enabled, the cache keys generated are:

- `httpstatic.yourdomain.com/media/file.mp4@@bytes=0-1048575`
- `httpstatic.yourdomain.com/media/file.mp4@@bytes=1048576-2097151`

## Cached HTTP methods

For cached `POST` or `OPTIONS` requests, the cache key appends the `@@` separator followed by the MD5 hash of the request body.

For example:

- `httpsdynamic.yourdomain.com/path@@md5_of_post_arguments`
- `httpsdynamic.yourdomain.com/path@@md5_of_options_arguments`
