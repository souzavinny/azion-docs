[Cache](/en/documentation/build/cache/) applies default limits to the TTL values you set, the objects it stores, and the purge operations you run. Only the purge operation limit changes with the support plan on the account. Every other limit on this page is the same on every plan.

:::tip
**Increase your limits** <br></br>
Contact [technical support](/en/documentation/services/support/) to request a higher limit for your plan.
:::

---

## Cache TTL

The cache TTL sets how long an object stays cached on Azion edge nodes. The minimum value you can set depends on which modules the application has active, so [Application Accelerator](/en/documentation/build/application-accelerator/) and [Tiered Cache](/en/documentation/build/cache/tiered-cache/) each move that floor.

| Scope | Limit |
| --- | --- |
| Default cache TTL | 60 seconds |
| Minimum cache TTL | 60 seconds |
| Minimum cache TTL with Application Accelerator active | 0 seconds |
| Minimum cache TTL with Tiered Cache active | 3 seconds |
| Maximum cache TTL | 31,536,000 seconds |
| Default stale window | 300 seconds |

Azion applies the default [stale cache](/en/documentation/build/cache/how-it-works/#stale-cache) window when the cache setting overrides origin headers, or when the origin sends no `stale-while-revalidate` directive. When the origin sends the directive and the cache setting honors origin headers, the origin value decides how long the object is served stale.

## Object and fragment sizes

Cache stores each object on Azion edge nodes up to a maximum size. [Large File Optimization](/en/documentation/build/cache/reference/cache-settings/#large-file-optimization) splits a larger file into fragments and caches each fragment under its own cache key.

| Scope | Limit |
| --- | --- |
| Single object size in cache | 10 GB |
| Slice file size | 1,024 kB |

The slice file size is the fragment size Large File Optimization uses. To change the fragmentation range, [contact the Sales team](https://www.azion.com/en/contact-sales/).

## Tiered Cache

Tiered Cache is a Cache module that adds a second cache layer between Azion edge nodes and your origin servers. That layer carries its own TTL bounds, and they are narrower than the bounds of the cache on Azion edge nodes.

| Scope | Limit |
| --- | --- |
| Minimum TTL in Tiered Cache | 3 seconds |
| Maximum TTL in Tiered Cache | 2,592,000 seconds |

:::note
Tiered Cache does not support bypass cache. A [Bypass Cache rule](/en/documentation/build/applications/reference/rules-engine/#bypass-cache) applies to caching on Azion edge nodes. An application with an active Tiered Cache setting still caches in the tiered layer for the minimum TTL.
:::

## Real-Time Purge

[Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/) deletes cached objects before their TTL expires. The limits below bound the size of a purge argument, the rate of purge operations, and the purge history.

| Scope | Limit |
| --- | --- |
| Number of requests in history | 1,000,000 requests |
| Purge history time | 6 months |
| URL and cache key size | 4,096 characters |
| URL and cache key operations per client | 200 requests with 50 objects per request |
| URL and cache key operations per minute | 10,000 objects every 60 seconds |
| Wildcard operations per day (24-hour interval) | 2,000 requests |
| Wildcard size | 256 characters |
| Wildcards per request | 1 |

## Limits by support plan

One Cache limit changes with the support plan on the account: the number of purge operations per month.

| Scope | Developer | Business, Enterprise, and Mission-Critical |
| --- | --- | --- |
| Purge operations | 1,000 per month | 1,000 per month<br />Additional purge operations are negotiable |

For the price of purge operations, refer to [Pricing](/en/documentation/platform/pricing/#cache).
