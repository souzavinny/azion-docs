The tables on this page list the default limits for [Cache](/en/documentation/build/cache/), [Tiered Cache](/en/documentation/build/cache/tiered-cache/), and [Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/). Where a limit depends on a module or a plan, the table names that condition in its own column. The technical support team can raise a limit for your plan. To request it, contact [technical support](/en/documentation/services/support/).

## Cache TTL

A cache setting configures the TTL. The floor depends on the module the application has, and the ceiling depends on the layer that holds the object.

| Scope | Module | Minimum TTL | Maximum TTL |
| --- | --- | --- | --- |
| Edge cache TTL | None | 60 seconds | 31,536,000 seconds |
| Edge cache TTL | [Application Accelerator](/en/documentation/build/application-accelerator/) | 0 seconds | 31,536,000 seconds |
| Tiered Cache layer TTL | [Tiered Cache](/en/documentation/build/cache/tiered-cache/) | 3 seconds | 2,592,000 seconds |

A TTL of 0 seconds is not the same as a Bypass Cache rule. For the difference, refer to [How Cache works](/en/documentation/build/cache/how-it-works/).

---

## Object and fragment sizes

Cache stores one object up to the size in the table. With Large File Optimization, Cache splits an object into fragments of the size in the table.

| Scope | Limit | Condition |
| --- | --- | --- |
| Single object size in cache | 10 GB | None |
| Large File Optimization fragment size | 1,024 kB | Large File Optimization enabled |

To turn on Large File Optimization in a cache setting, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/).

---

## Tiered Cache

A cache setting with Tiered Cache keeps an object in the Tiered Cache layer for a TTL inside the range in the table.

| Scope | Limit |
| --- | --- |
| Minimum TTL in Tiered Cache | 3 seconds |
| Maximum TTL in Tiered Cache | 2,592,000 seconds |

A Bypass Cache rule does not reach the Tiered Cache layer, which keeps the object in cache for the minimum TTL. For more information, refer to [Tiered Cache](/en/documentation/build/cache/tiered-cache/).

## Real-Time Purge

Real-Time Purge removes objects from the cache before their TTL ends. Each purge type, and the purge history, has a limit in the table.

| Scope | Limit |
| --- | --- |
| Requests kept in the purge history | 1,000,000 requests |
| Purge history retention | 6 months |
| URL and cache key length | 4,096 characters |
| URL and cache key purge operations per client | 200 requests with 50 objects per request |
| URL and cache key purge operations per minute | 10,000 objects every 60 seconds |
| Wildcard purge operations per day (24-hour interval) | 2,000 requests |
| Wildcard expression length | 256 characters |
| Wildcard expressions per request | 1 expression |

The number of purge operations per month depends on the Support service of the account:

| Scope | Developer | Business, Enterprise, and Mission-Critical |
| --- | --- | --- |
| Purge operations | 1,000 per month | 1,000 per month<br />Additional purge operations are negotiable |

For the purge types, their arguments, and the layers they reach, refer to [Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/).
