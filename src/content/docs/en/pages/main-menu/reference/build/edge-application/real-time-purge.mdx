**Real-Time Purge** removes cached objects from [Cache](/en/documentation/build/cache/) before their TTL expires. A purge names the objects by URL, by cache key, or by wildcard expression, and runs against the Cache layer or the Tiered Cache layer. After the purge, the next request for an object fetches the latest version from the origin.

To run a purge from Azion Console, the API, or the CLI, refer to [Purge cached content](/en/documentation/build/cache/guides/purge-content/).

---

## Purge layers

A purge runs against one of two layers. The Tiered Cache layer accepts a purge only when the [Tiered Cache](/en/documentation/build/cache/tiered-cache/) module is active on the application.

| Layer | What it purges | Value in the CLI and `azion.config.js` |
| --- | --- | --- |
| Cache | Objects cached on Azion edge nodes | `cache`, the default |
| Tiered Cache | Objects cached in the second cache layer, between the edge nodes and the origin | `tiered_cache` |

When an application uses both layers, purge the Tiered Cache layer first and the Cache layer second. In that order, the edge nodes do not fill again from outdated Tiered Cache content. A wildcard purge runs against the Cache layer only.

## Purge types

Each purge type takes one kind of argument and matches cached objects in its own way. The argument formats and examples are in the sections that follow.

| Type | Argument | What it matches | Layers | Limits |
| --- | --- | --- | --- | --- |
| URL purge | A list of URLs | The cache key each URL converts to, with no content variation | Cache, Tiered Cache | URL size, objects per request, and objects per minute in [Limits](#limits) |
| Cache key purge | A list of cache keys | Exactly the cache keys listed, one per variation | Cache, Tiered Cache | Cache key size, objects per request, and objects per minute in [Limits](#limits) |
| Wildcard purge | One wildcard expression | Every cached object whose cache key matches the expression | Cache | Expression size, one expression per request, and requests per day in [Limits](#limits) |

### URL purge

A URL purge is non-recursive: only the URLs entered are purged. Each URL converts to its cache key without any content variation. Variations based on cookies, device groups, image format, or other markers do not expire with a URL purge. To purge them, use a [cache key purge](#cache-key-purge) or a [wildcard purge](#wildcard-purge).

A query string is a component of the URL, so a URL purge does expire a query string variation. The arguments must appear in the order in which the request presented them. With [Query String Sort](/en/documentation/build/cache/reference/cache-settings/) enabled, sort the arguments alphabetically in the purge, or use a cache key purge or a wildcard purge.

The argument follows the format `scheme://host` or `host`, with an optional `/path` and an optional `?query-string`. Without a scheme, the purge removes both the HTTP and the HTTPS content.

:::caution
An asterisk (`*`) in a URL purge argument is a character in the URL, not a wildcard.
:::

Valid URL purge arguments:

- `http://www.example.com`
- `http://static.example.com/include/site.css`
- `https://static.example.com/include/site.js`
- `dynamic.example.com/app.py?argument`

### Cache key purge

A cache key purge takes a list of cache keys and purges exactly those keys. A cache key concatenates the scheme, host, path, and query string of a request, plus a `@@` separator with any variation. For the full format and the debug header that returns the key of an object, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

A cache key identifies one variation of an object: a query string or Query String Sort argument, a cookie set by Advanced Cache Key, or an image format from [Image Processor](/en/documentation/build/image-processor/). To purge every variation of an object, list each cache key individually.

Cache key purge arguments for the object `https://static.example.com/page/site.js`:

- `httpsstatic.example.com/page/site.js`
- `httpsstatic.example.com/page/site.js@@`, the key when variations are enabled

### Wildcard purge

A wildcard purge takes one expression and purges every cached object whose cache key matches it. The expression follows the format `scheme://host` or `host`, with an optional `/path` and `?query-string`, and an asterisk (`*`) in the path or the query string. An expression can hold more than one asterisk to match a complex path pattern.

A wildcard purge does not reach the Tiered Cache layer. Each request carries one expression, and the purge requires the **Wildcard Purge** permission listed in [Permissions](#permissions).

Valid wildcard purge arguments:

- `www.example.com/*`
- `static.example.com/include/*.css`
- `static.example.com/*/site.js`
- `static.example.com/static/images/image_1.jpg?ims=*`
- `www.example.com/alpha*`
- `www.example.com/*beta*`
- `www.example.com/*a*/charlie`
- `www.example.com/*a*/*a*`
- `www.example.com/*?b*`
- `www.example.com/*?*2*c=*`

## Content variations

A variation is a cached copy of an object under a cache key that carries an extra marker, such as a cookie value or an image format. A cache key purge lists every variation individually; a wildcard purge matches them with an asterisk in the position the table shows. The markers themselves are documented on [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

| Variation | Produced by | Cache key purge | Wildcard purge |
| --- | --- | --- | --- |
| Cookie | Cache by Cookie, an Advanced Cache Key option of [Application Accelerator](/en/documentation/build/application-accelerator/) | One cache key per variation | `@@*` at the end of the expression |
| Query string | Cache by Query String, an Advanced Cache Key option of Application Accelerator | One cache key per variation | `?*` at the end of the expression |
| Image format | Image Processor | One cache key per variation | `*` at the end of the expression |
| File fragment | Large File Optimization | One cache key per fragment | `*` after the file name, as in `static.example.com/media/file.mp4*` |
| `POST` or `OPTIONS` body | HTTP method caching in Application Accelerator | One cache key per variation | `@@*` at the end of the expression |

A URL purge also expires a query string variation when the URL carries only the arguments used in the cache key. With Query String Sort, those arguments go in alphabetical order.

A cache key for an image treated by Image Processor carries the `?` separator, the key-value pairs of the processing, and the `@@` separator before the format. Cache key purge arguments for one such image:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

:::caution
When you purge individual fragments of a large file, outdated fragments can remain in cache after the content changes at the origin. A wildcard purge with `*` after the file name removes every fragment.
:::

## `DEL` method

The `DEL` method removes an object from the cache instead of a Real-Time Purge. After a `DEL`, the first `GET` request for the object goes to the origin. The method also prevents Azion from delivering a stale object when the origin is inaccessible: the request receives an error page instead. Stale delivery is described in [How Cache works](/en/documentation/build/cache/how-it-works/).

Use `DEL` to:

- Remove content from Azion's cache after it is removed from the origin.
- Force the removal and later update of content whose timestamp is unreliable.
- Force an error page instead of a stale object when the origin is inaccessible.

In the API v3 form of `azion.config.js`, a purge entry selects the method with `method: 'delete'`.

## Execution and history

A new purge returns a success message that confirms its creation. The purge is then queued for execution and appears in the history once completed, because the result can take some time to propagate to all edge nodes. The `Purge` response of Azion Libraries carries a `state` of `pending` or `executed`.

The purge history can be filtered by the user who made the purge, the time, the argument list, the purge type, and the method. The number of requests the history holds and the time it keeps them are in [Limits](#limits).

## Permissions

Two team permissions control who can purge. Both are documented on [Teams permissions](/en/documentation/account/reference/teams-permissions/).

| Permission | Grants |
| --- | --- |
| Real-Time Purge | Permission to add a new purge to Real-Time Purge |
| Wildcard Purge | Permission to select the purge type **Wildcard** in Real-Time Purge. Requires the permission **Real-Time Purge** |

## Interfaces

Every interface takes the same three purge types and, where it supports the choice, the same two layers.

| Interface | Purge form | Reference |
| --- | --- | --- |
| Azion Console | A purge with its purge type selected in **Real-Time Purge** | [Purge cached content](/en/documentation/build/cache/guides/purge-content/) |
| API | A request to the Cache Purge API | [Purge cached content](/en/documentation/build/cache/guides/purge-content/) |
| Azion CLI | `azion purge` with `--urls`, `--cachekey`, or `--wildcard`, and `--layer` | [`azion purge`](/en/documentation/devtools/cli/purge/) |
| Azion Libraries | `purgeURL`, `purgeCacheKey`, and `purgeWildCard` from `azion/purge` | [Azion Libraries, Purge](/en/documentation/products/azion-lib/purge/) |
| `azion.config.js` | A `purge` array with `type`, `items`, and `layer` | [`azion.config.js`](/en/documentation/devtools/cli/configs/azion-config-js/) |

### `azion purge` flags

| Flag | Purpose | Values |
| --- | --- | --- |
| `--urls` | A list of URLs to purge from Azion Cache | URLs |
| `--cachekey` | A list of URLs including the cache keys to purge from Azion Cache | Cache keys |
| `--wildcard` | The wildcard URL or cache key of the objects to purge; one expression per request | One wildcard expression |
| `--layer` | The layer the purge runs on | `cache`, the default, or `tiered_cache` |
| `--help` | Displays more information about the purge command | None |

### `purge` block in `azion.config.js`

Each entry of the `purge` array carries a `type` of `url`, `cachekey`, or `wildcard`, an `items` list, and an optional `layer` of `cache` or `tiered_cache`. A `purge` array with a URL purge on the Cache layer and a wildcard purge:

<Code lang="javascript" code={`purge: [
  {
    type: 'url',
    items: ['https://example.com/path/to/purge'],
    layer: 'cache',
  },
  {
    type: 'wildcard',
    items: ['https://example.com/images/*'],
  },
],`} />

## Object versioning

A version marker in the object name turns each update into a new object for Azion. Instead of `image.jpg`, name the object `image_1.jpg` and rename it `image_2.jpg` at the next update; a sequential number or a timestamp both serve as the marker. Each update is then a new object, so a request returns the version you name even when a browser or an intermediate cache holds the previous one. Versioned names also let you serve different versions to different users and roll back an update. To build a cache around versioned names, refer to [Build a versioned asset cache](/en/documentation/build/cache/tutorials/versioned-asset-cache/).

## Limits

:::tip
**Increase limits** <br />
You can request to increase the limits based on your plan. Contact the [technical support team](/en/documentation/services/support/) to request it.
:::

These are the **default limits**:

| Scope | Limit |
| --- | --- |
| Number of requests in history | 1,000,000 |
| Purge history time | 6 months |
| URL and Cache Key size | 4,096 characters |
| URL and Cache Key (operations per client) | 200 requests with 50 objects per request |
| URL and Cache Key (Operations per minute) | 10,000 objects every 60 seconds |
| Wildcard - Operations per day (24h interval) | 2,000 requests |
| Wildcard size | 256 characters |
| Wildcard per request | 1 |

These are the **default limits** for each Support service:

| Scope | Developer | Business, Enterprise, and Mission-Critical |
| --- | --- | --- |
| Purge operations | 1,000 per month | 1,000 per month<br />Additional purge operations are negotiable |

Purges are billed per 1,000 purges. For more information, refer to [Pricing](/en/documentation/platform/pricing/#cache).
