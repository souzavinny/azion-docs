**Real-Time Purge** deletes cached objects at Azion before their TTL expires. A [Cache](/en/documentation/build/cache/) policy decides how long an object stays cached, and a purge ends that period early. Azion then fetches the current version from the origin on the next request for the object.

Every purge names one layer, one type, and a list of arguments. The type decides which cached objects the arguments reach, because a purge reaches an object only when the argument matches that object's cache key.

---

## Purge layers

Real-Time Purge acts on one cache layer per request. **Cache** holds the objects stored on Azion edge nodes. **Tiered Cache** holds the second cache layer, between those edge nodes and the origin.

| Layer | What it holds | Purge types accepted |
| --- | --- | --- |
| Cache | Objects cached on Azion edge nodes | URL, cache key, wildcard |
| Tiered Cache | Objects cached on the second layer, between the edge nodes and the origin | URL, cache key |

The Tiered Cache layer accepts a purge only while the [Tiered Cache](/en/documentation/build/cache/tiered-cache/) module is active. An object held on both layers needs one purge per layer, and the order matters: purge Tiered Cache first and Cache second. In the other order, an edge node can refill its cache from the outdated copy still held on the tiered layer.

---

## Purge types

Real-Time Purge accepts three types, and each type takes a different argument. The type also decides whether a purge reaches the [content variations](#content-variations) of an object, because a variation carries its own cache key.

| Type | Argument | What it reaches |
| --- | --- | --- |
| [URL purge](#url-purge) | A list of URLs | The listed URLs, converted to their cache keys, with no variations |
| [Cache key purge](#cache-key-purge) | A list of cache keys | The object each listed cache key indexes, variations included |
| [Wildcard purge](#wildcard-purge) | One wildcard expression | Every cache key the expression matches |

## URL purge

A URL purge takes a list of URLs and expires the cached object behind each one. Azion converts every URL in the list to its cache key before purging, without considering content variations of the same URL. The operation is non-recursive: it purges the URLs in the list and nothing else.

Each URL follows the format `scheme://host`, or `host` alone, followed optionally by a `/path` and a `?query-string`. When the scheme is omitted, the purge covers both the HTTP and the HTTPS copies of the content.

For example:

- `http://www.example.com`
- `http://static.example.com/include/site.css`
- `https://static.example.com/include/site.js`
- `dynamic.example.com/app.py?argument`

A URL purge does expire variations based on query string, because the query string is part of the URL. Send the arguments in the same order the request presented them. When [Query String Sort](/en/documentation/build/cache/reference/cache-settings/#cache-by-query-string) is turned on, sort the arguments alphabetically in the request, or use a cache key purge or a wildcard purge instead.

:::note
Variations based on cookies, device groups, image format, or any other criterion do not expire with a URL purge. Use a [cache key purge](#cache-key-purge) or a [wildcard purge](#wildcard-purge) for those.
:::

:::caution
An asterisk (`*`) in a URL purge argument counts as a literal character of the URL, not as a wildcard.
:::

## Cache key purge

A cache key purge takes a list of [cache keys](/en/documentation/build/cache/reference/cache-keys/) and expires the object each key indexes. A cache key identifies one variation of an object, so this type reaches variations that a URL purge does not: query string and query string sort arguments, cookies configured through [Advanced Cache Key](/en/documentation/build/cache/reference/cache-settings/#advanced-cache-key), and the image formats [Image Processor](/en/documentation/build/image-processor/) produces for the browsers that support them.

A cache key concatenates the scheme, the host, the path, the query strings, and the variation separator, with no `://` between the scheme and the host. Cache keys are case sensitive, so uppercase and lowercase characters index different objects. To reach every variation of an object, list each variation's cache key individually, or use a [wildcard purge](#wildcard-purge).

Image Processor cache keys show the full form, with the processing arguments and the format variation:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

## Wildcard purge

A wildcard purge takes one wildcard expression per request and expires every cache key the expression matches. The expression follows the format `scheme://host`, or `host` alone, followed optionally by a `/path` and a `?query-string`. An asterisk (`*`) goes in the path or in the query string, and several asterisks in one expression match a more complex path pattern.

For example:

- `www.example.com/*`
- `static.example.com/include/*.css`
- `static.example.com/*/site.js`
- `static.example.com/static/images/image_1.jpg?ims=*`
- `www.example.com/alpha*`
- `www.example.com/*beta*`
- `www.example.com/*a*/charlie`
- `www.example.com/*a*/*a*`
- `www.example.com/*?b*`
- `www.example.com/*?*2*c=*`

:::note
The Tiered Cache layer does not accept a wildcard expression. Purge Tiered Cache content with a [URL purge](#url-purge) or a [cache key purge](#cache-key-purge).
:::

## Content variations

A purge reaches a content variation only when its argument matches that variation's cache key. Each feature that varies an object writes its own separator and value into the cache key, and the purge argument carries the same form. Cache by Cookie and Cache by Query String are [Advanced Cache Key](/en/documentation/build/cache/reference/cache-settings/#advanced-cache-key) options, provided by the [Application Accelerator](/en/documentation/build/application-accelerator/) module.

| Variation source | Cache key form | Purge with |
| --- | --- | --- |
| Cache by Cookie | `@@` followed by the cookie names and values, each closed by `;` | A cache key purge listing each variation, or a wildcard purge ending in `@@*` |
| Cache by Query String | The query separator and the arguments, in the order the request sent them | A cache key purge listing each variation, a wildcard purge ending in `?*`, or a URL purge carrying only the cache key arguments |
| [Image Processor](/en/documentation/build/image-processor/) | The `?` separator, the key-value pairs of the processing, and `@@` followed by the browser image format | A cache key purge listing each variation, or a wildcard purge ending in `*` |
| [Device Groups](/en/documentation/build/applications/reference/device-groups/) | `@@` followed by the device group name | A cache key purge listing each variation, or a wildcard purge |
| [Large File Optimization](/en/documentation/build/cache/reference/cache-settings/#large-file-optimization) | `@@bytes=` followed by the byte range of each fragment | A cache key purge listing every fragment, or a wildcard purge with `*` after the file path |
| Cached `POST` and `OPTIONS` requests | `@@` followed by the MD5 hash of the request body | A cache key purge listing each variation, or a wildcard purge ending in `@@*` |

One wildcard expression reaches every fragment of a file split by Large File Optimization, such as `static.example.com/media/file.mp4*`.

Azion caches `GET` and `HEAD` requests by default. Caching for `POST` and `OPTIONS` requires the Application Accelerator module.

:::caution
Purging fragments one at a time can leave outdated fragments in cache when the content changes at the origin.
:::

## DEL method

The `DEL` method is an alternative to Real-Time Purge for removing an object from cache. After a `DEL`, the first `GET` request for that object goes to the origin, as it does after a purge. The two differ when the origin is unreachable: Azion serves no [stale copy](/en/documentation/build/cache/how-it-works/#stale-cache) of an object removed with `DEL`, and returns an error page instead.

## Purge execution and history

Azion confirms a purge as soon as it accepts the request, then queues the purge for execution. Results take time to propagate to every edge node, so the purge appears in the purge history once it completes. A purge response carries a `state` field, either `pending` or `executed`, and an `items` field listing what the purge covered.

The purge history records the user who issued the purge, the time, the argument list, the purge type, and the method. You can filter the history on any of those fields.

## Permissions

Issuing a purge requires the **Real-Time Purge** team permission, which grants adding a new purge. Selecting the **Wildcard** type additionally requires the **Wildcard Purge** permission, which itself requires **Real-Time Purge**.

## Interfaces

A purge is issued from [Azion Console](https://console.azion.com/), the Azion API, the [Azion CLI](/en/documentation/products/azion-cli/overview/), or the Azion libraries. The purge API is a top-level resource rather than a sub-resource of an application, so a purge request names no application.

| Interface | How a purge is issued |
| --- | --- |
| Azion Console | **Products menu** > **Tools** > **Real-Time Purge** |
| API | `POST` to `https://api.azion.com/v4/workspace/purge/url` or `https://api.azion.com/v4/workspace/purge/wildcard` |
| Azion CLI | `azion purge` with `--urls`, `--cachekey`, or `--wildcard` |
| Azion libraries | `purgeURL`, `purgeCacheKey`, or `purgeWildCard` from `azion/purge` |
| `azion.config.js` | A `purge` entry whose `type` is `url`, `cachekey`, or `wildcard` |

The API body carries the arguments in `items` and the layer in `layer`. The `layer` field is optional, and its values are `cache`, the default, and `tiered_cache`. Purge two URLs from the Cache layer:

<Code lang="bash" code={`curl -X POST 'https://api.azion.com/v4/workspace/purge/url' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
    "items": [
      "https://www.example.com/image.jpg",
      "https://www.example.com/styles.css"
    ],
    "layer": "cache"
  }'`} />

The response carries the purge `state` and the `items` it covered.

The Azion CLI takes the same two layer values in its `--layer` flag and defaults to `cache`. A cache key argument keeps its separators, and a comma separates two arguments:

<Code lang="bash" code={`azion purge --urls "https://www.example.com/image.jpg" --layer tiered_cache

azion purge --cachekey "www.example.com/@@cookie_name=cookie_value,www.example.com/test.js"`} />

## Limits

Real-Time Purge limits the size and the rate of purge arguments, and each Support plan includes a set number of purge operations. The limited scopes are:

- The size of a URL or cache key argument, and the size of a wildcard expression.
- The number of objects per request, per client, and per minute.
- The number of wildcard requests per day, and the number of wildcard expressions per request.
- The number of purge requests kept in the history, and how long the history is retained.

For the values, refer to [Cache limits](/en/documentation/build/cache/limits/#limits-by-support-plan).

:::tip
**Increase limits** <br></br>
Contact [technical support](/en/documentation/services/support/) to request a higher limit for your plan.
:::
