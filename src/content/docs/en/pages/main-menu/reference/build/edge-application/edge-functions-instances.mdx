A function instance is the object that binds one function to one application or one firewall. The function, created in [Functions](/en/documentation/build/functions/), holds the code. The instance holds a name, a JSON object of arguments, and the association with the [application](/en/documentation/build/applications/) or [firewall](/en/documentation/secure/firewall/) that runs it.

## Functions and their instances

A function exists on its own. You create it and save it in Functions, or use one available from **Azion Marketplace**, before any instance refers to it. Instantiation creates a second object, the instance, and leaves the function's code unchanged. Only the instance's name, arguments, and association are set. One function can have instances on several applications, and each instance carries its own arguments.

An application or a firewall accepts instances only after its **Functions** module is turned on. The module is a setting of the application or the firewall, not of the function. An instance runs only when a rule in [Rules Engine](/en/documentation/build/applications/reference/rules-engine/) names it in the **Run Function** behavior.

## Instance fields

One instance has the fields below. The Azion API accepts `name`, `edge_function`, `args`, and `active` in a create request and assigns the rest. In Azion Console, the function comes from the **Functions** list and the arguments go in the **Arguments** field.

| Field | API key | Type | Set by | Description |
| --- | --- | --- | --- | --- |
| Name | `name` | string | You | The name of the instance. Azion Console lists the instance by this name in the **Functions Instances** tab and in the **Run Function** behavior. |
| Function | `edge_function` | integer | You | The ID of the function the instance runs. It is not the ID of the instance. |
| Arguments | `args` | JSON object | You | The arguments passed to the function's execution context, up to 100 KB. Some functions take no arguments. A firewall instance response returns this key as `json_args`. |
| Active | `active` | boolean | You | Whether the instance is turned on. |
| ID | `id` | integer | Azion | The ID of the instance, unique to the instance. The **Run Function** behavior refers to the instance by this value. |
| Last editor | `last_editor` | string | Azion | The account that last changed the instance. |
| Last modified | `last_modified` | string | Azion | The date and time of the last change. |

## JSON arguments

Arguments are a JSON object the instance passes to the function's execution context. They let one function behave differently on each instance without a change to its code. In Azion Console, the object goes in the **Arguments** field of the instance. In the API, it is the `args` key of the instance.

In the legacy Service Worker handler pattern, the code reads the argument stored under a key with `event.args("<key>")`. For the handler patterns and their parameters, refer to [Handlers](/en/documentation/build/functions/reference/handlers/).

The object is limited to 100 KB per instance. For that ceiling and every other limit, refer to [Functions limits](/en/documentation/build/functions/limits/).

## Argument defaults and overrides

A function carries default arguments, `default_args`, set when the function is created or edited. The defaults are the basis for every instance of the function. The arguments set on an instance override the defaults key by key. A key the instance sets takes the instance's value, and a key the instance does not set keeps the function's default.

The function defines these default arguments:

```json
{
  "threshold": 100,
  "action": "deny",
  "log_level": "info"
}
```

The instance sets these arguments:

```json
{
  "threshold": 50,
  "action": "block"
}
```

The function receives these arguments:

```json
{
  "threshold": 50,
  "action": "block",
  "log_level": "info"
}
```

In this example, `threshold` and `action` take the instance's values, and `log_level` keeps the function's default.

## Run Function behavior

An instance is idle until a rule in [Rules Engine](/en/documentation/build/applications/reference/rules-engine/) names it. The rule pairs criteria with the **Run Function** behavior, and the behavior's value is the instance. When a request matches the criteria, the instance's function runs on Azion edge nodes. On an application, the rule also sets the phase in which the function runs. On a firewall, the function runs in the request phase. A new or changed rule takes a few minutes to propagate across Azion's distributed network.

In the API, the behavior is one item of the rule's `behaviors` array:

| Side | `type` | Attribute that names the instance |
| --- | --- | --- |
| Application | `run_function` | `attributes.value`, set to the instance `id` |
| Firewall | `run_function` | `attributes.function_instance_id`, set to the instance `id` |

## Instances on applications and on firewalls

The same instance object exists on both sides of the platform. The table lists what differs.

| Property | On an application | On a firewall |
| --- | --- | --- |
| Parent object | The application | The firewall |
| Module that must be on | The application's **Functions** module | The firewall's **Functions** module, in its **Main Settings** tab |
| Handler that runs | `fetch`, which returns a response | `firewall`, which calls `ctx.deny()` to block the request or returns to let it continue |
| Phase | The phase the rule selects | Request phase |
| Rule that triggers it | A rule in the application's **Rules Engine** tab | A rule in the firewall's **Rules Engine** tab |
| Instance endpoint | `/v4/edge_application/applications/<your-application-id>/functions` | `/v4/edge_firewall/firewalls/<your-firewall-id>/functions` |
| Run Function attribute | `attributes.value` | `attributes.function_instance_id` |
| Arguments key in the response | `args` | `json_args` |

For the firewall side of the object, refer to [Functions Instances for Firewall](/en/documentation/secure/firewall/reference/functions-instances/). For the two handler signatures, refer to [Handlers](/en/documentation/build/functions/reference/handlers/).

## Interfaces

Instances are managed in [Azion Console](https://console.azion.com/) and through the [Azion API](https://api.azion.com/). The table lists where each object lives in Azion Console.

| Object | Location in Azion Console |
| --- | --- |
| Functions module of an application | **Applications** > the application, **Functions** module switch |
| Functions module of a firewall | **Firewall** > the firewall > **Main Settings** tab, **Functions** module switch |
| Instances of an application | **Applications** > the application > **Functions Instances** tab. **+ Function Instance** creates one. |
| Instances of a firewall | **Firewall** > the firewall > **Functions Instances** tab. **+ Function Instance** creates one. |
| Rule that runs an instance | **Rules Engine** tab of the application or the firewall, **Run Function** behavior |

The Azion API serves every call below at `https://api.azion.com`, with the header `Authorization: Token [TOKEN VALUE]`.

| Action | Method and path | Body keys |
| --- | --- | --- |
| Turn on the Functions module of an application | `PATCH /v4/edge_application/applications/<your-application-id>` | `modules.edge_functions.enabled: true` |
| Turn on the Functions module of a firewall | `PATCH /v4/edge_firewall/firewalls/<your-firewall-id>` | `modules.edge_functions.enabled: true` |
| List functions and their IDs | `GET /v4/edge_functions/functions` | None |
| Create an instance on an application | `POST /v4/edge_application/applications/<your-application-id>/functions` | `name`, `edge_function`, `args`, `active` |
| Create an instance on a firewall | `POST /v4/edge_firewall/firewalls/<your-firewall-id>/functions` | `name`, `edge_function`, `args`, `active` |
| Create a request rule that runs an instance on an application | `POST /v4/edge_application/applications/<your-application-id>/request_rules` | `behaviors[].type`, `behaviors[].attributes.value` |
| Create a request rule that runs an instance on a firewall | `POST /v4/edge_firewall/firewalls/<your-firewall-id>/request_rules` | `behaviors[].type`, `behaviors[].attributes.function_instance_id` |

A create request carries the four fields you set:

```json
{
  "name": "<your-instance-name>",
  "edge_function": <your-function-id>,
  "args": {},
  "active": true
}
```

To instantiate a function from Azion Console or the API, refer to [Instantiate functions](/en/documentation/build/functions/guides/instantiate-functions/).

| Limit | Value | Past the limit |
| --- | --- | --- |
