This guide instructs you through running your first function on Azion.

By the end, you will have:

- Written a function in Azion Console.
- Turned on the Functions module in an application.
- Instantiated the function in that application.
- Triggered the function with a Rules Engine rule.
- Confirmed that a request runs the function.

A function answers a request only after four objects exist and point at each other, in this order:

1. A function: the JavaScript code. The function belongs to your account, and you can reuse it in more than one application.
2. An application with the Functions module turned on. Without the module, the application cannot run a function.
3. A function instance: the link between one function and one application. The instance has its own ID, and each application keeps its own instances.
4. A rule in [Rules Engine](/en/documentation/build/applications/reference/rules-engine/): the trigger. The rule's **Run Function** behavior names the function instance, and the rule's criteria decide which requests run it.

Nothing invokes a function on its own. The rule is what turns a stored function into a response.

---

## Prerequisites

- An Azion account with access to [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/).
- An application. To create one, refer to [Applications quickstart](/en/documentation/build/applications/quickstart/).

---

## 1. Write your first function

You write function code in Azion Console, in the [Functions Code Editor](/en/documentation/products/applications/functions/runtime-api/code-editor/).

A function for an application answers a `fetch` event. The recommended form exports a default object whose `fetch` property receives the request, the environment, and the execution context, and returns a `Response`.

To write the function:

1. Access [Azion Console](https://console.azion.com/) > **Functions**.
2. Select **+ Function**.
3. Enter a name for the function. For example: `Hello World`.
4. Replace the editor's contents with this code:

<Code lang="javascript" code={`const html = \`<!DOCTYPE html>
<body>
  <h1>Hello World</h1>
  <p>This markup was generated by Azion - Functions.</p>
</body>\`;

export default {
  fetch: (request, env, ctx) => {
    return new Response(html, {
      headers: { 'content-type': 'text/html;charset=UTF-8' },
    });
  },
};`} />

5. Select **Save**.

The function belongs to your account, and any application on that account can instantiate it.

:::note
Azion also runs the older Service Worker form, which registers a handler with `addEventListener('fetch', ...)`. It is kept for backward compatibility. For both forms and how to move between them, refer to [Handlers](/en/documentation/build/functions/reference/handlers/).
:::

## 2. Turn on the Functions module

An application runs a function only after you turn on its Functions module. The module is a setting on the application, so you turn it on once per application. Every function instance in that application uses it.

:::caution
Computing time and invocations on an application with **Functions** turned on can generate usage costs. For more information, refer to [Pricing](/en/documentation/platform/pricing/#functions).
:::

To turn on the module:

1. Access [Azion Console](https://console.azion.com/) > **Applications**.
2. Select the application you want to configure.
3. Turn on the **Functions** module.
4. Select **Save**.

The application accepts function instances.

---

## 3. Instantiate the function in your application

A [function instance](/en/documentation/build/functions/reference/functions-instances/) links one function to one application. The instance carries its own name and its own ID. That ID is not the ID of the function it points to. Creating an instance does not run the code: the instance stays idle until a rule names it.

To instantiate the function:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > your application.
2. Go to the **Functions Instances** tab.
3. Select **+ Function Instance**.
4. Enter a name for the instance. For example: `Hello World function`.
5. Select the function you created.
6. Select **Save**.

The **Functions Instances** tab lists the new instance.

---

## 4. Trigger the function with a rule

Rules Engine decides which requests run your function instance. A rule pairs criteria with behaviors: the criteria match the request, and the **Run Function** behavior names the instance to run. This rule matches the URI `/hello-world`.

To create the rule:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > your application.
2. Go to the **Rules Engine** tab.
3. Select **+ Rule**.
4. Enter a name for the rule.
5. Select **Request Phase**.
6. In the **Criteria** section, select the `${uri}` variable. Azion Console can select it for you when the **Application Accelerator** module is off.
7. Select **is equal** as the comparison operator.
8. Enter `/hello-world` as the argument.
9. In the **Behaviors** section, select **Run Function**.
10. Select the function instance you created.
11. Select **Save**.

The rule runs your function instance on every request whose URI is `/hello-world`.

---

## 5. Verify that the function answers

Your application answers on a domain in the format `xxxxxxxxx.map.azionedge.net`. The rule created in Rules Engine runs the function instance on the `/hello-world` path of that domain.

To confirm the function answers:

<Code lang="bash" code={`curl https://<your-azion-domain>/hello-world`} />

The function returns the markup it builds:

```html
<!DOCTYPE html>
<body>
  <h1>Hello World</h1>
  <p>This markup was generated by Azion - Functions.</p>
</body>
```

The request to `/hello-world` runs your function instance.

New rules take a few minutes to propagate. On an unexpected response, wait and retry before you diagnose the function.
