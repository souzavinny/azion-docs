A cache setting is the object that carries the caching policy of an application on the [Cache](/en/documentation/build/cache/) module of [Applications](/en/documentation/build/applications/). A new application starts with one cache setting, created and active by default. A cache setting applies to requests through the [Set Cache Policy](/en/documentation/build/applications/reference/rules-engine/#set-cache-policy) behavior of a Rules Engine rule.

For the lookup path that a cache setting controls, refer to [How Cache works](/en/documentation/build/cache/how-it-works/).

## Cache setting object

The table lists every key of the request body that creates a cache setting through the API. Nested keys are written as dotted paths from the top of the body.

| Key | Values | Description |
| --- | --- | --- |
| `name` | string | The name of the cache setting. |
| `browser_cache.behavior` | `"honor"`, `"override"` | `"honor"` keeps the cache headers the origin sends; `"override"` applies `browser_cache.max_age`. |
| `browser_cache.max_age` | integer, seconds | The browser TTL when `browser_cache.behavior` is `"override"`. |
| `modules.edge_cache.behavior` | `"honor"`, `"override"` | `"honor"` uses the TTL headers from the origin; `"override"` applies `modules.edge_cache.max_age`. |
| `modules.edge_cache.max_age` | integer, seconds | The edge cache TTL when the origin headers are overridden. |
| `modules.edge_cache.stale_cache.enabled` | boolean | Serves expired content while the origin is unavailable or while updated content is fetched. |
| `modules.edge_cache.large_file_cache.enabled` | boolean | Caches large files in fragments. |
| `modules.edge_cache.large_file_cache.offset` | integer, kilobytes | The fragment size. Defaults to `1024`. |
| `modules.tiered_cache.topology` | `"near-edge"`, `"near-origin"` | The [Tiered Cache](/en/documentation/build/cache/tiered-cache/) topology, where supported. |
| `modules.application_accelerator.cache_vary_by_method` | list of `"post"`, `"options"` | The HTTP methods that vary the cache key. |
| `modules.application_accelerator.cache_vary_by_querystring.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | How query string fields vary the cache key. |
| `modules.application_accelerator.cache_vary_by_querystring.fields` | list of strings | The query string fields the behavior allows or blocks. |
| `modules.application_accelerator.cache_vary_by_querystring.sort_enabled` | boolean | Sorts the query string fields before the cache key is computed. |
| `modules.application_accelerator.cache_vary_by_cookies.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | How cookies vary the cache key. |
| `modules.application_accelerator.cache_vary_by_cookies.cookie_names` | list of strings | The cookie names that vary the cache key. |
| `modules.application_accelerator.cache_vary_by_devices.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | How device groups vary the cache key. |
| `modules.application_accelerator.cache_vary_by_devices.device_group` | list of integers | The IDs of the device groups that vary the cache key. |

The keys under `modules.application_accelerator` take effect when the [Application Accelerator](/en/documentation/build/application-accelerator/) module is active on the application. For a complete request body, refer to [Configure a cache policy using the API](/en/documentation/build/cache/guides/tune-cache-settings/).

## Browser Cache Settings

**Browser Cache Settings** sets how long a browser keeps a copy of the content. The TTL travels in the `Cache-Control` and `Expires` HTTP headers. The `max-age` directive of `Cache-Control` sets the TTL; when `Cache-Control` is absent, the timestamp in `Expires` does.

| Option | Effect |
| --- | --- |
| _Honor Origin Cache Headers_ | Keeps the cache headers the origin sends and forwards the same headers to the browser. |
| _Override Cache Settings_ | Replaces the origin TTL with the value in **Max Age (seconds)**. |

## CDN Cache Settings

**CDN Cache Settings** sets how long Azion edge nodes keep a copy of the content.

| Option | Effect |
| --- | --- |
| _Honor Origin Cache Headers_ | Uses the TTL that the origin sends in its `Cache-Control` and `Expires` headers. |
| _Override Cache Settings_ | Replaces the origin TTL with the value in **Max Age (seconds)**. |

With _Honor Origin Cache Headers_, **Max Age (seconds)** sets the TTL used when the origin sends no cache headers or sends invalid values.

The edge cache TTL runs from 60 to 31,536,000 seconds; from 0 seconds with Application Accelerator; from 3 seconds with Tiered Cache. Refer to [Cache limits](/en/documentation/build/cache/limits/). A TTL of 0 is not a cache bypass; for the difference, refer to [Bypass Cache](/en/documentation/build/applications/reference/rules-engine/#bypass-cache).

## Stale Cache

**Stale Cache** serves expired cached content while the origin is unavailable or while the cached object is renewed. Stale Cache is enabled by default on a cache setting, through the **Enable Stale Cache** switch. When the origin does not supply a stale window, Azion applies a default window of 300 seconds. For the revalidation flow, refer to [How Cache works](/en/documentation/build/cache/how-it-works/).

## Large File Optimization

**Large File Optimization** splits a large file into fragments, which Azion caches on demand as the user requests them. The default fragment size is 1,024 kB. Each fragment carries its own cache key; for the `@@bytes=` marker, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

The **Large file optimization** switch applies to the edge cache layer by default. When Tiered Cache is active, the setting also applies to the tiered layer. A different fragment size is requested from the [technical support team](/en/documentation/services/support/).

## Advanced Cache Key

**Advanced Cache Key** varies the cache key by query string fields, by cookies, or by both. The feature needs the [Application Accelerator](/en/documentation/build/application-accelerator/) module active on the application. By default, Azion treats each URL as one object in cache. Field names and cookie names are case-sensitive: uppercase and lowercase letters produce different cached objects.

### Cache by Query String

**Cache by Query String** decides which query string fields distinguish cached objects.

| Option | Effect | Example |
| --- | --- | --- |
| _Content does not vary by Query String (Improves Caching)_ | The cache key ignores the query string. Two URLs that differ only in the query string are one cached object. | `http://example.com/path?queryA` and `http://example.com/path?queryB` deliver the same cached content. |
| _Content varies by some Query String fields (Whitelist)_ | Only the listed fields distinguish cached objects. All other fields are ignored. | With `city` listed, `?city=A&name=X` and `?city=A&name=Y` are one object; `?city=A&name=X` and `?city=B&name=X` are two. |
| _Content varies by Query String, except for some fields (Blocklist)_ | The listed fields are ignored. All other fields distinguish cached objects. | With `random` listed, `?city=A&random=123` and `?city=B&random=123` are two objects; `?city=A&random=123` and `?city=A&random=456` are one. |
| _Content varies by all Query String fields_ | The cache key includes every field of the query string. Two URLs that differ in the query string are two cached objects. | `http://example.com/path?queryA` and `http://example.com/path?queryB` are stored as separate objects. |

**Query String Sort** orders the fields of the query string before the cache key is built, so the position of a field does not change the key. When field position distinguishes your content, leave the option off.

### Cache by Cookie

**Cache by Cookie** decides which cookies distinguish cached objects.

| Option | Effect |
| --- | --- |
| _Content does not vary by Cookies (Improves Caching)_ | Distinguishes cached objects by URL only. Cookies are ignored. |
| _Content varies by some Cookies (Allowed Rules)_ | Only the listed cookie names distinguish cached objects. All other cookies are ignored. |
| _Content varies by Cookies, with the exception of a few (Blocklist)_ | All cookies distinguish cached objects except the listed names. |
| _Content varies by all Cookies_ | Every cookie distinguishes cached objects, in addition to the URL. |

A cookie variation appends the cookie name and value to the cache key; for the format, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

## Caching HTTP methods

By default, Cache stores only `GET` and `HEAD` responses. With Application Accelerator, two switches extend caching to further methods. For both, the request body becomes part of the cache key, so requests with different bodies are different cached objects.

| Switch | API value | Effect |
| --- | --- | --- |
| **Enable caching for POST** | `"post"` in `cache_vary_by_method` | Caches `POST` responses. |
| **Enable caching for OPTIONS** | `"options"` in `cache_vary_by_method` | Caches `OPTIONS` responses. |

The cache key of a cached `POST` or `OPTIONS` response carries a hash of the request body; for the format, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

## Adaptive Delivery

**Adaptive Delivery** keeps device-based variations of an object in cache, one per [device group](/en/documentation/build/applications/reference/device-groups/). A device group matches the `User-Agent` header of the request against a regular expression.

| Option | Effect |
| --- | --- |
| _Content varies by some Device Groups (Whitelist)_ | Keeps one cached variation per selected device group. One or more device groups can be selected. |

In the API, `cache_vary_by_devices.behavior` takes `"ignore"`, `"whitelist"`, or `"blacklist"`, and `device_group` lists the device group IDs. In the Azion CLI, `--adaptive-delivery-action` defaults to `ignore`. The cache key of a device variation ends with the device group name; for the format, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

## Interfaces

| Interface | Where a cache setting is managed |
| --- | --- |
| Azion Console | The **Cache Settings** tab of the application. **+ Cache Setting** creates one. |
| API | `POST https://api.azionapi.net/v4/edge_application/applications/<application_id>/cache_settings`. The v3 path was `/edge_applications/{id}/cache_settings`; refer to [API v4 migration](/en/documentation/devtools/api/v4-migration/). |
| Azion CLI | `azion create cache-setting --application-id <application_id> --name "<your-cache-setting-name>"`; refer to [`azion create`](/en/documentation/devtools/cli/create/). |
| `azion.config.js` | The `cache` array of an application entry, typed `AzionCache`; refer to [`azion.config.js`](/en/documentation/devtools/cli/configs/azion-config-js/). |
| Terraform | The `azion_application_cache_setting` resource and the `azion_application_cache_settings` data source; refer to [Terraform Applications resources](/en/documentation/products/terraform-provider/resources/applications/). |
| Azion Libraries | `createCacheSetting`, `getCacheSetting`, `getCacheSettings`, `updateCacheSetting`, and `deleteCacheSetting` from `azion/applications`; refer to [Azion Libraries, Application](/en/documentation/products/azion-lib/application/). |

## Azion CLI flags

`azion create cache-setting` takes `--application-id` and `--name` as required flags. The optional flags follow.

| Flag | Description |
| --- | --- |
| `--adaptive-delivery-action` | The Adaptive Delivery action. Default `ignore`. |
| `--browser-cache-settings` | How long a browser caches the content: honor or override. Default `honor`. |
| `--browser-cache-settings-maximum-ttl` | The maximum browser TTL, in seconds. |
| `--cache-by-cookies` | Whether cache varies by cookies. Default `ignore`. |
| `--cache-by-query-string` | How the content is cached according to query string variations. Default `ignore`. |
| `--cdn-cache-settings` | Whether the edge cache honors origin cache headers or overrides them. Default `honor`. |
| `--cnd-cache-settings-maximum-ttl` | The maximum edge cache TTL, in seconds. Default `60`. |
| `--cookie-names` | The cookie names that distinguish cached objects. |
| `--enable-caching-for-options` | Whether `OPTIONS` responses are cached. Default `false`. |
| `--enable-caching-for-post` | Whether `POST` responses are cached. |
| `--enable-caching-string-sort` | Whether query string fields are sorted before the cache key is built. |
| `--file` | The path to a JSON file with the attributes of the cache setting. `-` reads from stdin. |
| `--l2-caching-enabled` | Whether Tiered Cache is active. |
| `--query-string-fields` | The query string fields that distinguish cached objects for the same URL. |
| `--slice-configuration-enabled` | Whether Large File Optimization is active. |
| `--slice-configuration-range` | The fragment range. |
| `--slice-l2-caching-enabled` | Whether Large File Optimization is active on the Tiered Cache layer. |

The JSON file for `--file` also accepts `enable_stale_cache`, `device_group`, `l2_region`, and `is_slice_edge_caching_enabled`, as the [`azion create`](/en/documentation/devtools/cli/create/) reference shows.

## azion.config.js keys

An entry of the `cache` array has the `AzionCache` type.

| Key | Values | Description |
| --- | --- | --- |
| `name` | string | The name of the cache configuration. |
| `stale` | boolean | Whether stale content is allowed. |
| `queryStringSort` | boolean | Whether query string fields are sorted. |
| `tieredCache.enabled` | boolean | Whether Tiered Cache is active. |
| `tieredCache.topology` | `nearest-region`, `br-east-1`, `us-east-1` | The Tiered Cache topology. |
| `methods.post` | boolean | Whether `POST` responses are cached. |
| `methods.options` | boolean | Whether `OPTIONS` responses are cached. |
| `browser.maxAgeSeconds` | number or string | The browser TTL, in seconds. |
| `edge.maxAgeSeconds` | number or string | The edge cache TTL, in seconds. |
| `cacheByCookie.option` | `ignore`, `all`, `allowlist`, `denylist` | How cookies vary the cache key. |
| `cacheByCookie.list` | list of strings | The cookie names for `allowlist` or `denylist`. |
| `cacheByQueryString.option` | `ignore`, `all`, `allowlist`, `denylist` | How query string fields vary the cache key. |
| `cacheByQueryString.list` | list of strings | The query string fields for `allowlist` or `denylist`. |

## Limits

| Scope | Limit |
| --- | --- |
| Minimum edge cache TTL | 60 seconds |
| Minimum edge cache TTL with Application Accelerator | 0 seconds |
| Maximum edge cache TTL | 31,536,000 seconds |
| Minimum TTL in Tiered Cache | 3 seconds |
| Maximum TTL in Tiered Cache | 2,592,000 seconds |
| Slice file size | 1,024 kB |

Limits depend on the plan and are raised through the [technical support team](/en/documentation/services/support/). For every Cache limit, by plan, refer to [Cache limits](/en/documentation/build/cache/limits/).
