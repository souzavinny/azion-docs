A handler is the entry point a function exposes to [Azion Runtime](/en/documentation/runtime/overview/), which calls it with each incoming request. [Functions](/en/documentation/build/functions/) supports two handlers: `fetch`, which returns the response, and `firewall`, which decides whether the request continues. A function declares them in one of two patterns, ES Modules or Service Worker.

## Handler patterns

The two patterns declare the same handlers with different syntax. ES Modules is the recommended pattern. Service Worker is the legacy pattern, kept for backward compatibility.

| Pattern | Status | Declaration | Blocks a request in `firewall` |
| --- | --- | --- | --- |
| ES Modules | Recommended | A default export object with a `fetch` property and a `firewall` property, each a function of `(request, env, ctx)`. | `ctx.deny()` |
| Service Worker | Legacy, kept for backward compatibility | One `addEventListener` call per handler, registered for the `'fetch'` or `'firewall'` event and receiving an event object. | `event.deny()` |

---

## `fetch` handler

The `fetch` handler receives the HTTP request and returns a `Response`. In ES Modules, it is the `fetch` property of the default export:

<Code lang="javascript" code={`export default {
  fetch: async (request, env, ctx) => {
    return new Response('Hello World');
  }
};`} />

| Parameter | Type | Description |
| --- | --- | --- |
| `request` | `Request` | The incoming HTTP request object. |
| `env` | Object | Environment variables and bindings. |
| `ctx` | Object | Execution context. `ctx.waitUntil(promise)` extends the function's lifetime for an asynchronous task. |

For more information on the variables `env` carries, refer to [Environment variables](/en/documentation/products/functions/environment-variables/).

## `firewall` handler

The `firewall` handler runs in the request phase, before the `fetch` handler, and decides whether the request continues. It is declared beside `fetch` in the same default export:

<Code lang="javascript" code={`export default {
  fetch: async (request, env, ctx) => {
    return new Response('Access granted');
  },

  firewall: async (request, env, ctx) => {
    const userAgent = request.headers.get('User-Agent');

    if (userAgent && userAgent.includes('bot')) {
      ctx.deny();
      return;
    }

    // Allow the request to continue to the fetch handler
    return;
  }
};`} />

| Parameter | Type | Description |
| --- | --- | --- |
| `request` | `Request` | The incoming HTTP request object. |
| `env` | Object | Environment variables and bindings. |
| `ctx` | Object | Execution context. `ctx.deny()` blocks the request immediately. |

A call to `ctx.deny()` blocks the request immediately. When the handler returns without calling `ctx.deny()`, the request continues to the `fetch` handler. The handler returns no value and never returns a `Response`. `ctx.deny()` exists in the ES Modules pattern only. The Service Worker equivalent is `event.deny()`.

## Service Worker event handlers

The Service Worker pattern is legacy, kept for backward compatibility. Each handler is a listener registered with `addEventListener`, and it acts on the request through the event object it receives:

<Code lang="javascript" code={`addEventListener('fetch', (event) => {
  event.respondWith(handleRequest(event.request));
});

addEventListener('firewall', (event) => {
  event.deny();
});

async function handleRequest(request) {
  return new Response('Hello World');
}`} />

| Member | Description |
| --- | --- |
| `event.request` | The incoming `Request` object, in both handlers. |
| `event.respondWith(response)` | Sends the given `Response` to the client. In a `firewall` handler, it intercepts the request with a custom response. |
| `event.deny()` | Finishing outcome of a `firewall` handler. Blocks the request immediately and returns `403 Forbidden`. When it is not called, the request continues to the `fetch` handler. |
| `event.drop()` | Finishing outcome of a `firewall` handler. Closes the request without a response to the client. |
| `event.continue()` | Finishing outcome of a `firewall` handler. Lets the request continue. |
| `event.addRequestHeader(name, value)` | In a `firewall` handler, adds a header to the request sent to the origin. |
| `event.addResponseHeader(name, value)` | In a `firewall` handler, adds a header to the response sent to the client. |
| `event.waitUntil(promise)` | In a `firewall` handler, runs an asynchronous function from the synchronous listener. Without it, the promise can raise an unexpected exception. |
| `event.args("<argument-name>")` | Reads one JSON argument set on the function instance. |

A function instantiated on a firewall must end in a finishing outcome: `event.continue()`, `event.deny()`, or `event.drop()`. A handler that reaches both `event.drop()` and `event.continue()` in one run behaves unpredictably.

## Asynchronous work with `waitUntil`

`ctx.waitUntil(promise)` extends the function's lifetime for an asynchronous task that must not block the response. The function returns its `Response` while the task completes:

<Code lang="javascript" code={`export default {
  fetch: async (request, env, ctx) => {
    ctx.waitUntil(logRequest(request));

    return new Response('Hello World');
  }
};

async function logRequest(request) {
  console.log(\`Request to: \${request.url}\`);
}`} />

In the Service Worker pattern, a `firewall` listener passes its asynchronous handler to `event.waitUntil(promise)`.

## Migration from Service Worker to ES Modules

Each Service Worker construct has one ES Modules equivalent. In both patterns, a `firewall` handler that returns without denying lets the request continue to `fetch`.

| Service Worker | ES Modules |
| --- | --- |
| `addEventListener('fetch', (event) => { ... })` | `fetch: async (request, env, ctx) => { ... }` in the default export |
| `addEventListener('firewall', (event) => { ... })` | `firewall: async (request, env, ctx) => { ... }` in the same default export |
| `event.request` | `request` |
| `event.respondWith(response)` | `return response` |
| `event.deny()` | `ctx.deny()` |
| `return` without `event.deny()` | `return` without `ctx.deny()` |
| A separate `handleRequest(request)` function passed to `event.respondWith()` | The body of the `fetch` handler |

The same function before, in the Service Worker pattern:

<Code lang="javascript" code={`addEventListener('fetch', (event) => {
  event.respondWith(handleRequest(event.request));
});

async function handleRequest(request) {
  const url = new URL(request.url);

  if (url.pathname === '/api/hello') {
    return new Response(JSON.stringify({ message: 'Hello World' }), {
      headers: { 'Content-Type': 'application/json' }
    });
  }

  return new Response('Not Found', { status: 404 });
}`} />

After, in ES Modules:

<Code lang="javascript" code={`export default {
  fetch: async (request, env, ctx) => {
    const url = new URL(request.url);

    if (url.pathname === '/api/hello') {
      return new Response(JSON.stringify({ message: 'Hello World' }), {
        headers: { 'Content-Type': 'application/json' }
      });
    }

    return new Response('Not Found', { status: 404 });
  }
};`} />

## Unsupported patterns

Functions accepts only the ES Modules and Service Worker patterns. Code in any of the following shapes raises the error `Unsupported handler pattern detected`:

| Shape | Example |
| --- | --- |
| Direct function export | `export default function(request) { return new Response('Hello'); }` |
| Named export | `export function fetch(request) { return new Response('Hello'); }` |
| No export | `function handleRequest(request) { return new Response('Hello'); }` |

To clear the error, move the code into an ES Modules default export with a `fetch` property:

<Code lang="javascript" code={`export default {
  fetch: async (request, env, ctx) => {
    return new Response('Hello World');
  }
};`} />

The Service Worker pattern also clears the error. Azion treats it as a temporary measure and recommends the ES Modules pattern.

## Request metadata

A `firewall` handler reads request metadata: the client IP address and TCP port, GeoIP location, the request protocol, TLS details, server fingerprints, and request identifiers. In the Service Worker pattern, the handler reads a value by name through `event.request.metadata`:

<Code lang="javascript" code={`let ip = event.request.metadata["remote_addr"];`} />

For the full list of metadata names, refer to [Metadata API](/en/documentation/products/applications/functions/runtime/api-reference/metadata/).
