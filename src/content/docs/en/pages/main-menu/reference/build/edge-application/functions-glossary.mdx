This glossary defines the terms the [Functions](/en/documentation/build/functions/) documentation uses.

<GlossaryFilter lang="en">

| Term | Definition |
| --- | --- |
| Azion Bundler | An [open-source framework adapter](https://github.com/aziontech/bundler) that [converts a web framework project into functions](/en/documentation/build/functions/how-it-works/) for Azion Runtime. When you initialize a project with the [Azion CLI](/en/documentation/products/azion-cli/overview/), the bundler identifies the framework and converts its server-side logic, API routes, and middleware into functions. Each route, API endpoint, or server component of a [supported framework](/en/documentation/products/devtools/azion-edge-runtime/frameworks-compatibility/) becomes a function. |
| Azion Runtime | The [runtime](/en/documentation/runtime/overview/) that executes functions on Azion's distributed network. It runs JavaScript built on Web standards and provides a set of [Web APIs](/en/documentation/runtime-apis/javascript/). |
| environment variable | A value you configure outside a function's code, such as an API key, and [manage through the Azion API or Azion CLI](/en/documentation/products/functions/environment-variables/). A function reads a variable by its key with `Azion.env.get()`, and the [`env` parameter](/en/documentation/build/functions/reference/handlers/) of an ES Modules handler carries the variables. The combined size of all variables for one function has a ceiling listed in [Functions limits](/en/documentation/build/functions/limits/). |
| ES Modules pattern | The recommended [handler pattern](/en/documentation/build/functions/reference/handlers/) for a function: an `export default` object whose `fetch` and `firewall` properties are the handlers. Each handler receives `request`, `env`, and `ctx`. The Service Worker pattern is the legacy alternative. |
| execution context (`ctx`) | The `ctx` object an [ES Modules handler](/en/documentation/build/functions/reference/handlers/) receives as its third parameter. In a `fetch` handler, `ctx.waitUntil(promise)` extends the function's lifetime for an async task that should not block the response. In a `firewall` handler, `ctx.deny()` blocks the request immediately. |
| `fetch` handler | The [handler](/en/documentation/build/functions/reference/handlers/) that answers an HTTP request with a `Response`. It receives `request`, `env`, and `ctx`. When a function also defines a `firewall` handler, the request reaches `fetch` only if that handler does not call `ctx.deny()`. |
| `firewall` handler | The [handler](/en/documentation/build/functions/reference/handlers/) that applies security logic to a request before the `fetch` handler runs. It calls `ctx.deny()` to block the request, or returns without calling it to let the request continue to `fetch`. A function instantiated in a firewall [runs in the request phase](/en/documentation/secure/firewall/reference/functions/). |
| function | The code you write and save in [Functions](/en/documentation/build/functions/), structured as one or more [handlers](/en/documentation/build/functions/reference/handlers/). It runs on Azion Runtime when a [rule invokes one of its function instances](/en/documentation/build/functions/how-it-works/) in an application or a firewall. You can instantiate the same function in more than one application or firewall, each with its own args. |
| function instance | The object that [links a saved function to one application](/en/documentation/build/functions/reference/functions-instances/) or [firewall](/en/documentation/secure/firewall/reference/functions-instances/), with its own ID. An instance cannot change the function's code, only the JSON args it receives. A rule with the Run Function behavior selects an instance, not the function itself. |
| Functions | The [Build product](/en/documentation/build/functions/) that runs your functions on Azion Runtime, in the request path of an application or a firewall. You write a function once in Functions and instantiate it in each application or firewall that runs it. |
| Functions module | A module you [turn on in an application or a firewall](/en/documentation/build/functions/guides/instantiate-functions/) before it can instantiate functions. When the module is on, compute time and invocations can generate [usage charges](/en/documentation/platform/pricing/#functions). |
| handler | The [entry point in a function's code](/en/documentation/build/functions/reference/handlers/) that Azion Runtime calls when a rule invokes the function. A function defines handlers in the ES Modules pattern or the legacy Service Worker pattern. The two handler types are `fetch`, which answers an HTTP request, and `firewall`, which applies security logic. |
| JSON args | A JSON object passed to a function when it executes, so that one function can behave differently in each instance without a code change. A function carries default args, and a [function instance overrides them](/en/documentation/build/functions/reference/functions-instances/) key by key: a key the instance does not set keeps the default. In the Service Worker pattern, code reads an argument by name with `event.args()`. |
| Preview Deployment | A feature of the [Functions Code Editor](/en/documentation/products/applications/functions/runtime-api/code-editor/) that [runs a function against a simulated request](/en/documentation/products/applications/functions/runtime-api/preview-deployment/) and shows the outcome. It depends on a `PreviewProvider` function in the source code, which builds the simulated request and calls the handler. Without `PreviewProvider`, no preview renders. |
| request metadata | A set of values about the incoming request that a function reads through the [Metadata API](/en/documentation/products/applications/functions/runtime/api-reference/metadata/). It covers the client's GeoIP location, remote IP address and port, the server protocol, TLS details, server fingerprints, and request identifiers. A function in a firewall uses it to filter access to an application and to apply logic per scenario. |
| Run Function behavior | The [Rules Engine](/en/documentation/build/applications/reference/rules-engine/) behavior that invokes a [function instance](/en/documentation/build/functions/reference/functions-instances/). When a request meets the rule's criteria, the edge node runs the instance's function on Azion Runtime. In the API, the behavior type is `run_function` and it takes the function instance ID. |
| Service Worker pattern | The legacy [handler pattern](/en/documentation/build/functions/reference/handlers/) for a function, kept for backward compatibility. Code registers a `fetch` or `firewall` handler with `addEventListener()` and reads the request from `event.request`. Azion recommends that you migrate functions on this pattern to the ES Modules pattern. |

</GlossaryFilter>
