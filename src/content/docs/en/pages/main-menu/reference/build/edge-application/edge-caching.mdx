**Cache** is an **Applications** module that stores content on Azion edge nodes, close to your end users.

With Cache, your application:

- Answers a request from the edge node nearest the user, so the request never reaches the origin.
- Keeps serving content from the edge nodes when origin servers experience downtime or become unavailable.
- Controls how long content stays on edge nodes and in the browser, through *time-to-live* (TTL) values.
- Varies what it stores by query string, cookie, device group, or HTTP method.

## Expiration

A TTL value sets how long an object stays cached. A large TTL reduces traffic to the origin and keeps content closer to users. A low TTL keeps end users on the most current version of the content. [How Cache works](/en/documentation/build/cache/how-it-works/) covers the tradeoff between the two, and [Cache settings](/en/documentation/build/cache/reference/cache-settings/) carries the fields.

## Cache keys

A cache key is the index entry for an object on an edge node. Its format decides which requests share a stored object and which get their own. For the format and every variation, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).

## Stale cache

Stale Cache lets edge nodes keep serving objects after those objects expire, so a failing origin returns content instead of an error page. For the revalidation triggers and the stale window, refer to [How Cache works](/en/documentation/build/cache/how-it-works/).

## Tiered Cache

Tiered Cache adds a second cache layer between the edge nodes and your origin servers, so a miss on the edge node can still be answered without reaching the origin.

<LinkButton link="/en/documentation/build/cache/tiered-cache/" label="go to Tiered Cache documentation" />

## Adaptive Delivery

Adaptive Delivery detects device groups you created using [Device Groups](/en/documentation/build/applications/reference/device-groups/). You can deliver the same version of the content regardless of device detection, or keep device-based variations of objects in cache.

<LinkButton link="/en/documentation/build/cache/reference/cache-settings/#adaptive-delivery" label="go to Adaptive Delivery documentation" />

## Large File Optimization

Large File Optimization is a resource for **Applications** that processes large amounts of data, reducing latency and saving bandwidth. Large files are fragmented into smaller ones, and those fragments are delivered as the end user consumes them, which avoids an abrupt transfer the user could interrupt. The fragments are cached on demand, at the moment the user requests them.

<LinkButton link="/en/documentation/build/cache/reference/cache-settings/#large-file-optimization" label="go to Large File Optimization documentation" />

## Real-Time Purge

Real-Time Purge removes cached objects before their TTL expires, by URL, by cache key, or by wildcard.
