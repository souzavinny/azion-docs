**Cache** is an [Applications](/en/documentation/build/applications/) module that controls how Azion edge nodes store and serve your content.

An application without Cache forwards every request to your origin servers. With Cache, an edge node stores a copy of the response and answers later requests for the same object without contacting the origin. You turn the module on in the **Main Settings** tab of an application, together with the other Applications modules.

With Cache, you can:

- Set how long an object stays on Azion edge nodes and in the user's browser.
- Separate cached objects by query string, cookie, device group, or HTTP method.
- Serve expired content while your origin servers are unreachable.
- Remove objects from cache before their TTL expires.
- Add a second cache layer between the edge nodes and your origin servers.

## Cache Settings

A cache setting is the object that carries an application's caching policy. Each setting holds two TTLs: one for the user's browser and one for Azion edge nodes. Each TTL either honors the `Cache-Control` and `Expires` headers your origin sends, or overrides them with the value you enter. A new application starts with one cache setting, created and activated for you. To apply a different policy to a path, create a second setting and assign it with the **Set Cache Policy** behavior in [Rules Engine](/en/documentation/build/applications/reference/rules-engine/).

For more information, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/).

## Cache keys

A cache key is the index entry an edge node builds for each object it stores. The default key concatenates the scheme of the request, the host, the path, the query string, and a variation separator. Two requests that produce the same key return the same cached object, and keys are case sensitive. Several features append their own marker to the key:

- [Advanced Cache Key](/en/documentation/build/cache/reference/cache-settings/#advanced-cache-key) adds the cookie names and query string arguments you select.
- [Device Groups](/en/documentation/build/applications/reference/device-groups/) adds the name of the matching device group.
- [Image Processor](/en/documentation/build/image-processor/) adds the format of a converted image.
- **Large File Optimization** adds the byte range of each fragment.
- [Caching HTTP methods](/en/documentation/build/cache/reference/cache-settings/#caching-http-methods) adds the MD5 hash of the request body for cached `POST` and `OPTIONS` requests.

For the full format, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/#cache-key-format).

## Cache status

Every response carries a cache status that records where the content came from. `HIT` means an edge node served a valid copy from cache, and `MISS` means it fetched the object from the origin. The remaining statuses cover expiry, revalidation, stale delivery, and requests that the [Bypass Cache](/en/documentation/build/applications/reference/rules-engine/#bypass-cache) behavior sends straight to the origin. To read the status, send the request with the `Pragma: azion-debug-cache` header. The response then carries an `X-Cache` header with the status, the IP address of the edge node, and the protocol used.

For the definition of each status, refer to [How Cache works](/en/documentation/build/cache/how-it-works/#cache-status).

## Origin protection

Cache keeps traffic off your origin servers even on the requests it cannot answer from cache. Azion edge nodes hold keep-alive connections to the origin whenever possible, which removes the TCP/IP handshake from each fetch. Thundering Herd control handles simultaneous demand. When many requests arrive at once for the same uncached object, an edge node opens one connection to the origin, not one per request. Each edge node requests the object from the origin once per `MISS` or other non-`HIT` status.

For more information, refer to [How Cache works](/en/documentation/build/cache/how-it-works/#origin-protection).

## Stale Cache

**Stale Cache** lets an edge node serve an expired object while it fetches a fresh copy. It applies when revalidation fails, for example when the origin returns a 5xx error, times out, or sends no valid cache-control headers. During the stale window the node answers from the expired copy and updates the object in the background. Stale Cache is enabled by default. Azion applies a default stale window of 300 seconds when the setting overrides origin cache, or when the origin omits the `stale-while-revalidate` directive.

For more information, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/#stale-cache).

## Large File Optimization

**Large File Optimization** splits a large file into fragments and caches each fragment when a user requests it. Each fragment carries its own cache key, and delivery follows the user's consumption instead of transferring the whole file at once. The default fragment size is 1,024 kB. The feature applies to the cache on Azion edge nodes and, when Tiered Cache is active, to the tiered layer as well.

For more information, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/#large-file-optimization).

## Adaptive Delivery

**Adaptive Delivery** decides whether cached objects vary by device. It reads the groups you create with [Device Groups](/en/documentation/build/applications/reference/device-groups/) and appends the name of the matching group to the cache key. One URL can then hold a separate copy per group. Select the option that varies content by device group when a mobile client and a desktop client need different responses. Otherwise every device receives the same cached object.

For more information, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/#adaptive-delivery).

## Tiered Cache

**Tiered Cache** is a Cache module that adds a second cache layer between Azion edge nodes and your origin servers. When an edge node holds no copy of a requested object, it asks the tiered layer before it asks the origin. A miss on the edge node can still be answered from cache, so fewer requests reach your servers. The layer suits objects that stay in cache for long periods. You can only activate it on cache policies with a TTL of 3 seconds or more. Its servers run in the United States (`na-united-states`) by default, and Brazil (`sa-brazil`) is available as an alternative.

:::note
Tiered Cache requires activation for your account. To activate it, or to switch regions, [contact the Sales team](https://www.azion.com/en/contact-sales/).
:::

For more information, refer to [Tiered Cache](/en/documentation/build/cache/tiered-cache/).

## Real-Time Purge

**Real-Time Purge** removes cached objects before their TTL expires. You purge by URL, by cache key, or by wildcard expression, and you choose the layer: the cache on Azion edge nodes, or the Tiered Cache layer when that module is active. A URL purge is non-recursive and ignores content variations. An object that varies by cookie, device group, or image format needs a cache key purge or a wildcard purge. Purge the Tiered Cache layer before Cache, so the edge nodes do not refill from an outdated tiered copy.

For more information, refer to [Real-Time Purge](/en/documentation/build/cache/reference/real-time-purge/).

## Limits

Cache carries default limits on fragment size, object size, and the TTL range a cache setting accepts. The TTL for Azion edge nodes starts at 60 seconds. The [Application Accelerator](/en/documentation/build/application-accelerator/) module lowers that floor to 0 seconds, and Tiered Cache raises it to 3 seconds. These values are defaults rather than fixed ceilings, and technical support can raise them for your plan.

For the full list of limits and the plans they apply to, refer to [Cache limits](/en/documentation/build/cache/limits/#limits-by-support-plan).

## Interfaces

You can create and manage cache settings using:

- [Azion Console](https://console.azion.com/), in the **Cache Settings** tab of an application.
- [Azion API](https://api.azion.com/), through the `cache_settings` resource of an application.
- [Azion CLI](/en/documentation/products/azion-cli/overview/), with `azion create cache-setting` and the matching `list`, `describe`, `update`, and `delete` commands.
- Azion Terraform Provider, with the `azion_application_cache_setting` resource.
- Azion Libraries, with the `createCacheSetting`, `getCacheSetting`, `getCacheSettings`, `updateCacheSetting`, and `deleteCacheSetting` functions of the `azion/applications` module.
