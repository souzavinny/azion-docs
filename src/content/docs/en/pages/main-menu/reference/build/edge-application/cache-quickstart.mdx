This guide instructs you through your first cache setting on an Azion application.

- Turn on the **Application Accelerator** module.
- Create a cache setting with a custom TTL.
- Apply the cache setting to a request path with a rule.
- Confirm the cache status of a request.

To cache content on Azion's distributed network, you create and connect these objects:

1. An **application**, which owns the cache setting.
2. A **cache setting**, which holds the cache expiration policies.
3. A **rule** in the [Rules Engine](/en/documentation/build/applications/reference/rules-engine/), which applies the cache setting to a request path.

A cache setting that no rule references does nothing. The rule decides which requests the cache setting applies to.

---

## Prerequisites

- Access to [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/).
- An application on Azion Platform, reachable at a domain. To create one, refer to [Start with a template](/en/documentation/get-started/start-with-a-template/).

---

## 1. Turn on Application Accelerator

The [Application Accelerator](/en/documentation/build/application-accelerator/) module unlocks the advanced cache key configurations of a cache setting and lets you set an edge TTL below 60 seconds.

To turn on the module:

1. Access [Azion Console](https://console.azion.com/) > **Applications**.
2. Select the application you want to configure.
3. On the **Main Settings** tab, in the **Modules** section, turn on the **Application Accelerator** switch.
4. Select **Save**.

The application has the **Application Accelerator** module active.

:::caution[important]
With **Application Accelerator** active, data transfer can generate usage-related costs. For more information, refer to [Pricing](/en/documentation/platform/pricing/).
:::

## 2. Create a cache setting

A cache setting holds the cache expiration policies of an application: how long edge nodes and the browser keep the content. An application can hold more than one cache setting.

To create the cache setting:

1. Go to the **Cache Settings** tab of your application.
2. Select **+ Cache Setting**.
3. Enter a name for the cache setting.
4. (Optional) In **Browser Cache Settings**, select **Override Cache Settings** and enter the browser TTL in **Maximum TTL**.
5. In **Cache Settings**, select **Override Cache Settings**.
6. In **Maximum TTL**, enter `864000`, which is 10 days in seconds.
7. Select **Save**.

The cache settings page lists the new cache setting.

:::note
The edge TTL takes a value between `60` and `31536000` seconds, which is 1 year. With the **Application Accelerator** module active, the minimum is `0`.
:::

## 3. Apply the cache setting with a rule

A cache setting stays inactive until a rule references it. A rule in the Rules Engine matches a request and applies the cache setting through the **Set Cache Policy** behavior.

The following rule applies the cache setting to every request to the `/cache` path of your application.

To create the rule:

1. Go to the **Rules Engine** tab of your application.
2. Select **+ Rule**.
3. Enter a name for the rule.
4. Select **Request Phase**.
5. In the **Criteria** section, select the `${uri}` variable.
6. As a comparison operator, select **is equal**.
7. As an argument, enter `/cache`.
8. In the **Behaviors** section, select **Set Cache Policy**.
9. Select the cache setting you created.
10. Select **Save**.

The rule applies the cache setting to every request to the `/cache` path. Changes can take a few minutes to propagate. On an unexpected response, wait and retry before diagnosing.

## 4. Verify the cache status

The `X-Cache` response header carries the cache status of a request. The edge node returns it when the request carries the `Pragma: azion-debug-cache` debug header.

Request the cached path with the debug header:

<Code lang="bash" code={`curl -s -D - -o /dev/null -H "Pragma: azion-debug-cache" "https://<your-azion-domain>/cache"`} />

A successful response returns an `X-Cache` header with the cache status, the IP of the edge node, and the protocol used in the request:

```text
X-Cache: HIT from 200.000.000.00 with HTTP/2.0
```

A `HIT` status means the edge node served the content from the cache. A `MISS` status means the content was not cached on the edge node, so the node fetched it from the origin. Send the request again to check for a `HIT`.
