This guide instructs you through your first cache policy on Azion. You will:

- Create a cache setting that overrides the expiration your origin sends.
- Apply the cache setting to a path with a Rules Engine rule.
- Read the cache status of a request from the terminal.

A cache policy on Azion is three linked objects. The cache setting belongs to an application in [Applications](/en/documentation/build/applications/) and carries the expiration values. A rule in [Rules Engine](/en/documentation/build/applications/reference/rules-engine/) then points at the cache setting and decides which requests it applies to. Until a rule with the **Set Cache Policy** behavior references it, a cache setting changes nothing.

---

## Prerequisites

- An Azion account with access to [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/).
- An application with a configured origin. To create one, refer to [First steps](/en/documentation/build/applications/quickstart/).
- A path on that application that serves content you want cached, such as `/static`.

---

## 1. Create a cache setting

A cache setting holds the expiration values for a group of requests. The **Cache** section sets how long an Azion edge node keeps an object. **Browser Cache** does the same for the user's browser.

This quickstart overrides the cache expiration and leaves **Browser Cache** on **Honor cache policies**, the default. Your origin then controls the browser expiration through the `Cache-Control` and `Expires` headers.

:::note
Cache expiration accepts values from `60` to `31536000` seconds, which is 1 year, and the default is `60` seconds. With the [Application Accelerator](/en/documentation/build/application-accelerator/) module active, the minimum drops to `0` seconds. [Tiered Cache](/en/documentation/build/cache/tiered-cache/) needs a value of at least `3` seconds to keep the object in its second layer.
:::

To create the cache setting:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.
2. Go to the **Cache Settings** tab.
3. Select **+ Cache Setting**.
4. Enter a name for the cache setting, for example `/static - Cache TTL`.
5. In the **Cache** section, select **Override cache settings**.
6. In **Max Age (seconds)**, enter `86400`.
7. Select **Save**.

The cache setting appears in the cache settings list.

A new cache setting has **Stale cache** enabled by default. Azion edge nodes then keep serving the last cached copy when your origin is down or the cache is being renewed. To review the remaining fields of a cache setting, refer to [Cache Settings](/en/documentation/build/cache/reference/cache-settings/).

## 2. Apply the cache setting with a rule

[Rules Engine](/en/documentation/build/applications/reference/rules-engine/) decides which requests a cache setting applies to, through the **Set Cache Policy** behavior. That behavior runs in the request phase, where an application determines how it caches content. A cache setting with no rule pointing at it is never used.

To apply the cache setting to every request under `/static`:

1. Go to the **Rules Engine** tab of your application.
2. Select **+ Rule**.
3. Enter a name for the rule, for example `/static - Set cache policy`.
4. Select **Request Phase**.
5. In the **Criteria** section, select the `${uri}` variable.
6. As the comparison operator, select **starts with**.
7. As the argument, enter `/static`.
8. In the **Behaviors** section, select **Set Cache Policy**.
9. Select the cache setting you created.
10. Select **Save**.

The rule appears in the rules list and applies to every request whose URI starts with `/static`.

New rules take a few minutes to propagate across Azion's distributed network. On an unexpected cache status, wait and retry before diagnosing.

## 3. Verify the cache status

Azion returns the cache status of a resource when the request carries the `Pragma: azion-debug-cache` debug header. The response includes an `X-Cache` header with the status, the IP address of the edge node, and the protocol.

To read the cache status of a resource under `/static`:

<Code lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" https://<your-azion-domain>/static/<your-file>`} />

The response carries the `X-Cache` header:

```bash
X-Cache: HIT from 192.0.2.10 with HTTP/2.0
```

`HIT` means valid and up-to-date content came from the cache on the edge node. The cache setting is in effect. The first request after the rule propagates returns `MISS` instead. The content is not in the cache, so the edge node fetches it from the origin. Run the same command again to see the status change to `HIT`.

Azion caches `GET` and `HEAD` requests by default, and `curl -I` sends a `HEAD` request. For the other statuses a request can return, refer to [How Cache works](/en/documentation/build/cache/how-it-works/#cache-status).
