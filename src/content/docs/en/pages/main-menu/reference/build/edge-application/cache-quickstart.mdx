This guide instructs you through caching the home page of your application for the first time. When you finish, you will have:

- Created your first cache setting, with a 60-second time-to-live (TTL) on Azion edge nodes.
- Applied the cache setting to the home page with a Set Cache Policy rule.
- Verified the cache status with a request that carries the `Pragma: azion-debug-cache` header.

[Cache](/en/documentation/build/cache/) is an [Applications](/en/documentation/build/applications/) module. You configure it through a chain of objects, in this order:

1. An application, which owns the cache setting and the rule.
2. A cache setting inside the application, which holds the TTL. Creating a cache setting does not activate it.
3. A rule in the application's [Rules Engine](/en/documentation/build/applications/reference/rules-engine/), which applies the cache setting to matching requests. The rule does this with the [Set Cache Policy](/en/documentation/build/applications/reference/rules-engine/#set-cache-policy) behavior.
4. A request to the application with the `Pragma: azion-debug-cache` header. Its `X-Cache` response header carries the cache status.

## Prerequisites

- An Azion account with access to [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/).
- An [application](/en/documentation/build/applications/quickstart/) that serves content on an Azion domain.
- The `curl` command in your terminal.

---

## 1. Create a cache setting

The cache setting overrides the TTL your origin sends. It keeps the home page on Azion edge nodes for 60 seconds. Every other option keeps its default.

To create the cache setting:

1. Access [Azion Console](https://console.azion.com/) > **Applications**.
2. Select the application you want to configure.
3. In the **Cache Settings** tab, select **+ Cache Setting**.
4. Enter a name for the cache setting.
5. In the **Cache Expiration Policies** section, under **Cache**, select **Override cache settings**.
6. In **Max Age (seconds)**, enter `60`.
7. Select **Save**.

The **Cache Settings** tab lists the new cache setting. No request uses it yet: a rule activates it in the next stage.

---

## 2. Apply the cache setting with a rule

A rule applies a cache setting to every request whose path matches its criteria. This rule matches the path `/`, so the home page uses the cache setting created in Create a cache setting.

To create the rule:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.
2. In the **Rules Engine** tab, select **+ Rule**.
3. Enter a name for the rule.
4. Select **Request Phase**.
5. In the **Criteria** section, select the `${uri}` variable.
6. Select the _is equal_ operator.
7. Enter `/` as the argument.
8. In the **Behaviors** section, select _Set Cache Policy_.
9. As the argument, select the cache setting created in Create a cache setting.
10. Select **Save**.

The **Rules Engine** tab lists the new rule. A new rule takes a few minutes to propagate, so wait before you verify it.

---

## 3. Verify the cache status

A request that carries the `Pragma: azion-debug-cache` header returns an `X-Cache` response header. The header states the cache status, the IP address of the edge node, and the protocol of the request.

To verify the cache status of the home page:

1. Request the home page with the debug header, replacing `xxxxxxxxxx.map.azionedge.net` with the domain of your application:

   <Code lang="bash" code={`curl -s -D - -o /dev/null -H "Pragma: azion-debug-cache" https://xxxxxxxxxx.map.azionedge.net/`} />

   The response headers include the cache status:

   ```text
   X-Cache: MISS from 203.0.113.10 with HTTP/2.0
   ```

   The edge node has no copy of the home page on the first request. The status is `MISS`, and the edge node fetches the page from the origin.

2. Run the same command again:

   <Code lang="bash" code={`curl -s -D - -o /dev/null -H "Pragma: azion-debug-cache" https://xxxxxxxxxx.map.azionedge.net/`} />

   The status changes:

   ```text
   X-Cache: HIT from 203.0.113.10 with HTTP/2.0
   ```

The status `HIT` means the edge node served the home page from its cache, without a request to the origin. If the second request does not return `HIT`, wait a few minutes and retry before you diagnose. The same response carries the cache key in the `X-Cache-Key` header and the other `X-Cache-*` debug headers. For more information, refer to [Cache keys](/en/documentation/build/cache/reference/cache-keys/).
