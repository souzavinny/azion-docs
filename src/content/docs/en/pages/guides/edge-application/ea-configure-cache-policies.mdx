You can define the time-to-live (TTL) for cached content on edge nodes and in the browser, bypass origin cache settings, and forward cookies from Azion Console, using cache settings and [Rules Engine](/en/documentation/build/applications/reference/rules-engine/).

:::tip
To configure cache settings for dynamic content, see the guide on [How to configure Advanced Cache Key for Applications](/en/documentation/build/application-accelerator/guides/advanced-cache-key/).
:::

---

## Prerequisites

- An application on Azion Platform, or [create a new one](/en/documentation/get-started/journeys/launch/).
- Access to [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/).

---

## Turn on Application Accelerator

The **Application Accelerator** module extends the capabilities of **Rules Engine** and allows a cache TTL below 60 seconds.

To turn on the module:

1. Access [Azion Console](/en/documentation/account/guides/how-to-access-azion-console/) > **Applications**.
2. Select the application you want to configure or [create a new one](/en/documentation/get-started/journeys/launch/).
3. On the **Main Settings** tab, in the **Modules** section, turn on the **Application Accelerator** switch.
4. Select **Save**.

The application accepts the advanced cache options.

---

## Create a cache policy

A cache setting defines how long static content remains in cache.

To create the cache setting:

1. Go to the **Cache Settings** tab of your application.
2. Select **+ Cache Setting**.
3. Enter an easy to remember name for your cache setting. For example: `/target-uri - Cache TTL`.
4. In the **Cache Expiration Policies** section, customize the TTL:
   - Under **Browser Cache Settings**, select **Override Cache Settings** to define how long your content can be cached in browsers.
   - Under **Cache Settings**, select **Override Cache Settings** to define how long your content can be cached on edge nodes.
5. If you chose to override cache settings, add the desired **Maximum TTL** in seconds.
   - You can also customize other cache settings for dynamic content provided by the [Advanced Cache Key](/en/documentation/build/cache/reference/cache-settings/#advanced-cache-key) feature.
6. Select **Save**.

The cache settings page lists the new setting, which no request uses until a rule selects it.

---

## Apply the policy with a rule

A rule connects the cache setting to the requests it applies to.

To create the rule:

1. Go to the **Rules Engine** tab of your application.
2. Select **+ Rule**.
3. Enter an easy to remember name for your rule.
4. Select **Request Phase**.
5. In the **Criteria** section, set the criteria that trigger the rule. To apply the cache settings to a specific URI:
    - If `${uri}` *starts with* `/target-uri`
6. In the **Behaviors** section, select the **Set Cache Policy** behavior.
7. In the argument field, select the `/target-uri - Cache TTL` cache setting.
8. Select **Save**.

The cache setting now applies to the condition defined in the criteria. You can customize the rule further to suit the business needs of your application.

## Bypass origin cache

Bypass Cache makes the edge node request content from the origin instead of serving a cached version.

To bypass origin cache policies:

1. With the **Application Accelerator** module active, go to the **Rules Engine** tab of your application.
2. Select **+ Rule**.
3. Enter an easy to remember name for your rule. For example: `/target-uri - Bypass Cache`.
4. Select **Request Phase**.
5. In the **Criteria** section, set the criteria that trigger the rule. To bypass cache from a specific URI:
    - If `${uri}` *starts with* `/target-uri`
6. In the **Behaviors** section, select the **Bypass Cache** behavior.
7. Select **Save**.

Requests matching the criteria reach the origin. Bypass Cache only affects origin cache policies, not browser cache policies. You can customize browser cache through the **Set Cache Policy** behavior described above.

## Forward cookies to the user

Forward Cookies passes the contents of the `Set-Cookie` header through to your user.

To forward cookies:

1. Go to the **Rules Engine** tab of your application.
2. Select **+ Rule**.
3. Enter an easy to remember name for your rule. For example: `/target-uri - Forward Cookies`.
4. Select **Request Phase**.
5. In the **Criteria** section, set the criteria that trigger the rule. To forward cookies from a specific URI:
    - If `${uri}` *starts with* `/target-uri`
6. In the **Behaviors** section, select the **Forward Cookies** behavior.
7. Select **Save**.

The origin cookies reach the user for the matching URI.

:::tip
To forward cookies from the user to the origin, you can create the same rule in the **Request phase**.
:::

---

## Keep session cookies private

Session cookies can be included in the **Forward Cookies** behavior. A cache setting that excludes them prevents users from receiving cookies from private sessions.

To exclude the session cookies:

1. Go to the **Cache Settings** tab.
2. Select **+ Cache Setting**.
3. Enter an easy to remember name for your cache setting. For example: `/target-uri - Private cookies`.
4. Under the **Advanced Cache Key** section, on **Cache by Cookie**, select the option **Content varies by cookies, with the exception of a few (Blocklist)**.
5. List all session cookies you wish to keep private.
6. Select **Save**.

The setting excludes the listed cookies from the cache key.

To activate the cache setting for the `/target-uri` page:

1. Go to the **Rules Engine** tab.
2. Select the `/target-uri - Forward Cookies` rule you created in the previous steps.
3. In the **Behaviors** section, select **+ Behavior**.
4. Select the **Set Cache Policy** behavior.
5. In the argument field, select the `/target-uri - Private cookies` cache policy.
6. Select **Save**.

The rule forwards cookies and applies the private-cookies policy. You can also combine this feature with the **Bypass Cache** behavior described in the previous section.
