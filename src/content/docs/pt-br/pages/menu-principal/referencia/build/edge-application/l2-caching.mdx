**Tiered Cache** é um módulo do [Cache](/pt-br/documentacao/build/cache/) que adiciona uma segunda camada de cache entre os edge nodes da Azion e seus servidores de origem. Quando um edge node não tem uma cópia válida do objeto requisitado, ele consulta a camada do Tiered Cache antes que a requisição chegue à origem. Essa camada responde a partir do próprio cache enquanto a cópia é válida e consulta a origem apenas depois que essa cópia expira.

Menos requisições chegam aos seus servidores de origem, então a carga na origem diminui. O conteúdo também permanece em cache por mais tempo, porque a camada do Tiered Cache mantém o próprio TTL. Você também pode escolher a região que hospeda essa camada.

:::note[nota]
Tiered Cache está disponível apenas depois que o serviço é ativado para sua conta. Para ativá-lo, [entre em contato com a equipe de vendas](https://www.azion.com/pt-br/contato/).
:::

## Ativação

Tiered Cache tem dois switches. Você ativa o módulo para a aplicação e depois para cada política de cache que deve usar a camada do Tiered Cache. O conteúdo sob uma política com o switch desativado permanece apenas no cache dos edge nodes da Azion.

| Interface | Aplicação | Política de cache |
| --- | --- | --- |
| Azion Console | switch **Tiered Cache** na aba **Main Settings** | switch **Tiered Cache** na aba **Cache Settings** |
| Azion CLI | `azion update edge-application --l2-caching` | `azion create cache-setting --l2-caching-enabled` ou `azion update cache-setting --l2-caching-enabled` |
| API | `l2_caching` na aplicação, na API v3 | `l2_caching_enabled` na API v3, `modules.tiered_cache` na API v4 |

Em `azion.config.js`, o objeto `tieredCache` de uma entrada de cache contém `enabled` e `topology`.

Ativar o módulo pode gerar custos de uso. Para mais informações, consulte [Preços](/pt-br/documentacao/platform/pricing/#cache). Para os passos que criam uma política de cache e a aplicam a uma requisição, consulte [Configure uma política de cache](/pt-br/documentacao/build/cache/guides/cache-settings/).

## TTL do cache

Tiered Cache armazena objetos que permanecem válidos por longos períodos. Uma política de cache aceita o módulo apenas quando o TTL é de 3 segundos ou mais. O TTL padrão de uma política de cache é de 60 segundos, o que já atende a esse mínimo. Uma política de cache com um TTL menor não pode usar a camada do Tiered Cache.

Para os campos de expiração e como eles leem os headers da origem, consulte [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/#cdn-cache-settings). O TTL mínimo e o máximo da camada do Tiered Cache estão em [Limites do Cache](/pt-br/documentacao/build/cache/limites/).

## Regiões e topologia

Azion hospeda os servidores do Tiered Cache nos Estados Unidos (`na-united-states`) por padrão. Azion também oferece o Brasil (`sa-brazil`). Para mudar a região de uma aplicação, entre em contato com a [equipe de vendas](https://www.azion.com/pt-br/contato/). A API v3 carrega o valor no campo `l2_region` da cache setting.

Duas interfaces expressam o posicionamento da camada do Tiered Cache como um campo `topology`. Na API v4, `modules.tiered_cache.topology` aceita `near-edge` ou, onde houver suporte, `near-origin`. Em `azion.config.js`, `tieredCache.topology` aceita `nearest-region`, `br-east-1` ou `us-east-1`.

## Large File Optimization na camada do Tiered Cache

Large File Optimization fragmenta um arquivo grande e armazena os fragmentos em cache sob demanda. Ele se aplica ao cache dos edge nodes da Azion. Enquanto Tiered Cache é um módulo ativo, também se aplica à camada do Tiered Cache. Com Azion CLI, `--slice-l2-caching-enabled` ativa o recurso para essa camada. Na API v3, o mesmo campo se chama `is_slice_l2_caching_enabled`.

Real-Time Purge não aceita uma expressão wildcard para a camada do Tiered Cache, então remover fragmentos dela exige listar a cache key de cada fragmento. Para o formato da cache key de um fragmento, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/#large-file-optimization).

## Real-Time Purge

[Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/#camadas-de-purge) faz o purge de uma camada por requisição: **Cache**, o cache dos edge nodes da Azion, ou **Tiered Cache**, a segunda camada. A camada do Tiered Cache aceita um purge apenas enquanto o módulo está ativo na aplicação.

Faça o purge da camada **Tiered Cache** primeiro e o da camada **Cache** depois. Um edge node que não tem mais um objeto pede esse objeto à camada do Tiered Cache. Se essa camada ainda tiver o objeto desatualizado, ela responde à requisição e o edge node pode armazenar o objeto em cache de novo. Fazer o purge da camada do Tiered Cache primeiro deixa a origem como a única fonte para repor o objeto.

Com Azion CLI, `azion purge --layer tiered_cache` seleciona a camada do Tiered Cache, e o valor padrão de `--layer` é `cache`. Em `azion.config.js`, uma entrada de purge define `layer` como `l2_caching` para a camada do Tiered Cache e como `edge_caching` para o cache dos edge nodes da Azion.

Uma expressão wildcard não faz o purge da camada do Tiered Cache. Use um purge por URL ou um purge por cache key.

## Bypass Cache

Tiered Cache não é compatível com Bypass Cache. Uma regra de [Bypass Cache](/pt-br/documentacao/build/applications/reference/rules-engine/#bypass-cache) faz o edge node requisitar o conteúdo da origem em vez de usar uma cópia em cache. Uma aplicação com uma política de Tiered Cache ativa continua armazenando o objeto em cache na camada do Tiered Cache pelo TTL mínimo especificado.

## Limites

Tiered Cache tem um TTL mínimo e um máximo, e as operações de purge são limitadas por plano de suporte. Os valores estão em [Limites do Cache](/pt-br/documentacao/build/cache/limites/), e os que dependem do plano estão em [Limites por plano de suporte](/pt-br/documentacao/build/cache/limites/#limites-por-plano-de-suporte). Para solicitar um limite maior para seu plano, entre em contato com o [suporte técnico](/pt-br/documentacao/services/support/).
