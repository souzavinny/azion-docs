Um cache setting é o objeto que carrega a política de cache de uma aplicação no módulo [Cache](/pt-br/documentacao/build/cache/) de [Applications](/pt-br/documentacao/build/applications/). Uma nova aplicação começa com um cache setting, criado e ativo por padrão. Um cache setting se aplica às requisições por meio do behavior [Set Cache Policy](/pt-br/documentacao/build/applications/reference/rules-engine/#set-cache-policy) de uma regra do Rules Engine.

Para o caminho de busca que um cache setting controla, consulte [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

## Objeto cache setting

A tabela lista cada chave do corpo da requisição que cria um cache setting pela API. As chaves aninhadas são escritas como caminhos com pontos a partir do topo do corpo.

| Chave | Valores | Descrição |
| --- | --- | --- |
| `name` | string | O nome do cache setting. |
| `browser_cache.behavior` | `"honor"`, `"override"` | `"honor"` mantém os headers de cache que a origem envia; `"override"` aplica `browser_cache.max_age`. |
| `browser_cache.max_age` | inteiro, segundos | O TTL do navegador quando `browser_cache.behavior` é `"override"`. |
| `modules.edge_cache.behavior` | `"honor"`, `"override"` | `"honor"` usa os headers de TTL da origem; `"override"` aplica `modules.edge_cache.max_age`. |
| `modules.edge_cache.max_age` | inteiro, segundos | O TTL do edge cache quando os headers da origem são sobrescritos. |
| `modules.edge_cache.stale_cache.enabled` | booleano | Serve conteúdo expirado enquanto a origem está indisponível ou enquanto o conteúdo atualizado é buscado. |
| `modules.edge_cache.large_file_cache.enabled` | booleano | Armazena arquivos grandes em cache por fragmentos. |
| `modules.edge_cache.large_file_cache.offset` | inteiro, kilobytes | O tamanho do fragmento. O padrão é `1024`. |
| `modules.tiered_cache.topology` | `"near-edge"`, `"near-origin"` | A topologia de [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/), onde houver suporte. |
| `modules.application_accelerator.cache_vary_by_method` | lista de `"post"`, `"options"` | Os métodos HTTP que variam a cache key. |
| `modules.application_accelerator.cache_vary_by_querystring.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | Como os campos de query string variam a cache key. |
| `modules.application_accelerator.cache_vary_by_querystring.fields` | lista de strings | Os campos de query string que o behavior permite ou bloqueia. |
| `modules.application_accelerator.cache_vary_by_querystring.sort_enabled` | booleano | Ordena os campos de query string antes de a cache key ser calculada. |
| `modules.application_accelerator.cache_vary_by_cookies.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | Como os cookies variam a cache key. |
| `modules.application_accelerator.cache_vary_by_cookies.cookie_names` | lista de strings | Os nomes de cookie que variam a cache key. |
| `modules.application_accelerator.cache_vary_by_devices.behavior` | `"ignore"`, `"whitelist"`, `"blacklist"` | Como os grupos de dispositivos variam a cache key. |
| `modules.application_accelerator.cache_vary_by_devices.device_group` | lista de inteiros | Os IDs dos grupos de dispositivos que variam a cache key. |

As chaves em `modules.application_accelerator` entram em vigor quando o módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) está ativo na aplicação. Para um corpo de requisição completo, consulte [Configure uma política de cache via API](/pt-br/documentacao/build/cache/guides/ajustar-cache-settings/).

## Browser Cache Settings

**Browser Cache Settings** define por quanto tempo um navegador mantém uma cópia do conteúdo. O TTL viaja nos headers HTTP `Cache-Control` e `Expires`. A diretiva `max-age` de `Cache-Control` define o TTL; quando `Cache-Control` está ausente, o timestamp em `Expires` define.

| Opção | Efeito |
| --- | --- |
| _Honor Origin Cache Headers_ | Mantém os headers de cache que a origem envia e encaminha os mesmos headers ao navegador. |
| _Override Cache Settings_ | Substitui o TTL da origem pelo valor em **Max Age (seconds)**. |

## CDN Cache Settings

**CDN Cache Settings** define por quanto tempo os edge nodes da Azion mantêm uma cópia do conteúdo.

| Opção | Efeito |
| --- | --- |
| _Honor Origin Cache Headers_ | Usa o TTL que a origem envia nos headers `Cache-Control` e `Expires`. |
| _Override Cache Settings_ | Substitui o TTL da origem pelo valor em **Max Age (seconds)**. |

Com _Honor Origin Cache Headers_, **Max Age (seconds)** define o TTL usado quando a origem não envia headers de cache ou envia valores inválidos.

O TTL do edge cache vai de 60 a 31.536.000 segundos; a partir de 0 segundos com Application Accelerator; a partir de 3 segundos com Tiered Cache. Consulte [Limites do Cache](/pt-br/documentacao/build/cache/limites/). Um TTL de 0 não é um bypass de cache; para a diferença, consulte [Bypass Cache](/pt-br/documentacao/build/applications/reference/rules-engine/#bypass-cache).

## Stale Cache

**Stale Cache** serve conteúdo expirado do cache enquanto a origem está indisponível ou enquanto o objeto em cache é renovado. Stale Cache está habilitado por padrão em um cache setting, pelo switch **Enable Stale Cache**. Quando a origem não fornece uma janela de stale, a Azion aplica uma janela padrão de 300 segundos. Para o fluxo de revalidação, consulte [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

## Large File Optimization

**Large File Optimization** divide um arquivo grande em fragmentos, que a Azion armazena em cache sob demanda conforme o usuário os requisita. O tamanho padrão do fragmento é 1.024 kB. Cada fragmento carrega sua própria cache key; para o marcador `@@bytes=`, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

O switch **Large file optimization** se aplica à camada de edge cache por padrão. Quando Tiered Cache está ativo, a configuração também se aplica à camada Tiered Cache. Um tamanho de fragmento diferente é solicitado à [equipe de suporte técnico](/pt-br/documentacao/services/support/).

## Advanced Cache Key

**Advanced Cache Key** varia a cache key por campos de query string, por cookies ou por ambos. O recurso precisa do módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) ativo na aplicação. Por padrão, a Azion trata cada URL como um objeto em cache. Nomes de campo e nomes de cookie diferenciam maiúsculas de minúsculas: letras maiúsculas e minúsculas produzem objetos em cache diferentes.

### Cache by Query String

**Cache by Query String** decide quais campos de query string distinguem objetos em cache.

| Opção | Efeito | Exemplo |
| --- | --- | --- |
| _Content does not vary by Query String (Improves Caching)_ | A cache key ignora a query string. Duas URLs que diferem apenas na query string são um único objeto em cache. | `http://example.com/path?queryA` e `http://example.com/path?queryB` entregam o mesmo conteúdo em cache. |
| _Content varies by some Query String fields (Whitelist)_ | Apenas os campos listados distinguem objetos em cache. Todos os outros campos são ignorados. | Com `city` listado, `?city=A&name=X` e `?city=A&name=Y` são um objeto; `?city=A&name=X` e `?city=B&name=X` são dois. |
| _Content varies by Query String, except for some fields (Blocklist)_ | Os campos listados são ignorados. Todos os outros campos distinguem objetos em cache. | Com `random` listado, `?city=A&random=123` e `?city=B&random=123` são dois objetos; `?city=A&random=123` e `?city=A&random=456` são um. |
| _Content varies by all Query String fields_ | A cache key inclui cada campo da query string. Duas URLs que diferem na query string são dois objetos em cache. | `http://example.com/path?queryA` e `http://example.com/path?queryB` são armazenadas como objetos separados. |

**Query String Sort** ordena os campos da query string antes de a cache key ser construída. Assim, a posição de um campo não altera a chave. Quando a posição do campo distingue seu conteúdo, deixe a opção desligada.

### Cache by Cookie

**Cache by Cookie** decide quais cookies distinguem objetos em cache.

| Opção | Efeito |
| --- | --- |
| _Content does not vary by Cookies (Improves Caching)_ | Distingue objetos em cache apenas pela URL. Os cookies são ignorados. |
| _Content varies by some Cookies (Allowed Rules)_ | Apenas os nomes de cookie listados distinguem objetos em cache. Todos os outros cookies são ignorados. |
| _Content varies by Cookies, with the exception of a few (Blocklist)_ | Todos os cookies distinguem objetos em cache, exceto os nomes listados. |
| _Content varies by all Cookies_ | Cada cookie distingue objetos em cache, além da URL. |

Uma variação por cookie acrescenta o nome e o valor do cookie à cache key; para o formato, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

## Cache de métodos HTTP

Por padrão, Cache armazena apenas respostas `GET` e `HEAD`. Com Application Accelerator, dois switches estendem o cache a outros métodos. Para ambos, o corpo da requisição passa a fazer parte da cache key, então requisições com corpos diferentes são objetos em cache diferentes.

| Switch | Valor na API | Efeito |
| --- | --- | --- |
| **Enable caching for POST** | `"post"` em `cache_vary_by_method` | Armazena respostas `POST` em cache. |
| **Enable caching for OPTIONS** | `"options"` em `cache_vary_by_method` | Armazena respostas `OPTIONS` em cache. |

A cache key de uma resposta `POST` ou `OPTIONS` em cache carrega um hash do corpo da requisição; para o formato, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

## Adaptive Delivery

**Adaptive Delivery** mantém em cache variações de um objeto por dispositivo, uma por [grupo de dispositivos](/pt-br/documentacao/build/applications/reference/device-groups/). Um grupo de dispositivos compara o header `User-Agent` da requisição com uma expressão regular.

| Opção | Efeito |
| --- | --- |
| _Content varies by some Device Groups (Whitelist)_ | Mantém uma variação em cache por grupo de dispositivos selecionado. Um ou mais grupos de dispositivos podem ser selecionados. |

Na API, `cache_vary_by_devices.behavior` aceita `"ignore"`, `"whitelist"` ou `"blacklist"`, e `device_group` lista os IDs dos grupos de dispositivos. Na Azion CLI, `--adaptive-delivery-action` tem `ignore` como padrão. A cache key de uma variação por dispositivo termina com o nome do grupo de dispositivos; para o formato, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

## Interfaces

| Interface | Onde um cache setting é gerenciado |
| --- | --- |
| Azion Console | A aba **Cache Settings** da aplicação. **+ Cache Setting** cria um. |
| API | `POST https://api.azionapi.net/v4/edge_application/applications/<application_id>/cache_settings`. O caminho na v3 era `/edge_applications/{id}/cache_settings`; consulte [Migração para API v4](/pt-br/documentacao/devtools/api/v4-migration/). |
| Azion CLI | `azion create cache-setting --application-id <application_id> --name "<your-cache-setting-name>"`; consulte [`azion create`](/pt-br/documentacao/devtools/cli/create/). |
| `azion.config.js` | O array `cache` de uma entrada de aplicação, do tipo `AzionCache`; consulte [`azion.config.js`](/pt-br/documentacao/devtools/cli/configs/azion-config-js/). |
| Terraform | O resource `azion_application_cache_setting` e o data source `azion_application_cache_settings`; consulte [Applications - Terraform Resources](/pt-br/documentacao/produtos/terraform-provider/resources/applications/). |
| Azion Libraries | `createCacheSetting`, `getCacheSetting`, `getCacheSettings`, `updateCacheSetting` e `deleteCacheSetting` de `azion/applications`; consulte [Azion Libraries, Application](/en/documentation/products/azion-lib/application/). |

## Flags da Azion CLI

`azion create cache-setting` recebe `--application-id` e `--name` como flags obrigatórias. As flags opcionais seguem.

| Flag | Descrição |
| --- | --- |
| `--adaptive-delivery-action` | A ação de Adaptive Delivery. Padrão `ignore`. |
| `--browser-cache-settings` | Por quanto tempo um navegador armazena o conteúdo em cache: honor ou override. Padrão `honor`. |
| `--browser-cache-settings-maximum-ttl` | O TTL máximo do navegador, em segundos. |
| `--cache-by-cookies` | Se o cache varia por cookies. Padrão `ignore`. |
| `--cache-by-query-string` | Como o conteúdo é armazenado em cache de acordo com as variações de query string. Padrão `ignore`. |
| `--cdn-cache-settings` | Se o edge cache honra os headers de cache da origem ou os sobrescreve. Padrão `honor`. |
| `--cnd-cache-settings-maximum-ttl` | O TTL máximo do edge cache, em segundos. Padrão `60`. |
| `--cookie-names` | Os nomes de cookie que distinguem objetos em cache. |
| `--enable-caching-for-options` | Se respostas `OPTIONS` são armazenadas em cache. Padrão `false`. |
| `--enable-caching-for-post` | Se respostas `POST` são armazenadas em cache. |
| `--enable-caching-string-sort` | Se os campos de query string são ordenados antes de a cache key ser construída. |
| `--file` | O caminho de um arquivo JSON com os atributos do cache setting. `-` lê da stdin. |
| `--l2-caching-enabled` | Se Tiered Cache está ativo. |
| `--query-string-fields` | Os campos de query string que distinguem objetos em cache para a mesma URL. |
| `--slice-configuration-enabled` | Se Large File Optimization está ativo. |
| `--slice-configuration-range` | O intervalo do fragmento. |
| `--slice-l2-caching-enabled` | Se Large File Optimization está ativo na camada Tiered Cache. |

O arquivo JSON de `--file` também aceita `enable_stale_cache`, `device_group`, `l2_region` e `is_slice_edge_caching_enabled`, como mostra a referência de [`azion create`](/pt-br/documentacao/devtools/cli/create/).

## Chaves de azion.config.js

Uma entrada do array `cache` tem o tipo `AzionCache`.

| Chave | Valores | Descrição |
| --- | --- | --- |
| `name` | string | O nome da configuração de cache. |
| `stale` | booleano | Se conteúdo stale é permitido. |
| `queryStringSort` | booleano | Se os campos de query string são ordenados. |
| `tieredCache.enabled` | booleano | Se Tiered Cache está ativo. |
| `tieredCache.topology` | `nearest-region`, `br-east-1`, `us-east-1` | A topologia de Tiered Cache. |
| `methods.post` | booleano | Se respostas `POST` são armazenadas em cache. |
| `methods.options` | booleano | Se respostas `OPTIONS` são armazenadas em cache. |
| `browser.maxAgeSeconds` | número ou string | O TTL do navegador, em segundos. |
| `edge.maxAgeSeconds` | número ou string | O TTL do edge cache, em segundos. |
| `cacheByCookie.option` | `ignore`, `all`, `allowlist`, `denylist` | Como os cookies variam a cache key. |
| `cacheByCookie.list` | lista de strings | Os nomes de cookie para `allowlist` ou `denylist`. |
| `cacheByQueryString.option` | `ignore`, `all`, `allowlist`, `denylist` | Como os campos de query string variam a cache key. |
| `cacheByQueryString.list` | lista de strings | Os campos de query string para `allowlist` ou `denylist`. |

## Limites

| Escopo | Limite |
| --- | --- |
| TTL mínimo do edge cache | 60 segundos |
| TTL mínimo do edge cache com Application Accelerator | 0 segundos |
| TTL máximo do edge cache | 31.536.000 segundos |
| TTL mínimo em Tiered Cache | 3 segundos |
| TTL máximo em Tiered Cache | 2.592.000 segundos |
| Tamanho do fragmento de arquivo | 1.024 kB |

Os limites dependem do plano e são aumentados pela [equipe de suporte técnico](/pt-br/documentacao/services/support/). Para cada limite de Cache, por plano, consulte [Limites do Cache](/pt-br/documentacao/build/cache/limites/).
