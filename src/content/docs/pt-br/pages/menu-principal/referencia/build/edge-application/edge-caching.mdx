**Cache** é um módulo de **Applications** que armazena conteúdo nos edge nodes da Azion, perto dos seus usuários finais.

Com o Cache, sua aplicação:

- Responde a requisição a partir do edge node mais próximo do usuário, e a requisição nunca chega à origem.
- Continua entregando conteúdo do edge quando os servidores de origem ficam inativos ou indisponíveis.
- Controla por quanto tempo o conteúdo permanece no edge e no navegador, através de valores de *time-to-live* (TTL).
- Varia o que armazena por query string, cookie, device group ou método HTTP.

## Expiração

Um valor de TTL define por quanto tempo um objeto permanece em cache. Um TTL alto reduz o tráfego com a origem e mantém o conteúdo mais perto dos usuários. Um TTL baixo mantém os usuários finais na versão mais atual do conteúdo. [Como o Cache funciona](/pt-br/documentacao/build/cache/como-funciona/) trata do trade-off entre os dois, e [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/) carrega os campos.

## Cache keys

Uma cache key é a entrada de índice de um objeto em um edge node. O formato dela decide quais requisições compartilham um objeto armazenado e quais recebem o seu próprio. Para o formato e todas as variações, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

## Stale cache

O Stale Cache permite que os edge nodes continuem servindo objetos depois que eles expiram, então uma origem com falha retorna conteúdo em vez de uma página de erro. Para os gatilhos de revalidação e a janela de stale, consulte [Como o Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

## Tiered Cache

O Tiered Cache adiciona uma segunda camada de cache entre os edge nodes e seus servidores de origem, então um miss no edge ainda pode ser respondido sem chegar à origem.

<LinkButton link="/pt-br/documentacao/build/cache/tiered-cache/" label="Saiba mais sobre Tiered Cache" />

## Adaptive Delivery

**Adaptive Delivery** detecta os grupos de dispositivos que você criou usando o [Device Groups](/pt-br/documentacao/build/applications/reference/device-groups/). Você pode optar por fornecer a mesma versão do conteúdo, independentemente da detecção do dispositivo, ou manter variações de objetos baseadas no dispositivo em cache.

<LinkButton link="/pt-br/documentacao/build/cache/reference/cache-settings/#adaptive-delivery" label="Saiba mais sobre adaptive delivery" />

## Large File Optimization

**Large File Optimization** é um recurso para **Applications** que processa grandes quantidades de dados, reduzindo a latência e economizando banda. Arquivos grandes são fragmentados em arquivos menores, e esses fragmentos são entregues conforme o usuário final consome os dados, o que evita uma transferência abrupta que o usuário poderia interromper. Os fragmentos são armazenados em cache sob demanda, no momento em que o usuário os solicita.

<LinkButton link="/pt-br/documentacao/build/cache/reference/cache-settings/#large-file-optimization" label="Saiba mais sobre configurações de large file optimization" />

## Real-Time Purge

O Real-Time Purge remove objetos em cache antes que o TTL deles expire, por URL, por cache key ou por wildcard.
