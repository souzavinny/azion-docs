**Real-Time Purge** apaga objetos armazenados em cache na Azion antes que o TTL expire. Uma política de [Cache](/pt-br/documentacao/build/cache/) define por quanto tempo um objeto permanece em cache, e um purge encerra esse período antes do prazo. Na requisição seguinte ao objeto, Azion busca a versão atual na origem.

Todo purge indica uma camada, um tipo e uma lista de argumentos. O tipo determina quais objetos em cache os argumentos alcançam, porque um purge alcança um objeto apenas quando o argumento corresponde à cache key desse objeto.

---

## Camadas de purge

Real-Time Purge atua em uma camada de cache por requisição. **Cache** guarda os objetos armazenados nos edge nodes da Azion. **Tiered Cache** guarda a segunda camada de cache, entre esses edge nodes e a origem.

| Camada | O que guarda | Tipos de purge aceitos |
| --- | --- | --- |
| Cache | Objetos em cache nos edge nodes da Azion | URL, cache key, wildcard |
| Tiered Cache | Objetos em cache na segunda camada, entre os edge nodes e a origem | URL, cache key |

A camada Tiered Cache aceita um purge apenas enquanto o módulo [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) estiver ativo. Um objeto guardado nas duas camadas precisa de um purge por camada, e a ordem importa: faça purge primeiro no Tiered Cache e depois no Cache. Na ordem inversa, um edge node pode reabastecer seu cache com a cópia desatualizada que ainda está na camada do Tiered Cache.

---

## Tipos de purge

Real-Time Purge aceita três tipos, e cada tipo recebe um argumento diferente. O tipo também determina se um purge alcança as [variações de conteúdo](#variacoes-de-conteudo) de um objeto, porque cada variação tem sua própria cache key.

| Tipo | Argumento | O que alcança |
| --- | --- | --- |
| [Purge por URL](#purge-por-url) | Uma lista de URLs | As URLs listadas, convertidas em suas cache keys, sem as variações |
| [Purge por cache key](#purge-por-cache-key) | Uma lista de cache keys | O objeto que cada cache key listada indexa, com as variações |
| [Purge por wildcard](#purge-por-wildcard) | Uma expressão wildcard | Todas as cache keys correspondentes à expressão |

## Purge por URL

Um purge por URL recebe uma lista de URLs e expira o objeto em cache por trás de cada uma. Azion converte cada URL da lista em sua cache key antes do purge, sem considerar as variações de conteúdo da mesma URL. A operação não é recursiva: faz purge das URLs da lista e de nada mais.

Cada URL segue o formato `scheme://host`, ou apenas `host`, seguido opcionalmente por um `/path` e uma `?query-string`. Quando o scheme é omitido, o purge cobre as cópias HTTP e HTTPS do conteúdo.

Por exemplo:

- `http://www.example.com`
- `http://static.example.com/include/site.css`
- `https://static.example.com/include/site.js`
- `dynamic.example.com/app.py?argument`

Um purge por URL expira, sim, as variações baseadas em query string, porque a query string faz parte da URL. Envie os argumentos na mesma ordem em que a requisição os apresentou. Quando [Query String Sort](/pt-br/documentacao/build/cache/reference/cache-settings/#cache-by-query-string) está ativado, ordene os argumentos alfabeticamente na requisição, ou use um purge por cache key ou um purge por wildcard.

:::note[nota]
As variações baseadas em cookies, device groups, formato de imagem ou qualquer outro critério não expiram com um purge por URL. Use um [purge por cache key](#purge-por-cache-key) ou um [purge por wildcard](#purge-por-wildcard) para essas variações.
:::

:::caution[Atenção]
Um asterisco (`*`) em um argumento de purge por URL vale como caractere literal da URL, não como wildcard.
:::

## Purge por cache key

Um purge por cache key recebe uma lista de [cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/) e expira o objeto que cada chave indexa. Uma cache key identifica uma variação de um objeto, então esse tipo alcança variações que um purge por URL não alcança: argumentos de query string e de query string sort, cookies configurados por [Advanced Cache Key](/pt-br/documentacao/build/cache/reference/cache-settings/#advanced-cache-key) e os formatos de imagem que [Image Processor](/pt-br/documentacao/build/image-processor/) produz para os navegadores compatíveis.

Uma cache key concatena o scheme, o host, o path, as query strings e o separador de variação, sem o `://` entre o scheme e o host. Cache keys diferenciam maiúsculas de minúsculas, então caracteres maiúsculos e minúsculos indexam objetos diferentes. Para alcançar todas as variações de um objeto, liste a cache key de cada variação individualmente, ou use um [purge por wildcard](#purge-por-wildcard).

As cache keys do Image Processor mostram a forma completa, com os argumentos de processamento e a variação de formato:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

## Purge por wildcard

Um purge por wildcard recebe uma expressão wildcard por requisição e expira todas as cache keys correspondentes à expressão. A expressão segue o formato `scheme://host`, ou apenas `host`, seguido opcionalmente por um `/path` e uma `?query-string`. Um asterisco (`*`) fica no path ou na query string, e vários asteriscos em uma expressão correspondem a um padrão de path mais complexo.

Por exemplo:

- `www.example.com/*`
- `static.example.com/include/*.css`
- `static.example.com/*/site.js`
- `static.example.com/static/images/image_1.jpg?ims=*`
- `www.example.com/alpha*`
- `www.example.com/*beta*`
- `www.example.com/*a*/charlie`
- `www.example.com/*a*/*a*`
- `www.example.com/*?b*`
- `www.example.com/*?*2*c=*`

:::note[nota]
A camada Tiered Cache não aceita uma expressão wildcard. Faça purge do conteúdo do Tiered Cache com um [purge por URL](#purge-por-url) ou um [purge por cache key](#purge-por-cache-key).
:::

## Variações de conteúdo

Um purge alcança uma variação de conteúdo apenas quando seu argumento corresponde à cache key dessa variação. Cada recurso que varia um objeto grava seu próprio separador e valor na cache key, e o argumento do purge carrega a mesma forma. Cache by Cookie e Cache by Query String são opções de [Advanced Cache Key](/pt-br/documentacao/build/cache/reference/cache-settings/#advanced-cache-key), fornecidas pelo módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/).

| Origem da variação | Forma na cache key | Purge com |
| --- | --- | --- |
| Cache by Cookie | `@@` seguido dos nomes e valores dos cookies, cada um fechado por `;` | Um purge por cache key listando cada variação ou um purge por wildcard terminado em `@@*` |
| Cache by Query String | O separador de query e os argumentos, na ordem em que a requisição os enviou | Um purge por cache key listando cada variação, um purge por wildcard terminado em `?*` ou um purge por URL carregando apenas os argumentos da cache key |
| [Image Processor](/pt-br/documentacao/build/image-processor/) | O separador `?`, os pares chave-valor do processamento e `@@` seguido do formato de imagem do navegador | Um purge por cache key listando cada variação ou um purge por wildcard terminado em `*` |
| [Device Groups](/pt-br/documentacao/build/applications/reference/device-groups/) | `@@` seguido do nome do device group | Um purge por cache key listando cada variação ou um purge por wildcard |
| [Large File Optimization](/pt-br/documentacao/build/cache/reference/cache-settings/#large-file-optimization) | `@@bytes=` seguido do intervalo de bytes de cada fragmento | Um purge por cache key listando cada fragmento ou um purge por wildcard com `*` depois do path do arquivo |
| Requisições `POST` e `OPTIONS` em cache | `@@` seguido do hash MD5 do corpo da requisição | Um purge por cache key listando cada variação ou um purge por wildcard terminado em `@@*` |

Uma expressão wildcard alcança todos os fragmentos de um arquivo dividido por Large File Optimization, como `static.example.com/media/file.mp4*`.

Azion armazena em cache as requisições `GET` e `HEAD` por padrão. O cache de `POST` e `OPTIONS` exige o módulo Application Accelerator.

:::caution[Atenção]
Fazer purge dos fragmentos um a um pode deixar fragmentos desatualizados em cache quando o conteúdo muda na origem.
:::

## Método DEL

O método `DEL` é uma alternativa ao Real-Time Purge para remover um objeto do cache. Depois de um `DEL`, a primeira requisição `GET` para esse objeto vai para a origem, como acontece depois de um purge. Os dois diferem quando a origem está inacessível: Azion não entrega nenhuma [cópia stale](/pt-br/documentacao/build/cache/como-funciona/#stale-cache) de um objeto removido com `DEL` e retorna uma página de erro.

## Execução e histórico de purge

Azion confirma um purge assim que aceita a requisição e depois coloca o purge na fila de execução. Os resultados levam tempo para propagar a todos os edge nodes, então o purge aparece no histórico de purge quando é concluído. A resposta de um purge traz um campo `state`, com o valor `pending` ou `executed`, e um campo `items` que lista o que o purge cobriu.

O histórico de purge registra o usuário que emitiu o purge, o horário, a lista de argumentos, o tipo de purge e o método. Você pode filtrar o histórico por qualquer um desses campos.

## Permissões

Emitir um purge exige a team permission **Real-Time Purge**, que concede a criação de um novo purge. Selecionar o tipo **Wildcard** exige também a permissão **Wildcard Purge**, que por sua vez exige **Real-Time Purge**.

## Interfaces

Um purge é emitido por [Azion Console](https://console.azion.com/), pela Azion API, pelo [Azion CLI](/pt-br/documentacao/products/azion-cli/overview/) ou pelas Azion libraries. A purge API é um recurso de nível superior, e não um sub-recurso de uma aplicação, então uma requisição de purge não indica nenhuma aplicação.

| Interface | Como o purge é emitido |
| --- | --- |
| Azion Console | **Products menu** > **Tools** > **Real-Time Purge** |
| API | `POST` para `https://api.azion.com/v4/workspace/purge/url` ou `https://api.azion.com/v4/workspace/purge/wildcard` |
| Azion CLI | `azion purge` com `--urls`, `--cachekey` ou `--wildcard` |
| Azion libraries | `purgeURL`, `purgeCacheKey` ou `purgeWildCard` de `azion/purge` |
| `azion.config.js` | Uma entrada `purge` cujo `type` é `url`, `cachekey` ou `wildcard` |

O corpo da API carrega os argumentos em `items` e a camada em `layer`. O campo `layer` é opcional, e seus valores são `cache`, o padrão, e `tiered_cache`. Faça purge de duas URLs na camada Cache:

<Code lang="bash" code={`curl -X POST 'https://api.azion.com/v4/workspace/purge/url' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
    "items": [
      "https://www.example.com/image.jpg",
      "https://www.example.com/styles.css"
    ],
    "layer": "cache"
  }'`} />

A resposta traz o `state` do purge e os `items` que ele cobriu.

Azion CLI aceita os mesmos dois valores de camada na flag `--layer` e usa `cache` como padrão. Um argumento de cache key mantém seus separadores, e uma vírgula separa dois argumentos:

<Code lang="bash" code={`azion purge --urls "https://www.example.com/image.jpg" --layer tiered_cache

azion purge --cachekey "www.example.com/@@cookie_name=cookie_value,www.example.com/test.js"`} />

## Limites

Real-Time Purge limita o tamanho e a taxa dos argumentos de purge, e cada plano de suporte inclui um número definido de operações de purge. Os escopos limitados são:

- O tamanho de um argumento de URL ou de cache key e o tamanho de uma expressão wildcard.
- O número de objetos por requisição, por cliente e por minuto.
- O número de requisições wildcard por dia e o número de expressões wildcard por requisição.
- O número de requisições de purge mantidas no histórico e por quanto tempo o histórico é retido.

Para os valores, consulte [Limites do Cache](/pt-br/documentacao/build/cache/limites/#limites-por-plano-de-suporte).

:::tip[dica]
**Aumente os limites** <br></br>
Entre em contato com o [suporte técnico](/pt-br/documentacao/services/support/) para solicitar um limite maior para seu plano.
:::
