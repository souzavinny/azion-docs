**Real-Time Purge** remove objetos armazenados em [Cache](/pt-br/documentacao/build/cache/) antes que o TTL expire. Um purge nomeia os objetos por URL, por cache key ou por expressão wildcard e é executado na camada Cache ou na camada Tiered Cache. Após o purge, a próxima requisição de um objeto busca a versão mais recente na origem.

Para executar um purge pelo Azion Console, pela API ou pela CLI, consulte [Faça purge de conteúdo em cache](/pt-br/documentacao/build/cache/guides/purgar-conteudo/).

---

## Camadas de purge

Um purge é executado em uma de duas camadas. A camada Tiered Cache aceita um purge apenas quando o módulo [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) está ativo na aplicação.

| Camada | O que é purgado | Valor na CLI e em `azion.config.js` |
| --- | --- | --- |
| Cache | Objetos em cache nos edge nodes da Azion | `cache`, o padrão |
| Tiered Cache | Objetos em cache na segunda camada de cache, entre os edge nodes e a origem | `tiered_cache` |

Quando uma aplicação usa as duas camadas, faça purge primeiro da camada Tiered Cache e depois da camada Cache. Nessa ordem, os edge nodes não são preenchidos de novo com conteúdo desatualizado do Tiered Cache. Um purge por wildcard é executado apenas na camada Cache.

## Tipos de purge

Cada tipo de purge recebe um tipo de argumento e seleciona os objetos em cache de uma forma própria. Os formatos de argumento e os exemplos estão nas seções a seguir.

| Tipo | Argumento | O que seleciona | Camadas | Limites |
| --- | --- | --- | --- | --- |
| Purge por URL | Uma lista de URLs | A cache key em que cada URL é convertida, sem variação de conteúdo | Cache, Tiered Cache | Tamanho da URL, objetos por requisição e objetos por minuto em [Limites](#limites) |
| Purge por cache key | Uma lista de cache keys | Exatamente as cache keys listadas, uma por variação | Cache, Tiered Cache | Tamanho da cache key, objetos por requisição e objetos por minuto em [Limites](#limites) |
| Purge por wildcard | Uma expressão wildcard | Todo objeto em cache cuja cache key corresponde à expressão | Cache | Tamanho da expressão, uma expressão por requisição e requisições por dia em [Limites](#limites) |

### Purge por URL

Um purge por URL não é recursivo: apenas as URLs informadas são purgadas. Cada URL é convertida em sua cache key sem nenhuma variação de conteúdo. Variações baseadas em cookies, device groups, formato de imagem ou outros marcadores não expiram com um purge por URL. Para purgá-las, use um [purge por cache key](#purge-por-cache-key) ou um [purge por wildcard](#purge-por-wildcard).

Uma query string é um componente da URL, então um purge por URL expira uma variação por query string. Os argumentos devem aparecer na ordem em que a requisição os apresentou. Com [Query String Sort](/pt-br/documentacao/build/cache/reference/cache-settings/) ativado, ordene os argumentos em ordem alfabética no purge ou use um purge por cache key ou um purge por wildcard.

O argumento segue o formato `scheme://host` ou `host`, com um `/path` opcional e uma `?query-string` opcional. Sem um scheme, o purge remove tanto o conteúdo HTTP quanto o conteúdo HTTPS.

:::caution[Atenção]
Um asterisco (`*`) em um argumento de purge por URL é um caractere da URL, não um wildcard.
:::

Argumentos válidos de purge por URL:

- `http://www.example.com`
- `http://static.example.com/include/site.css`
- `https://static.example.com/include/site.js`
- `dynamic.example.com/app.py?argument`

### Purge por cache key

Um purge por cache key recebe uma lista de cache keys e purga exatamente essas keys. Uma cache key concatena o scheme, o host, o path e a query string de uma requisição, além de um separador `@@` com qualquer variação. Para o formato completo e o header de debug que retorna a key de um objeto, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

Uma cache key identifica uma variação de um objeto. A variação é um argumento de query string ou de Query String Sort, um cookie definido por Advanced Cache Key ou um formato de imagem de [Image Processor](/pt-br/documentacao/build/image-processor/). Para purgar todas as variações de um objeto, liste cada cache key individualmente.

Argumentos de purge por cache key para o objeto `https://static.example.com/page/site.js`:

- `httpsstatic.example.com/page/site.js`
- `httpsstatic.example.com/page/site.js@@`, a key quando as variações estão ativadas

### Purge por wildcard

Um purge por wildcard recebe uma expressão e purga todo objeto em cache cuja cache key corresponde a ela. A expressão segue o formato `scheme://host` ou `host`, com `/path` e `?query-string` opcionais e um asterisco (`*`) no path ou na query string. Uma expressão pode conter mais de um asterisco para corresponder a um padrão de path complexo.

Um purge por wildcard não alcança a camada Tiered Cache. Cada requisição leva uma expressão, e o purge exige a permissão **Wildcard Purge** listada em [Permissões](#permissões).

Argumentos válidos de purge por wildcard:

- `www.example.com/*`
- `static.example.com/include/*.css`
- `static.example.com/*/site.js`
- `static.example.com/static/images/image_1.jpg?ims=*`
- `www.example.com/alpha*`
- `www.example.com/*beta*`
- `www.example.com/*a*/charlie`
- `www.example.com/*a*/*a*`
- `www.example.com/*?b*`
- `www.example.com/*?*2*c=*`

## Variações de conteúdo

Uma variação é uma cópia em cache de um objeto sob uma cache key com um marcador extra. O marcador pode ser um valor de cookie ou um formato de imagem. Um purge por cache key lista cada variação individualmente. Um purge por wildcard as seleciona com um asterisco na posição que a tabela mostra. Os marcadores em si estão documentados em [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).

| Variação | Produzida por | Purge por cache key | Purge por wildcard |
| --- | --- | --- | --- |
| Cookie | Cache by Cookie, uma opção de Advanced Cache Key de [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) | Uma cache key por variação | `@@*` no fim da expressão |
| Query string | Cache by Query String, uma opção de Advanced Cache Key de Application Accelerator | Uma cache key por variação | `?*` no fim da expressão |
| Formato de imagem | Image Processor | Uma cache key por variação | `*` no fim da expressão |
| Fragmento de arquivo | Large File Optimization | Uma cache key por fragmento | `*` após o nome do arquivo, como em `static.example.com/media/file.mp4*` |
| Corpo de `POST` ou `OPTIONS` | Cache de métodos HTTP em Application Accelerator | Uma cache key por variação | `@@*` no fim da expressão |

Um purge por URL também expira uma variação por query string quando a URL leva apenas os argumentos usados na cache key. Com Query String Sort, esses argumentos vão em ordem alfabética.

Uma cache key de uma imagem tratada por Image Processor leva o separador `?`, os pares chave-valor do processamento e o separador `@@` antes do formato. Argumentos de purge por cache key para uma dessas imagens:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

:::caution[Atenção]
Quando você faz purge de fragmentos individuais de um arquivo grande, fragmentos desatualizados podem permanecer em cache após o conteúdo mudar na origem. Um purge por wildcard com `*` após o nome do arquivo remove todos os fragmentos.
:::

## Método `DEL`

O método `DEL` remove um objeto do cache em vez de um Real-Time Purge. Após um `DEL`, a primeira requisição `GET` do objeto vai para a origem. O método também impede que a Azion entregue um objeto stale quando a origem está inacessível: a requisição recebe uma página de erro. A entrega de conteúdo stale está descrita em [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

Use `DEL` para:

- Remover conteúdo do cache da Azion após ele ser removido da origem.
- Forçar a remoção e a posterior atualização de conteúdo cujo timestamp não é confiável.
- Forçar uma página de erro em vez de um objeto stale quando a origem está inacessível.

Na forma da API v3 de `azion.config.js`, uma entrada de purge seleciona o método com `method: 'delete'`.

## Execução e histórico

Um novo purge retorna uma mensagem de sucesso que confirma sua criação. O purge então entra na fila de execução. Ele aparece no histórico quando concluído, porque o resultado pode levar algum tempo para se propagar a todos os edge nodes. A resposta `Purge` de Azion Libraries leva um `state` de `pending` ou `executed`.

O histórico de purges pode ser filtrado pelo usuário que fez o purge, pelo horário, pela lista de argumentos, pelo tipo de purge e pelo método. O número de requisições que o histórico guarda e o tempo pelo qual ele as mantém estão em [Limites](#limites).

## Permissões

Duas permissões de equipe controlam quem pode fazer purge. Ambas estão documentadas em [Teams Permissions](/pt-br/documentacao/account/reference/teams-permissions/).

| Permissão | Concede |
| --- | --- |
| Real-Time Purge | Permissão para adicionar um novo purge em Real-Time Purge |
| Wildcard Purge | Permissão para selecionar o tipo de purge **Wildcard** em Real-Time Purge. Exige a permissão **Real-Time Purge** |

## Interfaces

Toda interface recebe os mesmos três tipos de purge e, onde suporta a escolha, as mesmas duas camadas.

| Interface | Forma do purge | Referência |
| --- | --- | --- |
| Azion Console | Um purge com seu tipo de purge selecionado em **Real-Time Purge** | [Faça purge de conteúdo em cache](/pt-br/documentacao/build/cache/guides/purgar-conteudo/) |
| API | Uma requisição à API de Cache Purge | [Faça purge de conteúdo em cache](/pt-br/documentacao/build/cache/guides/purgar-conteudo/) |
| Azion CLI | `azion purge` com `--urls`, `--cachekey` ou `--wildcard`, e `--layer` | [`azion purge`](/pt-br/documentacao/devtools/cli/purge/) |
| Azion Libraries | `purgeURL`, `purgeCacheKey` e `purgeWildCard` de `azion/purge` | [Azion Libraries, Purge](/pt-br/documentacao/produtos/azion-lib/purge/) |
| `azion.config.js` | Um array `purge` com `type`, `items` e `layer` | [`azion.config.js`](/pt-br/documentacao/devtools/cli/configs/azion-config-js/) |

### Flags de `azion purge`

| Flag | Finalidade | Valores |
| --- | --- | --- |
| `--urls` | Uma lista de URLs para purgar do Azion Cache | URLs |
| `--cachekey` | Uma lista de URLs incluindo as cache keys para purgar do Azion Cache | Cache keys |
| `--wildcard` | A URL ou cache key wildcard dos objetos a purgar; uma expressão por requisição | Uma expressão wildcard |
| `--layer` | A camada em que o purge é executado | `cache`, o padrão, ou `tiered_cache` |
| `--help` | Exibe mais informações sobre o comando purge | Nenhum |

### Bloco `purge` em `azion.config.js`

Cada entrada do array `purge` leva um `type` de `url`, `cachekey` ou `wildcard`, uma lista `items` e um `layer` opcional de `cache` ou `tiered_cache`. Um array `purge` com um purge por URL na camada Cache e um purge por wildcard:

<Code lang="javascript" code={`purge: [
  {
    type: 'url',
    items: ['https://example.com/path/to/purge'],
    layer: 'cache',
  },
  {
    type: 'wildcard',
    items: ['https://example.com/images/*'],
  },
],`} />

## Versionamento de objetos

Um marcador de versão no nome do objeto transforma cada atualização em um novo objeto para a Azion. Em vez de `image.jpg`, nomeie o objeto `image_1.jpg` e renomeie-o para `image_2.jpg` na próxima atualização. Um número sequencial ou um timestamp servem como marcador. Cada atualização é, assim, um novo objeto. Uma requisição retorna a versão que você nomeia mesmo quando um navegador ou um cache intermediário guarda a anterior. Nomes versionados também permitem entregar versões diferentes a usuários diferentes e reverter uma atualização. Para construir um cache em torno de nomes versionados, consulte [Construa um cache de assets versionados](/pt-br/documentacao/build/cache/tutorials/cache-de-assets-versionados/).

## Limites

:::tip[Dica]
**Aumentar limites** <br />
Você pode solicitar o aumento dos limites com base no seu plano. Entre em contato com a [equipe de suporte técnico](/pt-br/documentacao/services/support/) para solicitar.
:::

Estes são os **limites padrão**:

| Escopo | Limite |
| --- | --- |
| Número de requisições no histórico | 1.000.000 |
| Tempo do histórico de purges | 6 meses |
| Tamanho de URL e cache key | 4.096 caracteres |
| URL e cache key (operações por cliente) | 200 requisições com 50 objetos por requisição |
| URL e cache key (operações por minuto) | 10.000 objetos a cada 60 segundos |
| Wildcard - operações por dia (intervalo de 24h) | 2.000 requisições |
| Tamanho do wildcard | 256 caracteres |
| Wildcard por requisição | 1 |

Estes são os **limites padrão** para cada serviço de suporte:

| Escopo | Developer | Business, Enterprise e Mission-Critical |
| --- | --- | --- |
| Operações de purge | 1.000 por mês | 1.000 por mês<br />Operações de purge adicionais são negociáveis |

Os purges são cobrados por 1.000 purges. Para mais informações, consulte [Preços](/pt-br/documentacao/platform/pricing/#cache).
