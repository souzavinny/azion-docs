Este guia conduz você pela sua primeira política de cache na Azion. Você vai:

- Criar uma cache setting que sobrescreve a expiração enviada pela sua origem.
- Aplicar a cache setting a um path com uma regra do Rules Engine.
- Ler o status de cache de uma requisição pelo terminal.

Uma política de cache na Azion tem três objetos ligados entre si. A cache setting pertence a uma aplicação em [Applications](/pt-br/documentacao/build/applications/) e carrega os valores de expiração. Uma regra no [Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/) aponta para a cache setting e determina a quais requisições ela se aplica. Enquanto uma regra com o behavior **Set Cache Policy** não referenciar a cache setting, ela não muda nada.

---

## Pré-requisitos

- Uma conta Azion com acesso ao [Azion Console](/pt-br/documentacao/account/guides/como-acessar-o-azion-console/).
- Uma aplicação com uma origem configurada. Para criar uma, consulte [Applications primeiros passos](/pt-br/documentacao/build/applications/quickstart/).
- Um path nessa aplicação que serve o conteúdo que você quer armazenar em cache, como `/static`.

---

## 1. Crie uma cache setting

Uma cache setting guarda os valores de expiração de um grupo de requisições. A seção **Cache** define por quanto tempo um edge node da Azion mantém um objeto. **Browser Cache** faz o mesmo para o navegador do usuário.

Este quickstart sobrescreve a expiração de cache e mantém **Browser Cache** em **Honor cache policies**, o padrão. Sua origem controla a expiração do navegador pelos headers `Cache-Control` e `Expires`.

:::note[nota]
A expiração de cache aceita valores de `60` a `31536000` segundos, o equivalente a 1 ano, e o padrão é `60` segundos. Com o módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) ativo, o mínimo cai para `0` segundos. [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) exige um valor de pelo menos `3` segundos para manter o objeto na segunda camada.
:::

Para criar a cache setting:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua aplicação**.
2. Vá para a aba **Cache Settings**.
3. Selecione **+ Cache Setting**.
4. Insira um nome para a cache setting, por exemplo `/static - Cache TTL`.
5. Na seção **Cache**, selecione **Override cache settings**.
6. Em **Max Age (seconds)**, insira `86400`.
7. Selecione **Save**.

A cache setting aparece na lista de cache settings.

Uma nova cache setting tem **Stale cache** habilitado por padrão. Os edge nodes da Azion continuam servindo a última cópia em cache quando sua origem está fora do ar ou o cache está sendo renovado. Para conhecer os demais campos de uma cache setting, consulte [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/).

## 2. Aplique a cache setting com uma regra

[Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/) determina a quais requisições uma cache setting se aplica, por meio do behavior **Set Cache Policy**. Esse behavior roda na fase de requisição, onde uma aplicação define como armazena conteúdo em cache. Uma cache setting sem nenhuma regra apontando para ela nunca é usada.

Para aplicar a cache setting a todas as requisições em `/static`:

1. Vá para a aba **Rules Engine** da sua aplicação.
2. Selecione **+ Rule**.
3. Insira um nome para a regra, por exemplo `/static - Set cache policy`.
4. Selecione **Request Phase**.
5. Na seção **Criteria**, selecione a variável `${uri}`.
6. Como operador de comparação, selecione **starts with**.
7. Como argumento, insira `/static`.
8. Na seção **Behaviors**, selecione **Set Cache Policy**.
9. Selecione a cache setting que você criou.
10. Selecione **Save**.

A regra aparece na lista de regras e se aplica a todas as requisições cuja URI começa com `/static`.

Novas regras levam alguns minutos para se propagar pela rede distribuída da Azion. Diante de um status de cache inesperado, espere e tente de novo antes de diagnosticar.

## 3. Verifique o status de cache

A Azion retorna o status de cache de um recurso quando a requisição carrega o header de debug `Pragma: azion-debug-cache`. A resposta inclui um header `X-Cache` com o status, o endereço IP do edge node e o protocolo.

Para ler o status de cache de um recurso em `/static`:

<Code lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" https://<your-azion-domain>/static/<your-file>`} />

A resposta carrega o header `X-Cache`:

```bash
X-Cache: HIT from 192.0.2.10 with HTTP/2.0
```

`HIT` significa que conteúdo válido e atualizado veio do cache no edge node. A cache setting está em vigor. A primeira requisição depois que a regra se propaga retorna `MISS`. O conteúdo não está no cache, então o edge node o busca na origem. Execute o mesmo comando de novo para ver o status mudar para `HIT`.

A Azion armazena em cache requisições `GET` e `HEAD` por padrão, e `curl -I` envia uma requisição `HEAD`. Para os demais status que uma requisição pode retornar, consulte [Como o Cache funciona](/pt-br/documentacao/build/cache/como-funciona/#status-de-cache).
