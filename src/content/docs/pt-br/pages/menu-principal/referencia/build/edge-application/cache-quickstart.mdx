Este guia orienta você a colocar em cache a página inicial da sua aplicação pela primeira vez. Ao terminar, você terá:

- Criado seu primeiro cache setting, com um time-to-live (TTL) de 60 segundos nos edge nodes da Azion.
- Aplicado o cache setting à página inicial com uma regra Set Cache Policy.
- Verificado o status do cache com uma requisição que carrega o header `Pragma: azion-debug-cache`.

[Cache](/pt-br/documentacao/build/cache/) é um módulo de [Applications](/pt-br/documentacao/build/applications/). Você o configura por meio de uma cadeia de objetos, nesta ordem:

1. Uma aplicação, que contém o cache setting e a regra.
2. Um cache setting dentro da aplicação, que guarda o TTL. Criar um cache setting não o ativa.
3. Uma regra no [Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/) da aplicação, que aplica o cache setting às requisições correspondentes. A regra faz isso com o behavior [Set Cache Policy](/pt-br/documentacao/build/applications/reference/rules-engine/#set-cache-policy).
4. Uma requisição à aplicação com o header `Pragma: azion-debug-cache`. O header de resposta `X-Cache` informa o status do cache.

## Pré-requisitos

- Uma conta Azion com acesso ao [Azion Console](/pt-br/documentacao/account/guides/como-acessar-o-azion-console/).
- Uma [aplicação](/pt-br/documentacao/build/applications/quickstart/) que entrega conteúdo em um domínio Azion.
- O comando `curl` no seu terminal.

---

## 1. Crie um cache setting

O cache setting substitui o TTL que sua origem envia. Ele mantém a página inicial nos edge nodes da Azion por 60 segundos. Todas as outras opções mantêm o padrão.

Para criar o cache setting:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications**.
2. Selecione a aplicação que você quer configurar.
3. Na aba **Cache Settings**, selecione **+ Cache Setting**.
4. Insira um nome para o cache setting.
5. Na seção **Cache Expiration Policies**, em **Cache**, selecione **Override cache settings**.
6. Em **Max Age (seconds)**, insira `60`.
7. Selecione **Save**.

A aba **Cache Settings** lista o novo cache setting. Nenhuma requisição o usa ainda: uma regra o ativa na próxima etapa.

---

## 2. Aplique o cache setting com uma regra

Uma regra aplica um cache setting a toda requisição cujo caminho corresponde aos seus critérios. Esta regra corresponde ao caminho `/`, então a página inicial usa o cache setting criado em Crie um cache setting.

Para criar a regra:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua aplicação**.
2. Na aba **Rules Engine**, selecione **+ Rule**.
3. Insira um nome para a regra.
4. Selecione **Request Phase**.
5. Na seção **Criteria**, selecione a variável `${uri}`.
6. Selecione o operador _is equal_.
7. Insira `/` como argumento.
8. Na seção **Behaviors**, selecione _Set Cache Policy_.
9. Como argumento, selecione o cache setting criado em Crie um cache setting.
10. Selecione **Save**.

A aba **Rules Engine** lista a nova regra. Uma nova regra leva alguns minutos para propagar, então aguarde antes de verificá-la.

---

## 3. Verifique o status do cache

Uma requisição que carrega o header `Pragma: azion-debug-cache` retorna um header de resposta `X-Cache`. O header informa o status do cache, o endereço IP do edge node e o protocolo da requisição.

Para verificar o status do cache da página inicial:

1. Faça uma requisição à página inicial com o header de debug. Substitua `xxxxxxxxxx.map.azionedge.net` pelo domínio da sua aplicação:

   <Code lang="bash" code={`curl -s -D - -o /dev/null -H "Pragma: azion-debug-cache" https://xxxxxxxxxx.map.azionedge.net/`} />

   Os headers de resposta incluem o status do cache:

   ```text
   X-Cache: MISS from 203.0.113.10 with HTTP/2.0
   ```

   O edge node não tem cópia da página inicial na primeira requisição. O status é `MISS` e o edge node busca a página na origem.

2. Execute o mesmo comando novamente:

   <Code lang="bash" code={`curl -s -D - -o /dev/null -H "Pragma: azion-debug-cache" https://xxxxxxxxxx.map.azionedge.net/`} />

   O status muda:

   ```text
   X-Cache: HIT from 203.0.113.10 with HTTP/2.0
   ```

O status `HIT` significa que o edge node serviu a página inicial do cache, sem requisição à origem. Se a segunda requisição não retornar `HIT`, aguarde alguns minutos e tente de novo antes de diagnosticar. A mesma resposta carrega a cache key no header `X-Cache-Key` e os outros headers de debug `X-Cache-*`. Para mais informações, consulte [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/).
