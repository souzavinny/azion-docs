As tabelas desta página listam os limites padrão de [Cache](/pt-br/documentacao/build/cache/), [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) e [Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/). Quando um limite depende de um módulo ou de um plano, a tabela nomeia essa condição em uma coluna própria. A equipe de suporte técnico pode aumentar um limite para o seu plano. Para solicitar o aumento, entre em contato com o [suporte técnico](/pt-br/documentacao/services/support/).

## TTL do cache

Um cache setting configura o TTL. O mínimo depende do módulo que a aplicação tem, e o máximo depende da camada que guarda o objeto.

| Escopo | Módulo | TTL mínimo | TTL máximo |
| --- | --- | --- | --- |
| TTL do edge cache | Nenhum | 60 segundos | 31.536.000 segundos |
| TTL do edge cache | [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) | 0 segundos | 31.536.000 segundos |
| TTL da camada Tiered Cache | [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) | 3 segundos | 2.592.000 segundos |

Um TTL de 0 segundos não é o mesmo que uma regra de Bypass Cache. Para entender a diferença, consulte [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

## Tamanhos de objeto e fragmento

Cache armazena um objeto até o tamanho indicado na tabela. Com Large File Optimization, Cache divide um objeto em fragmentos do tamanho indicado na tabela.

| Escopo | Limite | Condição |
| --- | --- | --- |
| Tamanho de um objeto no cache | 10 GB | Nenhuma |
| Tamanho do fragmento de Large File Optimization | 1.024 kB | Large File Optimization ativado |

Para ativar Large File Optimization em um cache setting, consulte [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/).

---

## Tiered Cache

Um cache setting com Tiered Cache mantém um objeto na camada Tiered Cache por um TTL dentro da faixa indicada na tabela.

| Escopo | Limite |
| --- | --- |
| TTL mínimo em Tiered Cache | 3 segundos |
| TTL máximo em Tiered Cache | 2.592.000 segundos |

Uma regra de Bypass Cache não alcança a camada Tiered Cache, que mantém o objeto em cache pelo TTL mínimo. Para mais informações, consulte [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/).

## Real-Time Purge

Real-Time Purge remove objetos do cache antes do fim do TTL. Cada tipo de purge e o histórico de purge têm um limite na tabela.

| Escopo | Limite |
| --- | --- |
| Requisições mantidas no histórico de purge | 1.000.000 de requisições |
| Retenção do histórico de purge | 6 meses |
| Comprimento de URL e cache key | 4.096 caracteres |
| Operações de purge por URL e cache key por cliente | 200 requisições com 50 objetos por requisição |
| Operações de purge por URL e cache key por minuto | 10.000 objetos a cada 60 segundos |
| Operações de purge por wildcard por dia (intervalo de 24 horas) | 2.000 requisições |
| Comprimento da expressão wildcard | 256 caracteres |
| Expressões wildcard por requisição | 1 expressão |

O número de operações de purge por mês depende do serviço de Suporte da conta:

| Escopo | Developer | Business, Enterprise e Mission-Critical |
| --- | --- | --- |
| Operações de purge | 1.000 por mês | 1.000 por mês<br />Operações de purge adicionais são negociáveis |

Para os tipos de purge, seus argumentos e as camadas que eles alcançam, consulte [Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/).
