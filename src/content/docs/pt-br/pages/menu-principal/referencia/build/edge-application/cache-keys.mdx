Uma cache key é a entrada de índice que um edge node cria para cada objeto que armazena. [Cache](/pt-br/documentacao/build/cache/) cria a chave a partir da URI da requisição e acrescenta um marcador para cada variação que o cache setting habilita. Para saber como um edge node usa a chave para responder a uma requisição, consulte [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/).

## Formato da cache key

A cache key padrão concatena estes elementos da URI da requisição, nesta ordem e sem nada entre eles:

- Esquema da requisição
- Host
- Caminho do recurso
- Query string
- O separador de variação e, quando uma variação se aplica, a variação acrescentada

Um objeto com a URI `https://static.example.com/page/site.js` tem a cache key `httpsstatic.example.com/page/site.js`.

As cache keys diferenciam maiúsculas de minúsculas, então uma chave que difere apenas na caixa das letras identifica outro objeto.

Quando o cache setting habilita variações, a chave carrega o separador `@@` no final, seguido pelo marcador de qualquer variação que se aplique. Uma chave com o separador e sem marcador tem a forma `httpsexample.com/resource-path/image.jpeg@@`.

## Variações

Cada funcionalidade que varia o conteúdo acrescenta seu próprio marcador à cache key. Cada variação de um objeto é uma entrada de cache separada, com sua própria chave. A tabela lista cada variação, o marcador que ela adiciona e um exemplo de chave.

| Funcionalidade | Marcador | Exemplo de chave |
| --- | --- | --- |
| Método de requisição diferente de `GET` ou `HEAD` | O nome do método, como prefixo da chave | `optionshttpsstatic.example.com/page` |
| Conversão de formato do Image Processor | `@@` e o formato de arquivo convertido | `httpsstatic.example.com/static/images/image_1.jpg?ims=880x@@webp` |
| Adaptive Delivery por grupo de dispositivos | `@@` e o nome do grupo de dispositivos | `httpwww.example.com/@@Mobile` |
| Advanced Cache Key, Cache by Cookie | `@@` e, depois, cada nome e valor de cookie seguidos de `;` | `httpwww.example.com/@@user=user;` |
| Advanced Cache Key, Cache by Query String | `?` e os argumentos selecionados, na ordem da requisição | `httpstatic.example.com/page?name=name&city=city` |
| Query String Sort | Os argumentos da query string, em ordem alfabética | `httpstatic.example.com/page?city=city&name=name` |
| Large File Optimization | `@@bytes=` e o intervalo de bytes do fragmento | `httpstatic.example.com/media/file.mp4@@bytes=0-1048575` |
| Requisição `POST` ou `OPTIONS` em cache | `@@` e o hash MD5 do corpo da requisição | `httpsdynamic.example.com/path@@md5_of_post_arguments` |

As opções que ativam cada variação estão documentadas em [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/).

### Método da requisição

Quando uma requisição usa um método diferente de `GET` ou `HEAD`, o nome do método é adicionado como prefixo da cache key. Uma requisição `OPTIONS` para `https://static.example.com/page` tem a chave `optionshttpsstatic.example.com/page`.

Cache armazena respostas `GET` e `HEAD` por padrão. Armazenar respostas `POST` ou `OPTIONS` em cache requer [Application Accelerator](/pt-br/documentacao/build/application-accelerator/). Essas chaves também carregam o hash do corpo da requisição, descrito em Métodos HTTP em cache.

### Image Processor

Quando [Image Processor](/pt-br/documentacao/build/image-processor/) converte uma imagem para outro formato, o formato de arquivo convertido segue o separador `@@`. A query string `ims` que solicita o processamento permanece na posição de query string da chave.

Uma imagem redimensionada com `?ims=880x` e convertida para `webp` tem a chave `httpsstatic.example.com/static/images/image_1.jpg?ims=880x@@webp`.

### Device Groups

Quando a opção Adaptive Delivery do cache setting é **Content varies by some Device Groups (Whitelist)**, Cache mantém um objeto por grupo de dispositivos selecionado. A chave termina com o separador `@@` e o nome do grupo de dispositivos.

Uma aplicação com uma variação para o grupo `Mobile` tem a chave `httpwww.example.com/@@Mobile`. Os grupos de dispositivos são definidos em [Device Groups](/pt-br/documentacao/build/applications/reference/device-groups/).

### Cache by Cookie

Cache by Cookie é uma opção de Advanced Cache Key, disponível com [Application Accelerator](/pt-br/documentacao/build/application-accelerator/). A chave termina com o separador `@@` e, depois, cada nome e valor de cookie selecionado seguidos de `;`. Nomes e valores de cookie diferenciam maiúsculas de minúsculas.

Conteúdo que varia pelo cookie `user` produz estas chaves:

- `httpwww.example.com/@@;`
- `httpwww.example.com/@@user=user;`

A primeira chave não carrega nenhum valor de cookie depois do separador.

### Cache by Query String

Cache by Query String é uma opção de Advanced Cache Key, disponível com [Application Accelerator](/pt-br/documentacao/build/application-accelerator/). A chave carrega o separador `?` e os argumentos selecionados, na ordem em que a requisição os enviou. Nomes e valores de argumentos diferenciam maiúsculas de minúsculas.

Conteúdo que varia por `name` e `city` produz estas chaves:

- `httpstatic.example.com/page?name=name`
- `httpstatic.example.com/page?city=city&name=name`
- `httpstatic.example.com/page?name=name&city=city`

Com **Query String Sort** ativado, os argumentos são agrupados em uma única chave, em ordem alfabética. As requisições `?name=name&city=city` e `?city=city&name=name` passam então a compartilhar a chave `httpstatic.example.com/page?city=city&name=name`.

### Large File Optimization

Com Large File Optimization ativado, cada fragmento de um objeto tem sua própria cache key. A chave termina com o separador `@@bytes=` e o intervalo de bytes do fragmento.

Um arquivo de `2097151` bytes produz estas chaves:

- `httpstatic.example.com/media/file.mp4@@bytes=0-1048575`
- `httpstatic.example.com/media/file.mp4@@bytes=1048576-2097151`

### Métodos HTTP em cache

Quando o cache setting ativa **Enable caching for POST** ou **Enable caching for OPTIONS**, o corpo da requisição passa a fazer parte da cache key. A chave termina com o separador `@@` e o hash MD5 do corpo da requisição:

- `httpsdynamic.example.com/path@@md5_of_post_arguments`
- `httpsdynamic.example.com/path@@md5_of_options_arguments`

## Headers de debug

Uma requisição que carrega o header `Pragma: azion-debug-cache` recebe uma resposta com os headers `X-Cache-*`, que descrevem a entrada de cache do objeto solicitado.

Solicite um objeto com o header de debug:

<Code lang="bash" code={`curl -s -o /dev/null -D - -H "Pragma: azion-debug-cache" https://example.com/resource-path/image.jpeg`} />

Os headers da resposta incluem o status do cache e a cache key, nesta forma:

```text
X-Cache: HIT from 203.0.113.10 with HTTP/2.0
X-Cache-Key: httpsexample.com/resource-path/image.jpeg@@
```

O conjunto completo de headers de debug:

| Header | Valor |
| --- | --- |
| `X-Cache` | O status do cache da requisição, o IP do edge node que a respondeu e o protocolo da requisição. O status é um de `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED`, `BYPASS` ou `-`. |
| `X-Cache-Key` | A cache key do objeto, no formato descrito em Formato da cache key. |
| `X-Cache-File` | O arquivo de cache do objeto: o hash MD5 da cache key. |
| `X-Cache-Since` | O timestamp Unix de quando o objeto entrou no cache. |
| `X-Cache-Expire` | O timestamp Unix de quando o objeto sai do cache. |
| `X-Cache-Expire-In` | O tempo que o objeto permanece em cache, em segundos. |
| `X-Cache-Valid` | O tempo que o objeto está definido para permanecer em cache, definido na configuração de cache ou recebido dos headers `Cache-Control` da origem. |
| `X-Cache-Config` | O ID da configuração do virtual host, gerado pelo Azion Console. |
| `X-Cache-ID` | O ID único da requisição. |

Para a definição de cada status do cache, consulte [Como Cache funciona](/pt-br/documentacao/build/cache/como-funciona/). Para ler esses headers em um navegador, consulte [Verifique indicadores de cache no navegador](/pt-br/documentacao/build/cache/guides/verificar-tempo-de-cache-da-pagina/).

## Purge por cache key

Real-Time Purge aceita uma lista de cache keys como argumento de um purge por cache key. Cada chave tem a forma que o header `X-Cache-Key` retorna, incluindo o separador `@@` e qualquer marcador de variação. Cada variação de um objeto é purgada pela sua própria chave.

As variações de uma imagem processada por Image Processor, por exemplo, são purgadas como quatro chaves:

- `httpstatic.example.com/static/images/image.jpg@@`
- `httpstatic.example.com/static/images/image.jpg@@webp`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@`
- `httpstatic.example.com/static/images/image.jpg?ims=88x@@webp`

Para fazer purge de todas as variações de um objeto, liste cada chave ou use um purge por wildcard. Para os tipos de purge, camadas, argumentos e limites, consulte [Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/).
