Os termos a seguir são o vocabulário do [Cache](/pt-br/documentacao/build/cache/), o módulo de [Applications](/pt-br/documentacao/build/applications/) que armazena cópias do seu conteúdo nos edge nodes da Azion.

<GlossaryFilter lang="pt-br">

| Termo | Definição |
| --- | --- |
| Adaptive Delivery | Uma [opção de cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/) que mantém em cache variações de um objeto por dispositivo, uma por grupo de dispositivos que a Azion detecta com [Device Groups](/pt-br/documentacao/build/applications/reference/device-groups/). Com _Content varies by some Device Groups (Whitelist)_ selecionada, a cache key carrega o nome do grupo de dispositivos depois do separador `@@`. |
| Advanced Cache Key | Uma [seção do cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/) que varia os objetos em cache por campos de query string ou por valores de cookie, e não apenas por URL. Ela contém as opções Cache by Query String e Cache by Cookie e requer [Application Accelerator](/pt-br/documentacao/build/application-accelerator/). As duas opções diferenciam maiúsculas de minúsculas. |
| `BYPASS` | Um status do cache: o edge node requisita o conteúdo diretamente da origem, em vez de usar uma versão em cache, porque um behavior Bypass Cache está ativo. |
| Bypass Cache | Um [behavior do Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/#bypass-cache) para a fase de requisição que impede a Azion de armazenar em cache a resposta da origem para as requisições correspondentes, que são todas encaminhadas à origem. Ele não altera o cache do navegador e requer Application Accelerator. Ele não alcança a camada Tiered Cache, que continua a armazenar em cache durante o TTL mínimo. |
| Cache by Cookie | Uma [opção de Advanced Cache Key](/pt-br/documentacao/build/cache/reference/cache-settings/) que varia os objetos em cache por nome e valor de cookie. As quatro configurações são nenhuma variação por cookies, variação por alguns cookies listados, variação por todos os cookies exceto alguns listados e variação por todos os cookies. Na cache key, os nomes e valores dos cookies seguem o separador `@@` e terminam com `;`. |
| Cache by Query String | Uma [opção de Advanced Cache Key](/pt-br/documentacao/build/cache/reference/cache-settings/) que decide quais campos de query string distinguem os objetos em cache. As quatro configurações são nenhuma variação por query string, variação por alguns campos listados, variação por todos os campos exceto alguns listados e variação por todos os campos. |
| cache key | O identificador que um edge node constrói a partir de uma requisição para [indexar um objeto em cache](/pt-br/documentacao/build/cache/reference/cache-keys/) e associar requisições posteriores a ele. Por padrão, a cache key concatena o esquema, o host, o caminho e a query string, depois um separador `@@` com as variações anexadas, e diferencia maiúsculas de minúsculas. Por exemplo, `https://static.example.com/page/site.js` produz `httpsstatic.example.com/page/site.js`. |
| cache setting | O objeto de uma aplicação que contém uma política de cache, documentado em [Cache Settings](/pt-br/documentacao/build/cache/reference/cache-settings/): os modos de TTL do navegador e do edge cache, Stale Cache, Large File Optimization, Advanced Cache Key, os métodos HTTP em cache e Adaptive Delivery. Uma regra com o behavior Set Cache Policy atribui um cache setting às requisições que correspondem a ela. |
| camada de purge | A camada de cache sobre a qual um purge do [Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/) atua: _Cache_, o edge cache, ou _Tiered Cache_, disponível apenas quando esse módulo está ativo. Faça purge primeiro da camada Tiered Cache e depois da camada Cache, para que os edge nodes não se reabasteçam com conteúdo desatualizado da camada Tiered Cache. |
| controle de Thundering Herd | O mecanismo pelo qual um edge node [abre apenas uma conexão com a origem](/pt-br/documentacao/build/cache/como-funciona/) quando várias requisições simultâneas chegam para o mesmo objeto que não está em cache. Cada edge node requisita o objeto da origem uma vez por `MISS` ou outro status diferente de `HIT`. |
| edge node | Um servidor da rede distribuída da Azion que recebe requisições, mantém o [cache](/pt-br/documentacao/build/cache/como-funciona/) e busca na origem quando o cache não pode responder. O header `X-Cache` informa o IP do edge node que respondeu a uma requisição. Para o significado genérico de cache, consulte [o artigo do Learning Center sobre cache](https://www.azion.com/pt-br/learning/cdn/o-que-e-armazenamento-em-cache/). |
| Enforce HLS cache | Um [behavior do Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/#enforce-hls-cache) para a fase de requisição que a Azion adiciona quando você seleciona uma origem Live Ingest. Ele ignora suas regras da Cache Phase e aplica a política de cache da Azion para streams HLS ao vivo: 5 segundos para playlists (`.m3u8`) e 60 segundos para chunks (`.ts`). Para aplicar a mesma política manualmente, consulte [Implemente cache HLS para streaming ao vivo](/pt-br/documentacao/build/cache/guides/implementar-cache-hls/). |
| `EXPIRED` | Um status do cache: o conteúdo em cache ultrapassou o TTL definido no edge node, então o edge node busca na origem e atualiza a cópia em cache para as próximas requisições. |
| Forward Cookies | Um [behavior do Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/#forward-cookies) para a fase de requisição que encaminha ao usuário o header `Set-Cookie` recebido da origem, mesmo em um `HIT` de cache. Ele requer Application Accelerator. |
| fragmento | Uma parte de um arquivo que [Large File Optimization](/pt-br/documentacao/build/cache/reference/cache-settings/) divide e armazena em cache separadamente, sob demanda. Cada fragmento carrega sua própria cache key, com o separador `@@bytes=` e o intervalo de bytes, e o tamanho padrão do fragmento é 1.024 kB. |
| grupo de dispositivos | Um objeto criado com [Device Groups](/pt-br/documentacao/build/applications/reference/device-groups/) que compara uma expressão regular com o header `User-Agent` de uma requisição. Adaptive Delivery lê os grupos de dispositivos para manter uma variação em cache de um objeto por grupo. |
| `HIT` | Um status do cache: conteúdo válido e atualizado é entregue diretamente do cache do edge node, sem uma requisição à origem. |
| Honor Origin Cache Headers | Um [modo de cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/), para o cache do navegador ou o edge cache, que mantém as definições de cache que a origem envia nos headers `Cache-Control` e `Expires`. Com Stale Cache, uma diretiva `stale-while-revalidate` da origem define então a janela de stale. |
| janela de stale | O período durante o qual [Stale Cache](/pt-br/documentacao/build/cache/como-funciona/) pode entregar um objeto expirado. Quando a origem envia uma diretiva `stale-while-revalidate` e o cache setting honra os headers da origem, esse valor define a janela; caso contrário, a Azion atribui um padrão de 300 segundos. |
| Large File Optimization | Uma [opção de cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/) que divide um arquivo grande em fragmentos, cada um com sua própria cache key, e os armazena em cache sob demanda conforme o usuário consome o arquivo. Ela se aplica ao edge cache e, quando Tiered Cache está ativo, também à camada Tiered Cache. |
| `MISS` | Um status do cache: o conteúdo requisitado não está no cache do edge node, então o edge node o busca na origem, e a resposta pode ser armazenada em cache para as próximas requisições. |
| origem | O servidor ou serviço que guarda a fonte do seu conteúdo: servidores web na sua infraestrutura, um serviço de nuvem ou Object Storage, alcançado por meio de um [Connector](/pt-br/documentacao/secure/connectors/reference/origins/). Um edge node busca na origem quando o status do cache é `MISS`, `EXPIRED` ou `BYPASS`. |
| Override Cache Settings | Um [modo de cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/) que substitui os headers de cache da origem por um TTL que você define, para o cache do navegador ou o edge cache. Um TTL do edge cache abaixo de 60 segundos requer Application Accelerator. Com Stale Cache, este modo usa a janela de stale padrão de 300 segundos. |
| `Pragma: azion-debug-cache` | Um header de requisição que faz o edge node retornar os [headers de debug `X-Cache` e `X-Cache-*`](/pt-br/documentacao/build/cache/reference/cache-keys/) com a resposta: status do cache, cache key, arquivo de cache, timestamps do cache e ID da configuração. Para lê-los em um navegador, consulte [Verifique indicadores de cache no navegador](/pt-br/documentacao/build/cache/guides/verificar-tempo-de-cache-da-pagina/). |
| purge por cache key | Um [tipo de Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/) que recebe uma lista de cache keys como argumento e remove exatamente esses objetos, incluindo as variações por query string, cookie ou formato de imagem. Cada variação a remover deve ser listada individualmente. |
| purge por URL | Um [tipo de Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/) que recebe uma lista de URLs, converte cada uma em sua cache key e remove apenas esses objetos, sem recursão. As variações por cookie, grupo de dispositivos ou formato de imagem não são removidas; as variações por query string são, quando os argumentos vêm na ordem que a cache key usa. Um asterisco em um purge por URL é um caractere literal, não um wildcard. |
| purge por wildcard | Um [tipo de Real-Time Purge](/pt-br/documentacao/build/cache/reference/real-time-purge/) que recebe uma expressão com um asterisco (`*`) no caminho ou na query string e remove todos os objetos correspondentes, incluindo suas variações. Ele não alcança a camada Tiered Cache. |
| Query String Sort | Uma [opção de Advanced Cache Key](/pt-br/documentacao/build/cache/reference/cache-settings/) que ordena os campos da query string em ordem alfabética antes de a cache key ser construída, para que a posição de um campo não crie mais um objeto separado. Um purge por URL desse objeto deve enviar os argumentos em ordem alfabética. |
| Real-Time Purge | O recurso da plataforma que [remove objetos em cache](/pt-br/documentacao/build/cache/reference/real-time-purge/) da camada Cache ou Tiered Cache antes que o TTL expire, para que a próxima requisição busque a versão mais recente na origem. Os três tipos de purge são purge por URL, purge por cache key e purge por wildcard. Para executar um, consulte [Faça purge de conteúdo em cache](/pt-br/documentacao/build/cache/guides/purgar-conteudo/). |
| `REVALIDATED` | Um status do cache: o edge node verificou o conteúdo em cache com a origem por meio de headers condicionais e o encontrou atualizado, então a origem não retransmitiu o recurso. |
| Set Cache Policy | Um [behavior do Rules Engine](/pt-br/documentacao/build/applications/reference/rules-engine/#set-cache-policy) para a fase de requisição que atribui um cache setting às requisições que correspondem aos critérios da regra. O cache setting deve existir na aba Cache Settings antes que a regra o referencie. |
| `STALE` | Um status do cache: o conteúdo em cache expirou e a origem não respondeu, então o edge node entregou a cópia expirada sob Stale Cache. |
| Stale Cache | Uma opção do cache setting, ativada por padrão, que permite a um edge node [continuar a entregar um objeto expirado](/pt-br/documentacao/build/cache/como-funciona/) quando a revalidação falha. Ela cobre um erro 5xx da origem, um timeout de conexão ou origem inacessível, headers cache-control inválidos ou ausentes e uma atualização em andamento. Durante a janela de stale, o edge node entrega a cópia expirada imediatamente e busca uma nova em segundo plano. |
| status do cache | O resultado da [consulta ao cache](/pt-br/documentacao/build/cache/como-funciona/) que um edge node faz para uma requisição, retornado no header `X-Cache` quando a requisição carrega `Pragma: azion-debug-cache`. Os oito valores são `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED`, `BYPASS` e `-`. O valor `-` significa que nenhum status foi recebido porque o conteúdo tem restrição de cache, por exemplo uma requisição `POST` enquanto o cache para POST está desativado. |
| Tiered Cache | Um [módulo do Cache](/pt-br/documentacao/build/cache/tiered-cache/) que adiciona uma segunda camada de cache entre os edge nodes e seus servidores de origem e mantém o conteúdo em cache por períodos mais longos. Ele requer ativação para a conta por meio da equipe de Vendas, e um cache setting que o usa precisa de um TTL de pelo menos 3 segundos. Para o significado genérico, consulte [o artigo do Learning Center sobre tiered caching](https://www.azion.com/pt-br/learning/cdn/o-que-e-tiered-caching/). |
| TTL | Time to live: o número de segundos que um objeto em cache permanece válido antes de expirar, definido separadamente para o cache do navegador e o edge cache em um [cache setting](/pt-br/documentacao/build/cache/reference/cache-settings/). Sem Application Accelerator, o TTL do edge cache não pode ficar abaixo de 60 segundos. O piso e o teto de cada camada estão listados em [Limites do Cache](/pt-br/documentacao/build/cache/limites/). |
| `UPDATING` | Um status do cache: o conteúdo em cache expirou e uma cópia expirada é entregue enquanto o edge node busca o conteúdo atualizado na origem. |
| `X-Cache` | O header de resposta que carrega o status do cache, o IP do edge node e o protocolo da requisição, retornado quando a requisição carrega `Pragma: azion-debug-cache`. Por exemplo: `X-Cache: HIT from 203.0.113.10 with HTTP/2.0`. O conjunto completo de headers de debug está listado em [Cache keys](/pt-br/documentacao/build/cache/reference/cache-keys/). |

</GlossaryFilter>
