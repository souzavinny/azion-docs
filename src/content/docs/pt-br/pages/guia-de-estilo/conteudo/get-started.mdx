## Propósito

Uma página Get started é um tutorial cujo objetivo é a primeira ativação de um produto: de não usar o produto até o menor resultado que funciona. Ela é um padrão do tipo [tutorial](/pt-br/documentacao/guia-de-estilo/conteudo/tutoriais/), não um novo tipo de conteúdo.

## Quando usar

- Escreva uma página Get started quando um produto precisa de um caminho documentado até o primeiro resultado que funciona.
- Escreva uma página Get started por produto, como ponto de entrada logo depois do Overview do produto.
- Não escreva uma página Get started para uma tarefa que o leitor já tem em mente. Essa tarefa precisa de um [guia how-to](/pt-br/documentacao/guia-de-estilo/conteudo/guias-how-to/).
- Não escreva uma página Get started para apresentar opções ou comparar interfaces. O padrão tem um único caminho.
- Não escreva uma página Get started separada para uma solução ou um recurso. O padrão cobre um produto inteiro.

## Registro

Procedural: 20 palavras por frase, uma instrução por passo, imperativo e ativo. [Estrutura de frases](/pt-br/documentacao/guia-de-estilo/escrita/estrutura-de-frases/) tem as regras.

## Estrutura

Uma página Get started segue o esqueleto do tutorial. [Tutoriais](/pt-br/documentacao/guia-de-estilo/conteudo/tutoriais/) argumenta cada parte; a lista abaixo nomeia o que o padrão exige.

**Componentes obrigatórios**

- **Parágrafo de abertura**: o que o leitor terá ao final e aproximadamente quanto tempo a página leva.
- **Antes de começar**: o conjunto mínimo real de pré-requisitos, cada um como link ou comando de uma linha.
- **Passos**: seções de passos numerados em um único caminho, até o menor resultado que funciona.
- **O que você construiu**: um parágrafo que reafirma o resultado que funciona.
- **Próximos passos**: dois ou três links para os guias do produto, cada um com uma razão para o clique.

**Componentes opcionais**

- **Capturas de tela**: para um passo cujo resultado visível é uma tela, não a saída de um comando.
- **Asides**: raros. Um tutorial cheio de blocos de nota tenta ser material de referência.

## Template

```md
[Um parágrafo: o que o leitor terá ao final e
aproximadamente quanto tempo leva.]

## Antes de começar

- <Pré-requisito que a página não pode fornecer, como link ou comando de uma linha>

## Passo 1: <frase verbal>

<O que fazer. Uma instrução por frase.>

<O que o leitor vê: saída de comando, captura de tela ou uma URL para abrir.>

## Passo 2: <frase verbal>

<...>

## O que você construiu

<Um parágrafo. Reafirme o resultado que funciona.>

## Próximos passos

- <Guia how-to dos Guias deste produto, com uma razão para o clique>
- <Um segundo guia, ou a referência do produto>
```

## Regras

- **Mantenha os pré-requisitos no mínimo real.** Cada item é um motivo para abandonar a página.
- **Documente um único caminho mínimo.** Sem opções, sem comparação de interfaces.
- **Termine com o resultado funcionando.** Retome o resultado e aponte dois ou três guias.
- **Coloque a página logo depois da visão geral do produto.**
- **Teste todo comando antes de publicar.** Uma instrução por passo, e um resultado visível em cada um.
