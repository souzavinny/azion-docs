**Tiered Cache** is a Cache module that creates an additional cache layer between the edge and the origin servers. With the module active, content stays cached for longer periods and the origin receives fewer requests. Tiered Cache is designed for objects that can remain in cache for a long period of time. The module is available on request: activation goes through the Sales team.

Its behavior depends on five mechanisms: the cache layers, the second-layer region, the TTL requirements, the Bypass Cache limitation, and the purge order.

## Cache layers

End users send requests to the edge network, where content is cached. Without Tiered Cache, a request that misses the edge layer goes to the origin. Tiered Cache adds a second cache layer between that edge layer and the origin servers. The tiered layer can answer a request that misses the edge layer, so the request does not reach the origin. Content stays cached for longer periods, and the origin receives fewer requests.

## Second-layer region

Azion hosts the second-layer servers in the United States (`na-united-states`) by default. Brazil (`sa-brazil`) is also available. The region closest to the audience keeps the second layer's answers closer to users. To change the region, contact the Sales team.

---

## TTL requirements

You can activate Tiered Cache only on cache policies with a TTL equal to or greater than 3 seconds. The TTL for a cache policy has these limits:

| TTL | Value |
| --- | --- |
| Minimum | 3 seconds |
| Default | 60 seconds |
| Maximum | 2,592,000 seconds |

To set the TTL for a cache policy, refer to [Configure cache policies](/en/documentation/products/guides/cache-settings/).

## Bypass Cache limitation

Tiered Cache does not support bypass cache. A Bypass Cache rule works at the edge layer only. An application with Tiered Cache active keeps content cached in the tiered layer for at least the minimum TTL of 3 seconds.

:::caution
Content that must never stay in cache does not belong behind Tiered Cache.
:::

---

## Purge order

Real-Time Purge expires Tiered Cache content before the TTL. Purge the tiered layer first and the edge layer second. If you purge the edge layer first, it can re-fetch outdated content from the tiered layer. For more information, refer to [Real-Time Purge](/en/documentation/products/build/applications/real-time-purge/).
