A storefront team already deploys a catalogue site, with a cart and a checkout under the same domain. The catalogue changes hourly and can answer from cache. The cart is different for every visitor and must never be shared between users. The checkout must resist abusive traffic. This page configures a catalogue cache rule and a cart bypass in **Applications**, and a checkout rate limit in **Firewall**.

This use case covers catalogue caching, cart bypass, and checkout rate limiting. It does not cover payment processing or inventory synchronization.

## Prerequisites

- An application that serves your storefront domain
- A firewall in your account

## Architecture

In this storefront setup, the application and the firewall handle three request paths:

1. A request to a path that starts with `/catalog` matches the cache rule and answers from cache.
2. A request to a path that starts with `/cart` matches the Bypass Cache rule and never answers from cache.
3. A request to a path that starts with `/checkout` counts toward the rate limit for its client IP address.
4. Checkout requests above the rate limit receive HTTP `429 Too Many Requests`.

## Configure the catalogue cache

The storefront catalogue changes hourly, so one hour is the longest safe TTL.

To create the cache setting:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.
2. In the **Cache Settings** tab, select **+ Cache Setting**.
3. Enter a name for the cache setting.
4. In **Cache Expiration Policies**, set **CDN Cache Settings** to _Override Cache Settings_.
5. Set **Maximum TTL** to `3600` seconds.
6. Select **Save**.

The application now has a cache setting with a one-hour TTL.

To apply the cache setting to the catalogue path:

1. In the **Rules Engine** tab, select **+ Rule**.
2. Select **Request Phase**.
3. Set the criteria to `if ${uri} starts with /catalog`.
4. As the behavior, select **Set Cache Policy** and select the cache setting you created.
5. Select **Save**.

Requests to paths that start with `/catalog` use the cache setting and answer from cache for up to one hour.

For more information, refer to [Cache Settings](/en/documentation/products/build/applications/cache-settings/).

## Configure the cart bypass

In this storefront setup, the cart path must never answer from the cache. The **Bypass Cache** behavior requires the **Application Accelerator** module. For more information, refer to [Application Accelerator](/en/documentation/products/build/applications/application-accelerator/).

To turn on the module and create the bypass rule:

1. Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.
2. In the **Main Settings** tab, in **Modules**, turn on **Application Accelerator**.
3. Select **Save**.
4. In the **Rules Engine** tab, select **+ Rule**.
5. Select **Request Phase**.
6. Set the criteria to `if ${uri} starts with /cart`.
7. As the behavior, select **Bypass Cache**.
8. Select **Save**.

Requests to paths that start with `/cart` never answer from the cache.

:::note
**Bypass Cache** affects origin cache policies, not browser cache policies.
:::

## Configure the checkout rate limit

In this storefront setup, the rate limit on the checkout path resists abusive traffic. An average rate limit of `10` requests per second is a starting point. Adjust it from observed traffic.

To create the rate limit rule:

1. Access [Azion Console](https://console.azion.com/) > **Firewall** > **your firewall**.
2. In the **Rules Engine** tab, select **+ Rule**.
3. Set the criteria to **Request URI** _starts with_ `/checkout`.
4. As the behavior, select **Set Rate Limit**.
5. Set **Type** to _Req/s_.
6. Set **Average Rate Limit** to `10`.
7. Set the limit to count per **Client IP address**.
8. Select **Save**.

Checkout requests above the limit receive HTTP `429 Too Many Requests`.

## Verify the setup

To check that catalogue pages answer from cache, request a catalogue page:

<Code lang="bash" code={`curl -I https://<your-domain>/catalog/<a-page>`} />

The response includes the `X-Cache-Key` header. Azion generates this header when content is cached at the edge.

The cart must never answer from the cache. This use case has no documented check for a bypassed request. [GAP: no response header or signal identifies a bypassed cart request]

To check the checkout rate limit, send more than `10` requests in one second from one client. The requests above the limit receive HTTP `429 Too Many Requests`.
